# 财小智首页设计对比与优化建议

核对日期：2026-11-16。方法：两项独立评估，A 为 home_design_review，B 为 home_evidence；主线程另行实看当前首页、Kimi 首页及 Codex 官方产品截图。仅分析，不修改产品代码。

核心建议：保留蓝白机器人品牌、统一任务输入和右侧详情工作区；优先强化业务信息可读性、待办下一步操作以及任务续接，减少重复入口。

## 当前值得保留的设计

输入、四个业务快捷动作、待办、历史构成清晰骨架。蓝白配色与机器人有品牌辨识；详情在右侧工作区按需打开；使用指引默认收起，Esc关闭后焦点返回入口。状态有文字表达，空输入的发送按钮禁用。

## 优先问题与建议

1. P1 业务信息可读性。待办摘要11px、状态10px、历史时间10px。摘要#8994a6在白底的对比度约3.07:1，工具文字#73829a约3.90:1，低于普通文字4.5:1。建议待办标题14–15px、摘要及状态12–13px；关键金额和疑点使用更深文字，颜色只表达选中、操作和业务状态。
2. P2 首屏重心。首页顶部内边距62px，快捷入口下间距39px，问候与空输入区占据较大空间。建议问候22–24px、顶部间距32–40px；初始输入框适当收紧，按内容扩展。保留单列结构，使常见笔记本首屏清楚呈现输入和待办。
3. P2 任务续接。上海客户拜访和今日待审同时出现在侧栏、首页待办和最近任务。首页优先呈现需人工介入的事项；历史归侧栏，首页确需保留时改为有阶段和动作的“继续处理”。待办尾部提供“核对3项信息”“审阅单据”等真实动作。
4. P2 工具入口与交互预期。应用、技能、引用是工具分类，员工仍需理解区别；“技能”还会离开当前首页。建议突出添加票据、关联单据或制度，低频工具收进更多。现有四个快捷动作名称可保留，但应填入可编辑任务或打开相应选择，避免“报一笔费用”直接发送固定上海案例、“分析费用”直接执行固定10月任务。
5. P2 导航与矮屏。侧栏展开7个应用、历史、账户；1024×768检查中内容约867px，账户区掉出视口，侧栏不能独立滚动，新建按钮还发生flex压缩。建议账户固定底部，中部导航可滚动，高频应用保留，规则/技能等低频管理入口按权限收纳。

实现关联：Chat.tsx 的 Home、quickActions 和 Composer；styles.css 的 workspace-home、composer-tool、row-text、sidebar。

## 数据与状态呈现

首页待办数字和两个对象目前固定渲染，侧栏待办数量按任务状态计算。不同浏览器原有任务状态可产生“我的任务6”与“待我处理2”的差异。若首页只展示精选事项，应明确范围；若代表全部待办，需统一数据来源。不得用视觉简化掩盖真实异常或伪造完成状态。

## 有限范围启发式评分

4分为最佳。系统状态3，现实语言3，控制自由2（暂定），一致性3，错误预防2（暂定），识别优于记忆3，灵活效率2，美观极简3，帮助2（暂定）；错误恢复未验证。已观察九项合计23/36，不代表全产品质量，未验证项不计入分母。

初次员工主要遇到工具术语；高频员工主要受任务重复与下一步不明确影响；低视力和长时间办公者主要受小字与低对比度影响。

机械检测一次，退出0，输出[]；没有命中不代表没有问题。人工验证补充了文字对比、矮屏裁切及待办口径问题。浏览器状态不同，因此截图中的具体状态不互相替代。

建议改版后的验证目标：首次用户可直接判断如何添加票据或查询单据；回访用户可定位需要自己介入的事项并看到下一步；1366×768和1024×768下账户、主要操作均可达；所有状态和计数遵循真实数据；使用指引默认收起。
