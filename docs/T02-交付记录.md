# T02 / M12 身份与主数据交付记录

本轮实现服务端身份、会话与主数据部分；界面由主集成任务接入。所有身份均来自数据库和签名 Cookie，不支持 `x-user-id` 或浏览器自报角色。

## 实际文件与迁移

- `packages/identity/src/{service,ports,fixtures,index}.ts`：身份服务、可替换提供方端口、明确授权清单、七人四部门三组及主数据。
- `packages/contracts/src/identity.ts`：严格登录输入、grants、目录、城市和当前身份合同。
- `apps/api/src/modules/identity/routes.ts`：HTTP 登录、切换、注销、`/me`、目录、主数据与统一 Cookie/CSRF 上下文。
- `infra/migrations/0002_identity.sql`：身份、组织、授权、会话、委托、字典、审计与保留 180 天的身份命令账本。迁移由主集成任务统一应用。
- `tests/contracts/identity.spec.ts`、`tests/integration/authz.spec.ts`：合同与真实 PostgreSQL / Fastify 验证。

## 接口与边界

`createIdentityService(database,{sessionSecret,appMode,demoAccessEnabled,identityProvider?})` 创建身份服务；支持通过 `sessionKeys` 与 `activeSigningKeyId` 轮换签名密钥。生产拒绝演示认证，未提供就绪的正式 `IdentityProvider` 时构造失败。

公开服务包括 `getActor`、`getCurrentActor`、`requireCurrentActor`、`loginDemo`、`logout`、`validateCsrf`、`getMe`、`assertPermission`、`assertResourceAccess`、`getResourceScope`、目录与主数据查询、只读订阅委托、受控 Demo 撤权和组成员调整。

资源所有者注册 `registerResourceResolver(type,resolver)`，返回真实业务资源元数据。身份服务不复制业务单据。列表使用 `getResourceScope(ctx,'expense.read')` 返回的本人和部门范围构造数据库条件。财务人员所属财务部与销售、技术业务授权分别保存。

`registerIdentityRoutes(app,deps)` 返回与 `createIdentityHttpContext` 相同的 `{requireActor,assertCsrf}`，供所有业务路由共用。演示登录和切换仅在 `APP_MODE=demo`、服务显式启用 Demo、部署传入 `DemoAccessGate` 三者同时成立时注册。Gate 返回可信 `tenantId/environmentId/generation`。

默认 Cookie 为 `__Host-caixiaozhi_session`，`Secure; HttpOnly; SameSite=Lax; Path=/`。开发显式关闭 Secure 时使用普通 `caixiaozhi_session`；生产拒绝此配置。HTTP 登录 JSON 只返回当前身份、CSRF、到期时间和缓存失效信号，不返回会话令牌。写请求校验 `Origin`、与会话绑定的 `x-csrf-token` 及 `Idempotency-Key`。代理开发来源可通过受部署控制的 `allowedOrigins` 显式列入白名单。

会话有效期为真实服务器时间 8 小时，闲置 30 分钟失效。切换在同一事务撤销旧会话并签发新会话；重试通过数据库幂等账本返回同一会话，账本不保存明文令牌。退出不删除订阅委托。订阅只接受只读白名单，与当前 grants 和授权时范围取交集；撤销委托或组成员调整后旧上下文无法继续读取。

## 实际验证

命令：

```sh
./node_modules/.bin/tsc -p packages/contracts/tsconfig.json
./node_modules/.bin/tsc -p packages/platform/tsconfig.json
./node_modules/.bin/tsc -p packages/identity/tsconfig.json
./node_modules/.bin/vitest run tests/contracts/identity.spec.ts tests/integration/authz.spec.ts
```

结果：3 项合同测试、15 项集成测试，共 18 项通过。覆盖指定的 `manager_cannot_read_other_department`、`admin_cannot_read_employee_memory`、`production_rejects_demo_auth`、`revoked_scope_blocks_next_tool`，以及签名篡改、切换、注销、真实过期、闲置过期、CSRF 会话绑定、部门隔离、城市歧义、成本中心限制、幂等切换、订阅撤销、组失效、管理员禁止自助增权、密钥轮换、HTTP Origin / CSRF 和非 Demo 路由关闭。

## 限制与后续集成

- 正式 OIDC 的签名、issuer/audience、nonce/state 与组织映射由真正的 `IdentityProvider` 接入；当前没有伪造的生产认证实现。
- 默认七人均无 `identity.grant.manage`；授权编辑即使配置了此能力也需后续 M11 专用确认动作和部署管理范围，当前失败关闭。受控撤权入口只供服务端 Demo 场景调用，不暴露普通 HTTP 增权接口。
- SSE 建连、持续权限检查和运行中断由 M14 集成 `requireCurrentActor`；各业务模块必须注册自己的解析器并在 SQL 访问前使用授权范围。
- 此次 HTTP 验证使用 Fastify `inject`，不等同真实浏览器 Cookie 验收。HTTPS / loopback Cookie、前端缓存清理与身份切换页面由主任务继续做浏览器联调。
