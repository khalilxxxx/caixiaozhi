# 财小智 SRS 本地交互 Demo

本轮直接在财小智本地工程中开发。使用已有 React + Vite，源码位于 `apps/web/src/demos/srs-review/`；不依赖云端页面，不需要后端 Agent、数据库或外部接口。

## 本地启动

项目根目录执行：

```bash
npm run demo:srs
```

浏览器打开 `http://127.0.0.1:5187/srs-review.html`。也可在 Finder 中双击本项目的 `scripts/demos/start-srs.command`。脚本优先使用项目已安装的 Node 24，调用已有 Vite，不安装新依赖。关闭终端或按 Ctrl+C 停止服务。

如果已经在运行项目原来的 Vite 服务（5173），同一个源码入口是 `http://127.0.0.1:5173/srs-review.html`。两个端口的浏览器本地状态彼此独立，评审时固定使用一个入口即可。

修改源码后 Vite 自动热更新；`apps/web/srs-review.html` 只是 Vite 入口模板，页面由本地 TSX/CSS 实时编译。

## 这次为什么重新划分界面

原 A/B 视觉可以保留，但有三类信息膨胀：同一异常在问候、叙述、卡片、主操作重复；队列和详情同时完整展开；“记住我的判断”等文案无法对应明确的业务状态。视觉上的智能感应来自正确的结果与上下文，而不是额外解释产品如何工作。

本轮保留冷白、蓝紫点缀，调整为以下层级：

| 层级       | 首屏显示                                           | 操作及进入下一层                           |
| ---------- | -------------------------------------------------- | ------------------------------------------ |
| 对话       | 一句结论 + 结果卡片                                | 点击整个卡片                               |
| 单据概要卡 | 标题、结果状态、一行元信息（来源/申请人/关键指标） | 打开右侧抽屉                               |
| 批量概要卡 | 单据数、系统范围、3类结果数量                      | 抽屉内筛选列表，再打开单据；保持一层抽屉   |
| 单据抽屉   | 单据概况、异常、实际与要求对照                     | 规则依据折叠；查看单据、审核备注、重新审查 |
| 规则应用   | 紧凑规则表、搜索、系统/来源筛选                    | 新增、编辑、启用、停用；单条在抽屉中处理   |

普通单据卡桌面目标约80px，两行；批量卡约108px。标题单行省略，不增加独立操作栏。完整单据号、部门、版本、依据及操作不会挤进概要卡。批量列表行约77px；规则管理行61px。这些是本项目的设计约束，并非竞品规格。

通用对象示例覆盖报销和 OA。金额是可选字段：报销展示金额，OA申请展示天数，保留同一张卡片的结构。业务状态（待审批/已提交）与规则状态（需关注/待核实/未发现异常）分别展示。规则通过不等于审批通过。

## 可评审的流程

1. **审单**：默认“今日待办预审” → 点击汇总卡 → 筛选“需关注”或“待核实” → 点单据 → 查看异常、折叠依据、单据信息；可保存审核备注。返回列表仍在同一抽屉。
2. **通用卡片**：点击“查看OA待审” → 返回请假申请卡 → 查看相同结构的抽屉，关键指标显示天数。
3. **规则应用**：左侧“规则平台” → 新增规则 → 填写名称、系统、执行场景和阈值 → 保存草稿或保存并启用。个人规则使用独立ID，可以再次编辑和单独启停。
4. **自然语言辅助**：新建规则抽屉展开“用一句话生成规则”，输入“餐饮合计超过2000元时，审单时提醒我”。生成可核对表单，不直接启用。当前仅支持明确的单个金额/天数阈值，无法解析时明确提示。
5. **提单**：最近对话“上海差旅报销” → 打开草稿 → 检查单据 → 发现住宿超标 → 按标准调整 → 重新检查 → 提交。检查过期时禁止提交。提交时保存检查快照，刷新后仍可回看。
6. **定时预审设置**：左下角进入设置，修改时间和启停。演示只保存配置，不在本机后台实际运行定时任务。

## 动作和规则边界

- 删除“记住我的判断”等暗示模型记忆或规则学习的动作。审核备注仅属于当前单据，不改变制度、审批状态或规则。
- 通用规则按系统默认启用；当前身份只能查看。个人规则仅补充提醒，不允许覆盖通用规则，不自动通过或退回单据。
- 保存未启用的规则不改变预审结果；只有对应系统与执行场景的有效规则变更，才提示重新审查。历史结果不会悄悄变成新结论。
- 当前“重新审查”刷新这批演示待办，包含单据抽屉内触发的刷新。无法取得的发票查验结果仍保持“待核实”。
- 提交、预审和规则执行均为本地模拟。没有真实审批、付款、发送消息或云端发布。会话只支持内置场景，不是通用大模型。
- 规则、审核备注、定时设置和已提交草稿保存在浏览器 localStorage，键为 `caixiaozhi.srs.local.v3`；浏览器清理该键可恢复初始演示。

## 竞品依据与设计取舍

资料查阅日期：2026-11-16。依据官方文档做交互分析，没有登录或实测竞品账号。

| 参考                                                                                        | 官方描述                                                         | 本次采用的设计                                                                 |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| [Ramp Full Expense Checks](https://support.ramp.com/policy-agent-full-expense-checks/)      | 先显示最重要的发现，详细检查按需展开；该能力目前标注Early Access | 卡片只承载结果概要，证据进入抽屉                                               |
| [Ramp Transaction Review](https://support.ramp.com/reviewing-transactions-from-ramp-cards/) | 使用Approve、Request changes等明确业务动作                       | 只展示当前原型真正支持的“查看单据、审核备注、重新审查”；没有用记录备注冒充审批 |
| [Ramp Policy Editing](https://support.ramp.com/edit-your-policy-when-using-policy-agent/)   | 草稿与发布区分，编辑草稿不立即影响现行评估                       | 规则中心独立管理；保存草稿与启用分开                                           |
| [Glean Canvas](https://docs.glean.com/user-guide/assistant/glean-chat/canvas)               | 工作区在对话旁打开，承接持续编辑                                 | 保留对话上下文，右侧展开对象详情；这里只借鉴分工，不照搬文档编辑器             |

## 源码与验证

- `SrsReviewDemo.tsx`：对话、通用卡片、单据抽屉、提单、设置与状态保存。
- `RulesApp.tsx` / `rules-app.css`：规则应用、筛选、编辑表单和自然语言辅助。

- `ui.tsx` / `srs-review.css`：公共按钮、图标、抽屉、键盘焦点与整体视觉。
- `apps/web/vite.srs-review.config.ts`：独立本地服务与构建入口。
