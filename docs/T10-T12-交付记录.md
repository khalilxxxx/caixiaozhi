# T10–T12 / M06、M03、M04 与共享文件交付记录

本轮交付可运行的私有文件服务、文本制度导入检索、确定性规则及持久预审链路；业务数据继续来自 M08/M09/M10 原始表，不建立可编辑的报销副本。

## 实际文件与迁移

- `packages/files/src/index.ts`、`packages/contracts/src/files.ts`、`apps/api/src/modules/files/routes.ts`：登记、私有上传、真实内容校验、父对象授权、鉴权下载与幂等回执。
- `packages/finance/src/{database,hash,ports,knowledge,evaluator,rule-seeds,rules,preaudit,index}.ts`：制度、规则、预审及动作/作业端口。
- `packages/contracts/src/{knowledge,rules,preaudit,preaudit-eligibility}.ts`：严格输入、唯一 SRS 快照、规则 AST、版本锁、覆盖度、结果与资格证明。
- `apps/api/src/modules/{knowledge,rules,preaudit}/routes.ts`：共用可信 HttpIdentity 的 HTTP 入口。
- `infra/migrations/0006_finance.sql`：文件安全补表、制度版本/分段/引用/检索、规则版本/测试/映射、预审任务/结果/失效与事务版本守卫。已由主任务统一迁移，未修改已应用迁移。
- `apps/web/src/features/business/{BusinessDocumentDrawer,InvoicePanel,PreauditPanel}.tsx` 与 `business.css`：三业务表单、城市选择、票据核对、差异采纳、预审及审批确认界面。
- `packages/business-adapters/src/domain/documents.ts`：按主任务移交增加事务内文件绑定端口；其余业务服务仍由主任务维护。

## 接口与真实行为

`createFileService(database,storage,{identity})` 提供 `registerUpload`、`upload`、`finalizeUpload`、`getFile`、`readFile`、`bindParent`。`invoice-v1` 为 PDF/PNG/JPEG、20MiB；`policy-text-v1` 为 UTF-8 txt/md、10MiB。PDF 使用 pdf-lib 1.17.1 验证内容、加密与最多50页；PNG/JPEG 使用 pngjs 7.0.0 / jpeg-js 0.4.4 验证真实图像。版本经 npm registry 实际查询并由主任务统一安装。

上传目标仅含鉴权代理 URL、短时上传凭据、期望版本与传输类型。真正上传在数据库行锁内完成，落败的并发请求不能覆盖已接受字节。完成校验在幂等锁和文件行锁内重查账本、字节数、MIME、实际 SHA256 与文件内容；数据库和响应不暴露对象存储路径。下载逐次检查当前身份、归属与父对象权限，并再次校验内容摘要。`bindParent(...,tx?)` 支持与业务保存使用同一事务。

`createFinanceService(database,{identity,business,files,jobs?,proposeRule?,answerKnowledge?})` 暴露 `knowledge`、`rules`、`preaudit`、`preauditEligibility`，并提供顶层 `startPreaudit/getTask/getResult/searchAuthorized`。业务端口为 `getPreauditInput(ctx,id,version,tx?)`、`getApprovalTask(ctx,ref,tx?)`、`listCurrentApprovalDocuments(ctx)`。SRS 的 `input` 与 `provenance` 来自同一快照，摘要统一使用 `@caixiaozhi/platform/hash`。

`knowledge.import` 与 `preaudit.item` 使用普通 durable_jobs。`handleJob` 先续租；开始写入、最终结果和失败事务内核验租约 owner、epoch、到期、状态和演示 generation，失效 Worker 无权提交。制度分段幂等建立 UTF-16 引用、真实原文 hash、标题/行号及固定中文 bigram 全文索引。搜索先在 SQL 中限制租户、已发布版本、组织和日期，再召回；无模型时返回明确标识的授权来源摘录。

DSL 仅允许固定 AST 操作；金额使用 bigint、有理数量交叉比较，缺失、未映射或来源失败传播 unknown。存在明确公司违规时保留 risk，即使同时还有材料缺失或个人提醒；个人提醒不能覆盖公司标准。当前草稿编辑不会停用已启用旧版。测试证明绑定编译内容、测试集和映射修订；修改草稿后旧测试不能启用新内容。

预审入口只接受显式 purpose 和固定 document refs；无权混批整体 404 且不建任务。当前审核人、节点、材料、票据、规则集、映射、制度来源与权限版本进入版本锁。结果、发现和输入快照原子提交；列表读取和审批执行前同步复核。失败重试只创建所选失败项的新任务，取消保留已完成结果并标记未检项目。

`preauditEligibility.check` 返回当前 `eligible/result_hash/lock_hash/locked_versions`；`validateManualReview` 校验当前本人结果、哈希、全部发现确认及人工理由。批量候选必须为当前节点、本审核人、未失效的 low。低风险结论不会自动产生批准。

`createFinanceActionHandlers` 提供 `rule.enable`、`rule.publish`、`policy.publish`、`policy.withdraw`，由主任务注册到 M11；没有独立绕过确认的发布 HTTP 端点。

## 当前限制

- 制度首期只支持 txt/md；PDF文本提取、扫描OCR和Office转换未启用。发票PDF支持内容校验，不代表制度PDF可检索。
- 规则自然语言草稿必须注入真实 `proposeRule` 模型端口；未配置明确返回依赖不可用，不写入猜测的餐饮阈值。手工规则创建、测试与确认启用可用。
- `knowledge.question` 专用记录必须关联服务端已有 owned run；已接 `answerKnowledge` 与服务端 `knowledgeModelVersion`。每块回答检查本轮引用、当前权限、适用日期、数值和计量单位；模型失败或输出不合格时明确降级为授权原文摘录。实际模型网络调用由主任务总装验证。
- 后续由统一动作任务补充规则持久测试作业、四边界 proof 与启用守卫，细节以该模块记录和实际路由为准。映射编辑发布界面、固定配置下100×100性能报告与全量语义冲突识别尚未由本记录验证，不能据此宣称全部产品门槛完成。
- 制度冲突只识别维护者已确认的结构化 assertion；没有声称穷尽所有自然语言冲突。生产身份、模型、真实业务与保存期限仍按主设计接入。
