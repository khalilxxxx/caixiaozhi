# 财小智 v1 逐模块开发设计包

版本：1.0｜日期：2026-11-05｜技术方向：dsh 服务端 Agent + 自有 B/S 产品 + 可替换的业务 Demo。

## 1. 这套文件交付了什么

这是供产品评审和 Codex 开发使用的详细设计，不是已经开发好的应用。15 个模块各一份文件，另有总体契约、联调数据与实施计划。模块内给出用户旅程、界面与抽屉状态、模型/接口、失败分支、实施步骤和具体可验收结果。

财小智采用“对话概要 → 抽屉详情和操作 → 结果回到对话”的主交互。用户既可以点击，也可以继续问答。规则中心、Skills、预审和运维可有独立管理页面，但不将员工日常任务变成在后台菜单之间跳转。

**本次建设深度的决定：M01–M07、M13、M14 按真实产品设计；M08–M12、M15 做简易可运行 Demo。** 支撑系统可以外观简单、业务范围小，但权限、单据版本、状态转换和回执需要真实，才能验证 Agent 是否真的能协作办事。

## 3. 给 Codex 的正确使用方法

建议将整个设计包先放到项目 `docs/caixiaozhi-v1/`，让 Codex 能读取公共约束和相邻接口；每次只要求实现当前模块或明确阶段。用户不必一次要求它开发全部模块。

如果只能逐个上传，第一轮上传 00、01、02、03；之后每轮上传当前模块，并确保之前的公共文件仍在仓库。只给一个模块而不给共同契约，容易让不同开发轮次自行发明不同的身份、金额、状态和接口。

每轮要求 Codex 先核对已有代码再实现；文档规定的类型统一进入 packages/contracts，不能在每个模块复制一份略有差异的定义。已完成模块保持回归，不能为了当前模块把真实错误变成前端假成功。

### 3.1 首轮项目初始化提示词

```text
请阅读 docs/caixiaozhi-v1/ 下的 00、01、02、03 四份公共文件。
当前任务是初始化财小智项目，并完成实施计划的第一阶段。

遵守以下要求：
1. 按 dsh 路线，使用自有 B/S 前端和服务端运行适配器。
2. 先检查已有仓库；没有工程则按共同契约建立 TypeScript monorepo。
3. 公共 API、金额、身份、状态、卡片和事件类型只在 packages/contracts 定义。
4. 优先完成内网模型 + dsh + 一个受控只读工具的真实技术验证，记录精确版本与限制。
5. 测试可以有明确标识的替身；业务成功、Agent 回复、审批回执不能在产品模式伪造。
6. 实现当前阶段必要的代码和验证，不提前扩展其他模块功能。
7. 完成后列出实际修改、启动方法、已执行测试、失败项和下一阶段依赖。

如果外部模型配置缺失，请完成本地可完成的合同、存储与测试，并明确列出
接入所需配置；不要输出“已真实接通”的结论，也不要要求我批准普通可逆实现。
```

## 4. 开发次序与使用方式

不要按 M01→M15 的数字顺序机械开发。数字表示领域，不表示依赖次序。先建立公共合同和最薄运行链路，再补充业务与财务能力，最后完善产品体验与可靠性。

| 波次 | 先做什么 | 可以看到的成果 |
|---|---|---|
| 0 | 公共合同、M12 最小身份、M14 dsh 兼容验证 | 登录后跑真实模型和一个受控只读工具 |
| 1 | M11 公共动作骨架、M13 工具骨架、M01 对话骨架；最小 seed | 能创建持久任务、流式返回、等待用户和记录回执 |
| 2 | M08/M10/M09 + M11 固定审批链 | 差旅、OA、报销数据真实保存并可跨身份审批 |
| 3 | M06→M03→M04，补齐 M11 批量审批和 M01 风险抽屉 | 完整待办预审、个人规则、风险证据与低风险批量处理 |
| 4 | M05、M07、M02 | Skill 选择、图表报告、个人记忆与主动日报 |
| 5 | M14/M13 产品完善、M15 控制台、全链路验收 | 多人隔离、恢复、配额、可复位演示和生产接入准备 |

M11 和 M14 分阶段实现是有意安排：先提供稳定公共端口，再验证真实业务下的恢复与边界。各模块文件均标明完整完成条件；骨架完成不代表整个模块完成。

## 5. 必须守住的设计决定

1. 个人 Agent 是独立身份、会话、记忆、任务和空间，不是每人常驻一套服务器进程。
2. 对话帮助发起和理解；详细处理在抽屉完成，按钮和追问具有同等地位。
3. 记忆不存公司真相；个人审单阈值是正式规则，不能藏在不可审计 prompt 里。
4. 规则、预审和审批是三个阶段；预审不自动批准、拒绝或修改单据。
5. 低风险批量审批必须基于当前权限、版本、覆盖度和当前审核人的规则，并由人确认。
6. 单据真源在业务系统；聊天、抽屉、报告引用同一对象和快照。
7. 所有有影响写入使用确认、幂等、版本校验和回执；未知结果先核实。
8. SSO 可以模拟；服务端授权和跨用户隔离不能模拟。
9. Skills 可共享步骤，不能共享额外数据权；私有 Skill 不向无权用户泄露说明和源码。
10. Agent 的会话日志恢复不能替代业务事务恢复；应用任务和动作账本独立保存。

## 6. 本期明确留到后续的内容

本期不建设完整财务服务工单产品、复杂跨团队补料协同、任意技能脚本执行、自动付款、总账、复杂预算控制、多币种实时换汇、企业全量聊天搜索、通用工作流画布。费用补件先通过退回理由/材料更新/通知闭环。外部财经新闻若展示，只作为标明合成来源的可选样例，不冒充实时消息。

日历第一版按周一至周五处理，节假日服务可通过后续配置接入。未来真实 SSO、OA、报销、MaaS 的适配不改变前端合同，但各自需要提供权限、版本、幂等和回执查询能力。

## 7. 使用本包后的验收标准

第一阶段要证明 dsh 真实可接入；核心业务阶段要证明八条旅程中的对象与状态贯通；产品完善阶段要证明跨用户、并发、刷新、重启、撤权和写入结果不明时仍有正确行为。UI 好看只是其中一项，不替代数据和执行可靠性。

本设计选择的技术栈和数量参数是可执行起点，可在实现时形成 ADR 调整。调整接口/状态/权限不能只改一个模块；同步公共契约、相关模块和验收数据，保留迁移与回归证据。
