# M06 制度知识库与问答

版本：1.0｜性质：产品级模块详设，供 Codex 分阶段实施；本文不表示功能已经实现。
依据：[总体架构与公共契约](./01_总体架构与公共契约.md)、[联调验收与演示数据](./02_联调验收与演示数据.md)。

## 1 定位 依赖与范围

本模块把真实导入的制度文件变成可检索、可引用、可追溯的知识，支持对话问答和规则来源绑定。
知识回答是带来源的解释；是否符合制度由 M03/M04 的版本化确定性规则处理。
M12 提供身份、组织与政策读写授权；M13 提供文件能力、模型能力和工具目录；M14 提供可靠导入任务。
M01 承载 policy_answer 卡片、来源抽屉和连续追问；M03 引用制度段落，M04 展示冻结的引用证据。
M02 可保存用户明确表达的展示偏好，不把个人会话、未确认答案自动写入公司制度。
首期必须真实支持 UTF-8 的 .txt/.md 上传、解析、分段、发布、中文检索、引用验证和问答反馈。
PDF 文本提取作为可启用扩展；未部署经过验证的 PDF parser 时明确显示“不支持，请上传文本版本”。
扫描 PDF、图片 OCR、Office 转换、爬取任意网址和全公司网盘同步均不作为首期完成前提。
没有向量库也可完成首期；PostgreSQL 全文索引配合固定中文分词，必须有实际召回测试。
不得用写死问答、只匹配关键词返回固定 800 元、模型直接浏览未授权文件替代本模块。

## 3 角色与授权

| 行为 | 员工 | 主管 | 授权财务维护者 | 平台管理员 |
|---|---|---|---|---|
| 搜索已发布适用制度 | 授权组织 | 授权组织 | 明确授权范围 | 无默认业务权 |
| 查看历史适用版本 | 有历史阅读权的组织 | 同左 | 明确授权范围 | 无默认业务权 |
| 创建个人问答及反馈 | 本人 | 本人 | 本人 | 有业务权才可 |
| 上传、编辑政策草稿 | knowledge.manage + policy维护范围 | 同左 | 同左 | 管理员角色不代替授权 |
| 发布、撤回制度 | knowledge.manage + policy发布/撤回资源动作 | 同左 | 同左 | 同左 |
| 查看他人澄清详情 | 无默认权 | 无默认权 | 授权受理范围 | 仅运行元数据 |

平台权限名严格复用01的 knowledge.manage；维护、发布、撤回通过 policy 资源动作及组织范围约束，不增设平台权限别名。所有服务使用 ActorContext，不接受模型声明身份。
search_scope 由当前授权组织交集计算，用户选择其他部门不能扩大交集；有歧义才询问目标组织。
同一制度可对多个组织适用，但知识阅读权、维护权与规则发布权分别授予。
上传附件也继承政策草稿的权限；没有正文权限不能通过文件名、摘要、命中数或下载绕过。
检索缓存键包含 tenant_id、actor_id、authz_version、有效日期、组织范围和 corpus_revision。
问答记录默认仅创建者可读；共享政策不代表相应问答或员工提供的行程信息也共享。

## 4 用户旅程与界面

### 4.1 制度问答与连续追问

1. 李娜输入“下周去杭州，住宿标准是多少”；Agent 读取业务时钟并提取目的地和日期候选。
2. 对“下周”若覆盖制度切换日，询问实际入住日期；日期已能确定则展示采用的区间，不反复确认。
3. 服务端用李娜所属授权组织、住宿场景和业务日期检索；未发布或无权制度不参加排名。
4. policy_answer 卡片展示短答案、“演示制度”标记、生效日期、适用范围和引用序号。
5. 点击引用打开 knowledge 来源抽屉，定位标题路径、版本和原文，允许展开相邻段落。
6. 追问“超标怎么办”，重新查询例外条款；只有住宿限额证据时回答未检索到例外流程，不推断可审批报销。
7. 无证据或存在冲突时可“补充条件”或“提交澄清”；创建澄清记录不自动向他人发送通知。
8. 切换账号后旧来源链接、问答记录和下载入口重新检查权限，不沿用上一账号的已授权结果。

### 4.2 导入与发布

维护者从“制度维护”进入列表，选择文件，填写名称、制度代码、责任人、组织、有效日期和版本说明。
上传展示真实字节进度；上传完成与解析完成分开显示，禁止固定计时动画冒充处理进度。
解析预览分三栏：版本元数据、标题树/段落、原文定位；错误定位到行号，空文件不能发布。
维护者确认解析结果，检查与现行版差异；发布摘要显示生效区间、受影响组织和依赖规则数量。
点击发布经 M11 通用确认服务执行 policy.publish；服务器重检草稿版本与发布权限。
新版本发布时间不替代生效日期；未来生效版可以发布，但生效前正常查询仍命中现行适用版。
发布后旧版本保持可追溯；更正原文、调整组织或生效日均创建新版本，不直接改已发布文本。

### 4.3 页面与局部状态

| 区域 | 必备内容 | 异常/空状态 |
|---|---|---|
| 对话回答卡 | 结论、口径、适用条件、引用、来源更新时间 | 无证据/待澄清/证据冲突分别显示 |
| 来源抽屉 | 精确段落、标题路径、版本、生效区间、前后文 | 被撤回、版本已替代或无权时不继续展示缓存 |
| 制度列表 | 发布状态、生效状态、责任人、授权组织、搜索 | 空库引导有权人员导入，不显示示例答案 |
| 草稿预览 | 解析警告、差异、引用锚点、发布操作 | 文件不支持/解析失败可替换或重试 |
| 澄清列表 | 个人问题、引用、处理结果、当前状态 | 没有处理权限只能查看本人条目 |

publication_state=draft/published/withdrawn 是政策版本领域状态；effective_state=future/current/historical 是日期投影。
import_stage=uploading/validating/parsing/indexing/ready/error 是导入领域阶段；普通 durable_jobs 保存 job_id 与可空 origin_run_id，不进入 Agent run_jobs 或占用 DSH 会话。
answer_state=answered/needs_clarification/no_evidence/conflict/degraded 是答案类型，不替换 run.status。
来源抽屉遵循公共宽度、路由和焦点约定；状态文字可读，不能仅用颜色表达冲突。

## 5 领域模型与字段约束

所有实体继承公共 id、tenant_id、version、created_at、updated_at；跨租户外键拒绝。

| 实体 | 主要字段 | 约束 |
|---|---|---|
| policy | policy_code、title、owner_id、maintainer_group_id、latest_published_ref | tenant+policy_code 唯一；标题非空≤200 字 |
| policy_version | policy_id、version_no、publication_state、source_file_id、content_hash、parser_version、supersedes_version_id | 发布版不可变；版本号递增；替代关系经人工确认 |
| policy_applicability | version_id、organization_ids、effective_from、effective_to、topic_tags | 日期左闭右开；end 可空且必须大于 start |
| policy_import | version_id、file_hash、stage、job_id、origin_run_id、parser_version、error_location | 同租户/版本/file_hash/parser 唯一；来源run可空 |
| policy_source_text | version_id、original_hash、normalized_text、normalization_version、offset_map | 保存引用基准文本及原文映射 |
| policy_chunk | version_id、ordinal、heading_path、text、start_line、end_line、content_hash、search_vector | 位置基于固定 normalization_version |
| policy_citation | policy_ref、chunk_id、quote、start_utf16、end_utf16、quote_hash、locator | 精确切片可验证；quote 非模型自由生成 |
| knowledge_question | owner_id、query、business_date、context_json、answer_state、origin_run_id | 本人私有；绑定 M01 已存在且授权的run，不进入公共政策索引 |
| knowledge_answer | question_id、answer_blocks、citation_ids、retrieval_snapshot_id、model_version | 制度事实块必须含 citation_ids |
| knowledge_clarification | owner_id、question_id、reason、referenced_policy_refs、status、resolution | open/in_review/resolved/closed；保留过程 |
| knowledge_feedback | owner_id、answer_id、kind、comment、citation_id | kind=helpful/incorrect/outdated/missing_context |
| knowledge_corpus | revision、effective_boundary、indexer_version | 每次发布/撤回/生效切换单调递增 |
| policy_assertion | version_id、chunk_id、topic_key、unit、normalized_value、scope、effective_interval、supersedes、confirmed_by、status | 维护者确认后才参与确定性冲突检测；保留原段落及hash |

policy_ref 使用公共 ResourceRef 的 type=policy、id=policy_id、version=version_no，不能把 chunk_id 当政策 ID。
organization_ids 必须来自 M12；全组织使用明确 tenant 范围标识，禁止把空数组解释为全公司。
场景字段只允许 module、category、city_code、employee_grade、travel_start、travel_end；按字段声明的权限读取。
employee_grade 等未知信息保留 null，不凭职务名称猜测等级；存在差异标准时转澄清。
单文件首期上限 10 MiB、最多 200 万 Unicode 字符；上限可配置但不可在前端单独放宽。
同内容重新上传可复用私有字节对象，但不得复用其他租户的政策 ID、权限或检索结果。
policy_chunk 和 citation 永久绑定源版本；更新文件不得使历史引用悄悄指向新文本。

## 6 导入 解析 分段与来源定位

### 6.1 文件处理的确定顺序

先注册上传获得 file_id、上传目标与大小约束；私有上传后 finalize，校验实际字节、MIME、扩展名和 hash。
finalize 成功才进入解析队列；伪造 text/plain 的二进制、非法 UTF-8、嵌入 NUL 字符返回 VALIDATION_ERROR。
UTF-8 BOM 可剥离并记录；换行统一 LF、Unicode 统一 NFC，保存 normalization_version 与原文偏移映射。
Markdown 保留源文本，解析标题、列表和表格为可检索段落；代码块作为数据，不执行脚本或链接。
段落按标题边界切分，目标 400–800 中文字符、上限 1200；过长段落按句界切，表格保留表头语义。
交叠最多 100 字符，保存 segment_span；相邻重叠引用需去重，不能让同一条款占据全部 top_k。
短段落按同一标题邻接合并，禁止跨不同生效范围或权限边界合并。
分段、hash、全文索引在 staging 区完成，完整成功后原子切换 ready；半成品不可检索。
重试根据版本/hash/parser_version 复用已完成阶段，避免产生重复 chunk 或重复政策版本。

### 6.2 精确引用约定

文本定位包含 source_file_id、normalization_version、heading_path、1-based start_line/end_line 和半开 UTF-16 偏移。
start_utf16/end_utf16 是 chunk.text 内偏移；locator.source_start_utf16 是整份规范化源文本偏移，二者不能混用。
quote 必须等于 chunk.text.slice(start_utf16,end_utf16)；quote_hash 为该切片 UTF-8 字节 SHA-256。
抽屉先取已授权固定版本，再验证 chunk 与 quote hash，最后高亮；校验失败报 SOURCE_CHANGED 子原因并提示重新取证。
原始文件下载与规范化文本查看分开标识；用户看到的行号注明“导入文本行号”，不谎称 PDF 页码。
启用 PDF 文本扩展时保留页码、页内字符范围、提取器版本；没有可靠坐标就只支持文本定位，不画伪矩形。
空白或纯图片 PDF 返回文本提取不足，不能将“未提取”当“制度没有写”。
M03 保存 citation_id、policy_ref、chunk_hash、quote_hash；M04 通过这些引用显示相同的已冻结证据。
引用示例中的 hash 由实际导入计算，不在 seed 中填写任意占位 hash 充当验证结果。

## 7 检索和问答算法

1. 校验 query 长度 1–1000 字、business_date、context strict schema；拒绝自由 SQL、网址抓取或未声明字段。
2. 从 ActorContext 计算授权组织与政策 grant，记录 authz_version；跨组织不明时返回 requires_input。
3. 按已发布、未撤回、组织适用和日期区间生成 authorized_versions 子查询，然后才召回 chunk。
4. 固定 ChineseTokenizer 接口和版本；首期可用可复现中文分词加 CJK bigram 备选索引，不依赖英文空格分词。
5. 用参数化 plainto_tsquery/固定构建 tsquery 与 ts_rank_cd 召回；查询词不能注入运算符或 SQL 结构。
6. 可用 pg_trgm 做词形容错；所有候选仍受相同 authorized_versions 约束，不能先全库召回再裁掉无权结果。
7. 采用固定权重的主题/标题/正文排序，版本 ID+chunk.ordinal 稳定打破平分，去除相邻重复，默认 top_k=6、最大10。
8. 保存 retrieval_snapshot：查询、日期、授权范围 hash、corpus_revision、命中引用与排序版本；不保存无权候选。
9. 同一 policy_code 的版本按适用时间唯一解析；不同制度重叠且条款相互矛盾，返回 conflict 并列授权证据。
10. 仅将授权片段、精确引用 ID 和任务问题交给 AgentRuntimeAdapter；来源文本标成不可信材料。
11. 输出按 answer_blocks 校验：制度事实句有至少一条有效引用；金额、单位和条件须能在引用片段中定位。
12. 无命中返回 no_evidence；证据缺少适用条件返回 needs_clarification；模型失败返回 degraded 的真实来源摘录。

同一政策同组织同时间区间不能发布两条竞争主版本；明确 supersedes 关系后在事务中收敛旧版有效区间。
跨制度冲突不能由“较新文件”“得分更高”自动裁决；仅明确登记的优先级关系或人工发布决定可解决。
首期确定性冲突检查使用维护者确认的 topic_key、适用范围、effective interval、unit、规范值；同 topic 在范围/时间交集内 unit/值不同且无明确覆盖关系即 conflict。
未结构化段落可由人工标 conflict_group；模型只能建议疑似冲突待复核，不能声明已穷尽语义冲突检测。
“800 元/间夜”不得被生成成“800 元/人/天”；超标是否可报、例外谁批准都必须另有相应条款。
历史问题按明确 business_date 返回当时适用版本，卡片标历史；默认查询使用演示业务时钟而非任意服务器日期。
被撤回版本不进入普通或历史问答；有审计权限的历史引用查看走专用只读路径并显示撤回状态。
检索无结果只说明当前授权、当前条件下未找到依据，不可断言全公司不存在相关政策。
可扩展 EmbeddingProvider.embed/query，但须固定内网模型、向量版本、权限预过滤与索引迁移策略。
向量索引不可用可降级到全文检索并记录模式；无权限的候选不得以“语义相近”进入模型上下文。

## 8 API 与工具 schema

路径统一加 /api/v1；修改使用 Idempotency-Key，编辑带 expected_version；公共错误 envelope 不另造。

| 方法与路径 | 请求关键字段 | 返回/语义 |
|---|---|---|
| GET /knowledge/policies | query、organization_id、publication_state、cursor | 只列授权政策，维护过滤需维护权 |
| POST /knowledge/uploads | filename、mime_type、size_bytes、policy_id? | file_id、私有上传目标、expires_at |
| POST /knowledge/uploads/{id}/finalize | content_hash、expected_version | 202 import_id/job_id；后台校验真实 hash |
| GET /knowledge/imports/{id} | 无 | stage、真实进度、warnings、error_location |
| PATCH /knowledge/policies/{id}/draft | expected_version、metadata、source_file_id | 返回新草稿及发布检查项 |
| POST /confirmations | action=policy.publish/withdraw、resource_refs、args | M11 确认；不直接发布 |
| POST /knowledge/search | query、business_date、context、top_k | retrieval_snapshot_id、hits、conflicts |
| POST /knowledge/questions | query、business_date?、context? | 202 question_id/origin_run_id；仅限M01既有run内部调用 |
| GET /knowledge/questions/{id} | 无 | 答案、引用、澄清问题、状态 |
| GET /knowledge/citations/{id} | 无 | 授权固定版本原文与定位，不返回任意存储 URL |
| POST /knowledge/clarifications | question_id、reason、comment | 私有/受理范围内澄清记录 |
| POST /knowledge/feedback | answer_id、kind、comment?、citation_id? | 保存反馈回执 |

导入使用 M14 可靠领域 job，返回 job_id 而非新 Agent run；独立制度后台直接轮询 imports 并预览 search 命中。
questions 只记录 M01 当前会话已有 run 的问答，origin_run_id 由服务端注入且必有；没有既有 run 时返回 INVALID_STATE。
该 API 不创建 run、不新增后台 Agent origin；后台检索预览不经过 questions，问答重试在同一 question/既有 run 边界中恢复。
finance.knowledge.search@1.0.0 的 arguments 与 POST /knowledge/search 共用 strict schema，required=query/business_date。
context 可省略；传入时 module 为 expense_claim/travel/oa_request，category 为六种 SRS 类别之一，其余字段沿用字段表。
不接受 actor_id、tenant_id、任意 organization_ids、include_unpublished 或 bypass_acl 参数。

```json
{"name":"finance.knowledge.search","version":"1.0.0","run_id":"run-06","call_id":"call-06","arguments":{"query":"杭州住宿标准","business_date":"2026-11-10","context":{"module":"travel","category":"lodging","city_code":"330100"},"top_k":6}}
```

```json
{"status":"ok","data":{"retrieval_snapshot_id":"ks-06","business_date":"2026-11-10","hits":[{"citation_id":"cit-pol-expense-lodging-v1","policy_ref":{"type":"policy","id":"pol-expense","version":1},"heading_path":["差旅报销","住宿"],"quote":"住宿演示标准为每间夜800元。","locator":{"kind":"text_lines","start_line":7,"end_line":7},"chunk_id":"pc-lodging-1","start_utf16":0,"end_utf16":15,"quote_hash":"0272f07c56bff5cfc2d8a146fedb5f535ccf9b45ce7fd2735fbf6a6b92208d2c","effective_from":"2026-01-01","effective_to":null,"organization_label":"当前授权组织"}],"conflicts":[]},"evidence_refs":["cit-pol-expense-lodging-v1"],"action_id":null,"error_code":null}
```

示例引用仅说明 schema；真实导入的原文、行号、偏移和 hash 必须从实际 fixture 生成，不能照抄示例位置。
工具结果命中项必含示例中的 chunk_id、start_utf16/end_utf16、quote_hash、effective_from/to、organization_label；null 结束日期表示无计划终止。
返回 exceeds_context_budget 时保留授权 snapshot，通过来源抽屉读取；不得截断半句话后继续声称引用完整。
ToolResult.status=requires_input 用于缺场景条件；status=ok 且 hits=[] 表示无证据，两者不能混淆。

## 9 版本变化与异常恢复

policy.publish/withdraw 事务同时更新版本索引、corpus_revision 和 policy.version_changed outbox。
未来生效版在边界到达时通过可重入调度更新 corpus_revision；服务端查询日期过滤始终是最终依据。
M03 消费事件后把实际依赖的来源标 source_review_required；新规则绑定必须由有权人员复核确认。
M04 对受影响 policy_ref 的结果标 stale；M11 执行前同步检查版本依赖，不等待 outbox 才发现失效。
历史证据保留原文与撤回说明，不能删引用来伪装旧预审从未使用该制度。
知识回答可以提出“生成规则草稿”入口，用户选择后交 M03；检索、回答、反馈都不自动启用审批规则。
文件上传断线可在有效期内续传；过期重新注册，未 finalize 的孤立对象由定时清理任务回收。
导入 worker 崩溃后从已提交阶段恢复，租约由 M14 管理；同一 hash/parser 重试不得重复索引。
发布事务失败保留上一现行版；索引失效时搜索报告依赖不可用，不能退回未经鉴权的全量文本。
权限在检索后被撤销，模型调用前再次核验 snapshot 授权；最终答案持久化/返回前仍核验，必要时拒绝返回正文。
解析告警可由维护者确认，但字符丢失、缺失文件和版本 hash 不匹配属于阻断发布错误。
错误详情使用公共 code 与 reason：UNSUPPORTED_FORMAT、INVALID_ENCODING、PARSE_FAILED、SOURCE_CHANGED、POLICY_CONFLICT。
用户纠错只追加 feedback；受理人可给澄清意见，改变制度要求必须新建政策版本再走发布。

## 10 Codex 分阶段实施建议

### 阶段一 文件和领域契约

创建 packages/contracts/src/knowledge.ts，定义 ImportCommand、SearchQuery、Citation、GroundedAnswer 和 strict schemas。
创建 infra/migrations/*_knowledge.sql：政策、不可变版本、文件、chunk、citation、授权范围、问答和 outbox 外键。
实现 apps/api/src/modules/knowledge/files.ts 的 registerUpload(ctx,input) 与 finalizeUpload(ctx,id,input) 签名。
接入私有对象存储，服务端独立计算 hash；只保存文件元数据不算完成真实导入。
断言伪 MIME、超限、跨租户 file_id、重复 finalize 和非法 UTF-8 分别返回稳定结果。

### 阶段二 解析和索引流水线

实现 parsers/text.ts、parsers/markdown.ts、chunker.ts、source-locator.ts、indexer.ts；PDF parser 作为独立可选注册项。
核心签名 parsePolicy(bytes,format,parserVersion):ParsedPolicy，chunkPolicy(parsed,options):Chunk[]，verifyCitation(citation,source):boolean。
后台执行放 apps/worker/src/runner/knowledge-import.ts，导入状态与 checkpoint 真实持久化。
断言多字节汉字、emoji、CRLF、表格、重复段落的定位与引用切片一致；重试 chunk 数和 hash 不变。

### 阶段三 权限检索和有据回答

实现 search.ts 的 searchAuthorized(ctx,query):RetrievalSnapshot，resolver.ts 的 resolveApplicableVersions(ctx,date,context)。
SQL 通过 Drizzle/参数化查询组合固定权限条件；中文 tokenizer 版本显式配置并包含检索回归样例。
实现 answer.ts 的 buildGroundedAnswer(ctx,snapshot,modelResult)；通过项目 AgentRuntimeAdapter 调用模型，勿编造 DSH 原生知识库 API。
在 M13 注册 finance.knowledge.search；无模型时展示引用摘要，模型接入后校验事实块与 citation 的绑定。
断言无权 chunk 从检索到模型请求全链路不存在，错误等级、缺日期、冲突版本均不能产出确定标准。

### 阶段四 发布和跨模块失效

实现 publish.ts 的 publishPolicy(ctx,intent,expectedVersion):ActionReceipt 和 withdrawPolicy，同 M11 共用动作账本。
实现 dependents.ts 的 listPolicyDependents 与事件处理，M03/M04 消费保持幂等、可补偿；禁止跨模块直接写私有表。
断言并发发布只成功一条；新版本生效、撤回、权限撤销均触发后续查询/审批的同步复核。

### 阶段五 产品页面和运维证据

创建 apps/web/src/features/knowledge/{PolicyAnswerCard,SourceDrawer,ImportPanel,PolicyVersionDiff,ClarificationPanel}.tsx。
补 tests/contracts/knowledge、tests/integration/knowledge、tests/e2e/knowledge-answer.spec.ts 和真实模型集成样例。
建立召回基准：住宿、间夜同义词、城市上下文、无依据例外、中文长问句、权限负例；记录实际召回和引用准确率。
将 parser、indexer、corpus_revision、队列时延、无证据率、引用校验失败数接入 M14，日志默认不保留敏感全文。

## 12 完成门槛

真实 txt/md 从上传到解析、发布、检索、答案、来源抽屉跑通；刷新与 Worker 重启后状态可恢复。
