# M01 对话、卡片与抽屉交互

版本：1.0｜设计日期：2026-11-05｜实现深度：产品级｜依赖：01 总体架构与公共契约。
本文是可交给 Codex 的实施规格，不代表已经实现；公共枚举、Money、身份与确认机制以 01 为准。

## 1. 上下文、职责与边界

目标是让员工、主管和财务从自然语言进入真实业务，在概要中理解结果，在抽屉中检查证据并完成操作。
生产界面由财小智自主 React 前端提供；dsh Web 与旧 HTML 只可作为视觉参考，不作为产品壳、状态源或浏览器通信协议。
M01 拥有会话、消息、卡片投影、抽屉绑定和导航；不拥有单据、预审、规则、指标、业务动作或 dsh 会话内部格式。

| 依赖 | M01 消费的能力 | 不可跨越的边界 |
|---|---|---|
| M02 | 能力卡未读数、收件箱条目、用户明确保存的偏好 | 首页刷新不把提醒写入聊天；聊天内容不自动变记忆 |
| M03/M04 | 规则建议、预审任务及权威分组 | 展示颜色不能替代规则结果；低风险不能自动审批 |
| M05/M06/M07 | Skill 选择、政策引文、分析快照 | 无权源码、知识和明细不能从卡片绕过授权 |
| M08–M12 | 当前单据、字段校验、审批动作、身份范围 | 抽屉使用共同应用服务，不另写一份业务数据 |
| M13/M14 | 工具结果、持久 run 事件、取消与恢复 | 不直接连接 SDK，不解释 dsh 私有消息，不生成确认 token |
| M15 | 明确标记的演示数据与故障开关 | 产品组件不读取 demo 全局变量或硬编码成功响应 |

## 2. 编号核心需求

- M01-R01：首页只展示输入框、常用任务、能力卡与未读数；首次进入不得创建 thread/run/message/card。
- M01-R02：能力卡包含自然名称、最多两行概要、一个主要数量及未读圆点/数字；名称采用“待我审批”“准备报销”“费用分析”“政策问答”。
- M01-R03：所有金额、条数、风险标签、权限按钮来自后端领域服务；模型仅提供经校验的标题和说明。
- M01-R04：同一 thread 只能有一个非终结 run，等待用户和等待确认均包括在内；刷新、多标签页和双击发送都不能绕过。
- M01-R05：新消息默认续接当前等待任务；独立任务需明确另开会话，或在当前任务终结后启动。
- M01-R06：一次结果默认一张概要卡；补充解释更新文本，任务进度更新同一卡片，禁止每个工具调用都生成卡片。
- M01-R07：抽屉提供清单、详情、证据、字段修改与确认；用户不必再到聊天框复述保存/确认内容。
- M01-R08：继续追问必须携带用户当前选择的明确资源引用；存在多个对象时询问选择，不能猜“这张”。
- M01-R09：历史卡显示生成时间与对象版本；展开时读取最新数据，版本变化后必须重新核验和确认。
- M01-R10：HTTP 提交命令，SSE 接收持久事件；断线、重复事件、乱序和游标过期都有恢复路径。
- M01-R11：业务成功仅根据 ActionReceipt；202、模型说“完成”或 run.succeeded 均不能单独构成审批成功。
- M01-R12：每次打开、下钻、附件预览、SSE 订阅、保存和确认重新鉴权；身份切换立即清理旧数据。
- M01-R13：键盘可完成核心旅程；摘要、风险状态、更新状态均有文本，不依赖颜色和鼠标悬停。
- M01-R14：首次加载、空态、部分成功、等待确认、取消、未知结果与依赖故障均使用真实数据状态。
- M01-R15：支持深链接、浏览器返回、抽屉关闭后滚动恢复；URL 不含姓名、金额、token 和原始附件地址。
- M01-R16：对话展示简短执行步骤和证据，不展示隐藏思维链、原始工具密钥或未经处理的工具报错。

## 3. 角色、权限和数据范围

| 身份 | 可见入口 | 默认范围 | 动作要求 |
|---|---|---|---|
| 普通员工 | 准备报销、我的申请、政策问答 | 自己的会话与有权业务资源 | 保存草稿与提交按业务权限；提交须确认 |
| 销售主管张伟 | 待我审批、预审、费用分析 | 本人会话和已授权销售部数据 | approval.decide 与当前审批节点同时满足 |
| 财务刘敏 | 财务待办、规则、分析 | 显式授权财务范围 | 公司规则、导出等另校验对应权限 |
| 平台管理员赵磊 | 平台诊断入口 | 操作元数据 | 默认不能打开任何员工会话、卡片、抽屉或附件 |

thread、message、card 均为用户私有；领导角色不获得下属聊天读取权。
分享业务对象不分享其对话。卡片资源失权后仍可显示“不再有权查看”，但不得继续返回旧名称、金额或摘要。
未授权资源与不存在资源返回 404；已能查看对象但不能执行动作返回 403。

## 4. 信息架构与界面规格

### 4.1 首页

桌面 ≥1280 px：左侧导航 220 px；主内容最大宽度 1080 px；上下内边距 32 px；首页不铺满统计仪表盘。
主内容从上到下为“财小智”标题与一句提示、最大宽 800 px 的输入框、常用任务、能力卡；收件箱入口在页头右侧。
输入框最小高度 112 px、最大高度 240 px；支持 Shift+Enter 换行；中文输入法 compositionend 前 Enter 不发送。
输入最多 8,000 字符；附件区显示上传中/校验中/可使用/失败，只有 M09 确认可使用的附件可随消息提交。
常用任务用最多 4 个文字按钮，如“检查待审报销”“帮我准备差旅”“分析本月费用”“查报销政策”。
能力卡宽 248–344 px、最小高 124 px、桌面最多 3 列；标题 16 px、概要 14 px、数字 24 px；不展示密集图表。
“待我审批”的概要示例为“有 5 张销售部报销等待处理”，其数量来自授权待办；未读数来自 M02，二者分别标注。
能力卡不可用时写明“暂时无法读取待办”及重试按钮，不用 0 代替接口失败；无权限入口不显示。
首次空态为“可以从一件具体的事开始”；已授权但无待办显示“当前没有待处理单据”；不自动推送开场对话卡。
页头收件箱更新只改变未读数，保留当前输入、焦点、滚动和已打开抽屉。

### 4.2 会话主区

桌面主区宽 720–960 px；打开抽屉时会话仍保留至少 420 px 可读宽，空间不足转覆盖式面板。
消息正文建议 15–16 px、行高 1.6；概要卡标题最多 32 字、摘要最多 140 字；超长说明放“查看详情”。
卡片常态包含标题、两行概要、最多 3 个关键值、状态、生成时间、主要按钮和至多 2 个次要操作。
流式文本占位显示“正在整理结果”；工具状态示例“正在读取待审报销”“正在核对票据”，不显示模型内部推理。
输入框上方的任务条显示排队/处理中/需要补充/待确认/正在核实；活动任务始终提供查看详情，允许时提供停止。
历史卡显示“生成于 09:10 · 单据版本 3”；已知版本变化增加“数据已有更新”；点击打开仍重新校验。
用户正在阅读历史内容时，新内容出现“有新消息”按钮，不强制滚到底；距底部 ≤80 px 时才自动跟随。

### 4.3 抽屉

桌面默认宽 640 px，可在 560–720 px 范围调节；扩展模式不超过主区 70%；≤900 px 使用全屏面板。
顶部固定：返回上一层、标题、对象状态、关闭；底部固定：保存/确认操作区；正文独立滚动。
清单用紧凑行展示姓名、单据号、金额、分组和一行原因；20 行分页；首屏不出现超过 8 个业务列。
详情分为“基本信息”“费用明细”“检查结果”“材料与记录”；先显示本次任务最相关的页签，不隐藏其他证据。
改字段时显示原值→建议值、来源和校验提示；AI 建议须选择后采纳，手工改动保存即明确保存意图。
关闭未保存表单显示“继续编辑 / 放弃修改”；关闭确认面板不会默认确认，保留尚未过期的动作意图。
切换同一清单的对象时保留清单筛选和滚动；保存成功后局部更新当前对象，再由后端刷新受影响概要。

### 4.4 无障碍与视觉状态

所有点击目标至少 44×44 px；正文对比度达到 WCAG AA；分组同时有标签“明确风险/材料不完整/需要关注/低风险”。
抽屉使用 aria-modal=true 和焦点圈定；打开聚焦标题，关闭回到触发按钮；Esc 遵循未保存拦截。
流式增量不逐字朗读；aria-live=polite 每段或状态变化通知，业务错误用 alert；减少动画设置关闭光标闪烁。
加载使用骨架，≤300 ms 不闪空态；超过 10 秒显示“仍在处理，可稍后回来”；超时标准由 M14 返回。

## 5. 完整用户旅程与状态转换

### 5.1 从首页处理待审报销

1. 张伟登录，GET /home 返回 5 张待审，总额 5,540.00 元；只渲染首页能力卡，无 thread 创建。
2. 点击“检查待审报销”，POST /home/entries/approval-review/open；服务端创建或续接该入口绑定的会话。
3. 无现有任务则持久化用户消息和 queued run，返回 thread_id/run_id；进入会话页订阅事件。
4. 工具读取授权清单并启动 M04；进度复用一张 preaudit_summary 卡，不为每张单据追加卡片。
5. 完成后显示 2 低风险、1 关注、1 风险、1 不完整；低风险 1,240.00 元，合计 5,540.00 元。
6. 点击“查看清单”打开抽屉，默认全量分组；选择“低风险”只显示 clm-001、clm-005。
7. 点击“审批选中项”，服务端基于当前版本准备 M11 confirmation；抽屉显示两项、金额、节点和影响。
8. 浏览器点击确认后执行；收到逐项回执再显示成功。若两项成功，显示转财务待审，张伟剩余 3 张。
9. 用户追问“那张住宿超标怎么回事”，有唯一 clm-003 上下文时附其 ref 查询，否则要求点选。
10. 同一预审任务继续解释只追加文字；新建 action_result 卡用于呈现这次独立、有回执的审批结果。

### 5.2 填单、修改和提交

用户说“帮我准备下周去上海的差旅”，缺出发地/日期时 run=waiting_user；补充消息续接原 run。
M08 返回草稿建议后生成 draft_proposal；抽屉区分建议值与已保存业务值，未采纳前不得显示“已保存”。
用户勾选建议并点击“采纳 3 项”，调用领域 patch 服务；字段错误保留本地输入并定位第一项错误。
用户点击“提交申请”，读取最新单据并生成 confirmation；确认后等待真实回执；成功卡深链接到同一单据。
若用户在等待补充时改问政策，提供“在此任务中查询”或“新会话查询”；选前者执行只读子步骤后回到待补充。

### 5.3 新消息、续接与多端竞争

| 当前 run 状态 | 默认发送行为 | 新独立任务行为 |
|---|---|---|
| 无活动任务 | 创建用户消息与新 run | 同默认 |
| queued/running | 明示“补充给当前任务”，持久化输入，下一安全检查点消费 | “另开会话”，不同时启动第二个本线程 run |
| waiting_user | 继续当前 run，并展示已补充字段 | 另开会话，或明确取消当前任务后发送 |
| waiting_confirmation | 作为澄清/修改意图；涉及范围变更先使旧确认失效 | 另开会话；不把新消息当成对旧动作的确认 |
| reconciling | 允许询问状态；写操作入口冻结，保持原 action | 另开会话执行独立读任务 |
| interrupted | 默认只保存草稿；必须点“继续任务”或“结束任务” | 另开会话 |
| succeeded/failed/cancelled | 新 run 继续当前 thread，引用必要历史 | 可使用新会话按钮 |

M14 持有唯一活动任务约束；需要显式恢复的 interrupted 保留 thread.active_run_id，恢复不创建第二个活动 run。
新增输入使用 client_message_id 幂等；两个标签页同时发送由服务端串行判定并返回同一活动任务或 409。
用户“停止”只停止未执行步骤；若写动作执行中则展示“已停止后续步骤，正在核实本次结果”。

## 6. 卡片与抽屉契约

AgentCard 直接使用公共契约；type 是固定枚举，payload 用判别联合校验，禁止 z.any() 和自由 JSON 穿透前端。

| type | 必需 payload 字段 | 默认抽屉 |
|---|---|---|
| todo_summary | count, total:Money, list_scope, source_as_of | 待办清单 |
| preaudit_summary | preaudit_task_id, counts, totals, progress, reviewer_id | 预审分组清单 |
| document_summary | document_ref, status, total:Money 或 null, missing_fields | 单据详情 |
| draft_proposal | proposal_id, base_ref 或 null, changes, validation_summary | 字段差异 |
| rule_proposal | proposal_id, rule_ref 或 null, test_summary 或 null | 规则建议与试跑 |
| policy_answer | answer, citation_refs, effective_at, unresolved_questions | 政策证据 |
| analysis_result | analysis_ref, metric_id, filter_summary, coverage | 分析图表与下钻 |
| report_result | report_ref, generation_status, download_action 或 null | 报告详情 |
| skill_result | invocation_id, skill_ref, result_kind, evidence_refs | Skill 结果 |
| action_result | action_ids, receipt_ids, outcomes, affected_refs | 逐项动作回执 |
| reminder_summary | inbox_item_id, generated_at, subject_refs, read_only | 主动摘要详情 |

counts 固定含 risk/incomplete/attention/low；progress 为已完成数/总数，不把失败数算成完成检查。
数组 ref 必须经服务端 scope 过滤；report 下载按钮只有 analytics.export 时出现；citation 点开再鉴权。
提醒、预审任务、调用等内部 ID 放对应 payload，不能擅自给 ResourceRef.type 新增枚举。

```json
{
  "id":"card-pa-001","schema_version":1,"type":"preaudit_summary",
  "thread_id":"thr-001","message_id":"msg-003","run_id":"run-001",
  "title":"待审报销检查完成","summary":"5 张中有 2 张低风险，其余 3 张需要查看。",
  "snapshot_at":"2026-11-05T01:10:00Z",
  "resource_refs":[{"type":"expense_claim","id":"clm-001","version":1},{"type":"expense_claim","id":"clm-005","version":1}],
  "payload":{"preaudit_task_id":"pat-001","reviewer_id":"u-zhang","counts":{"risk":1,"incomplete":1,"attention":1,"low":2},"totals":{"all":{"amount_minor":"554000","currency":"CNY"},"low":{"amount_minor":"124000","currency":"CNY"}},"progress":{"completed":5,"total":5}},
  "actions":[{"id":"view","label":"查看清单","kind":"open_drawer","target":"drawer:preaudit:pat-001"}],
  "revision":2,"stale":false
}
```

示例 version=1 只表结构；测试必须从 02 夹具或当前领域响应读取实际版本，不能把示例版本作为执行依据。
card.resource_refs 可是概要明确选中对象的引用，不代表全量清单；清单通过 task_id 与授权 scope 查询，不从此数组推断总数。
actions.target 使用注册的内部路由格式；open_source 只接受 M06/M09 返回的证据引用，不允许模型写任意 URL。
新卡条件：新用户意图形成独立结果、独立业务对象成果、正式动作回执；否则 card.upsert 原 id 并增加 revision。
完成的历史卡快照不随业务变化改写金额；stale 是读取时基于版本/权限计算的投影，最新详情放抽屉。
同一正在处理的结果可增加 revision 更新进度；最终快照锁定后，新证据对应新的结果消息或明确“刷新结果”版本。

```ts
export type DrawerResponse = {
  binding_id: string; drawer_type: string; source_card_id: string | null;
  snapshot_refs: ResourceRef[]; current_refs: ResourceRef[];
  changed: boolean; revalidation_required: boolean;
  capabilities: { can_edit: boolean; can_prepare: boolean; can_download: boolean };
  view: DrawerView; // 按 drawer_type 的受控判别联合
};
export async function openDrawer(ctx: ActorContext, binding: DrawerBinding): Promise<DrawerResponse>;
export async function buildAuthoritativeCard(ctx: ActorContext, result: DomainResult, copy: ValidatedCopy): Promise<AgentCard>;
```

深链接示例：`/assistant/threads/thr-001?drawer=preaudit&resource=pat-001&card=card-pa-001`。
地址恢复先鉴权 thread，再鉴权 drawer 目标；单独业务深链接从领域路由打开，不通过猜测其他人的 thread。

## 7. 数据模型与表约束

所有表含公共 id/tenant_id/version/created_at/updated_at；私有表增加 owner_id；所有跨表 FK 含 tenant_id。

| 表 | 主要字段 | 约束与索引 |
|---|---|---|
| threads | owner_id, title, active_run_id, last_message_seq, deleted_at | (tenant_id,owner_id,updated_at,id)；title ≤80；删除后不可继续 |
| messages | thread_id, seq, role, content, client_message_id, run_id, status | unique(tenant_id,thread_id,seq)；unique(tenant_id,owner_id,client_message_id) |
| cards | thread_id,message_id,run_id,type,schema_version,payload,resource_refs,revision,snapshot_at,finalized_at | 校验完整 AgentCard；表 version 与 revision 同步；message/thread/owner 同源 |
| drawer_bindings | thread_id,card_id,drawer_type,target_id,target_version,filter_json | drawer_type 白名单；filter 只允许领域 schema；不可保存附件签名 URL |
| thread_entry_bindings | owner_id,entry_key,thread_id,last_opened_at | unique(tenant_id,owner_id,entry_key)；指向未删除且本人 thread |
| thread_read_positions | owner_id,thread_id,last_read_seq | unique(tenant_id,owner_id,thread_id)；只能单调前进 |

messages.role 仅 user/assistant/system_notice；系统提示词、隐藏推理不存入可见 messages。
messages.status 为 accepted/pending_consumption/final/failed；这是消息投影状态，不代替公共 run 状态。
流式临时文本按 run_id/message_id 放前端内存；持久最终文本由 assistant.message 写入后端，刷新从 snapshot 恢复。
卡片存储字段只含当前用户可见结果；失权读取通过受控 redaction 投影清除内容，后台清理不延迟权限生效。
保存用户消息、绑定活动 run、创建 enqueue outbox 在一个数据库事务提交；排队失败回滚或形成可诊断任务，不丢消息。
M01 不建立 invoice/claim 副本；历史快照引用版本，只存必要展示字段并执行同等保留与删除规则。

## 8. HTTP、工具与事件接口

以下路径均在 /api/v1 下；所有写请求带 Idempotency-Key 与 CSRF，更新带 expected_version。

| 方法与路径 | 入参要点 | 返回与错误 |
|---|---|---|
| GET /home | 无身份参数 | 能力 entries、授权待办摘要、M02 unread_counts、各区块错误 |
| POST /home/entries/:entry/open | expected_binding_version 或 null, client_message_id | thread_id/run_id/reused；绑定冲突 409；不自动扩大查询范围 |
| GET /threads | cursor,limit | 本人会话摘要；不暴露第一条敏感消息作为默认标题 |
| POST /threads | title 或 null, initial_message 或 null | 201 thread；有消息时一并返回 queued run |
| GET /threads/:id/snapshot | 无 | messages/cards/active_run、through_seq、snapshot_at；一致性恢复点 |
| POST /threads/:id/messages | content,client_message_id,intent,expected_version,resource_refs,attachment_ids | 202 message_id/run_id/disposition，或 409 需明确选择 |
| POST /threads/:id/resume | run_id,expected_version | M14 恢复原任务，返回 202；过期 checkpoint 返回可恢复说明 |
| PATCH /threads/:id | title,expected_version | 更新本人标题，不改业务对象 |
| DELETE /threads/:id | expected_version | 软删除并撤销后续上下文；活动任务按 M14 取消/核实 |
| GET /cards/:id | 无 | 最新授权投影与 stale；无权统一 404 |
| GET /cards/:id/drawer | drawer_type,target_id,cursor,limit | DrawerResponse，重新读取领域数据 |
| GET /runs/:id/events | after 或 Last-Event-ID | M14 SSE；不能以 thread 权限代替 run 权限 |
| POST /confirmations | 领域动作意图、明确 resource versions | M11 生成确认记录和受保护 token；M01 仅消费 |
| POST /confirmations/:id/confirm | 服务端 token、expected_version | M11 action_id/receipt；模型不访问 token |

```json
{"content":"只检查这两张的票据是否齐全","client_message_id":"cm-88","intent":"continue","expected_version":6,"resource_refs":[{"type":"expense_claim","id":"clm-001","version":1},{"type":"expense_claim","id":"clm-005","version":1}],"attachment_ids":[]}
```

服务端 ToolRequest 示例：`{name:"finance.todo.list",version:"1.0.0",arguments:{object_types:["expense_claim"],cursor:null},run_id:"run-001",call_id:"call-001"}`。
arguments 按 M13 注册 schema 冻结；“当前人、当前待办”的语义由服务端限定，授权范围从 ActorContext 推导，不额外传 scope/status 或任意部门串。
工具返回 ToolResult.data 后由 card builder 调领域查询或核对 evidence_refs；模型输出的金额、审批状态不直接采信。

### 8.1 SSE 恢复与前端归并

事件 id 是单 run seq；连接 URL 已定位 run。after 与 Last-Event-ID 同时存在且冲突时返回 400。
服务端先写 run_event 再发送；客户端按 (run_id,seq) 去重，seq 连续后推进已确认游标；乱序暂存最多 100 条。
assistant.delta 追加临时文本；assistant.message 使用 message_id 替换为完整文本，不再次拼接；同一 card 只采纳更大 revision。
网络断开立即显示“连接暂时中断，任务仍在继续”；指数退避 1/2/4/8/16/30 秒并加随机抖动，最多 30 秒间隔。
重新连接先从最后已应用 seq 重放；若收到缺口、游标早于 7 天保留窗或无法合并，读取 thread snapshot 并从其 through_seq 续接。
游标过期使用 M14 的 409 子码：error.code=REVALIDATION_REQUIRED，details.reason="EVENT_CURSOR_EXPIRED"、details.recovery="read_snapshot"，并给出 snapshot 路径及最新 seq；不能清空历史，也不能重发业务命令。
SSE 每次连接与每次发送前检查授权版本；撤权关闭连接并要求刷新权限。浏览器退出/断线不取消 run。
usage.updated 只展示适合用户的配额提示；run.error 的用户文案与诊断 trace_id 分离。

## 9. 异常、恢复与审计

| 场景 | 用户界面 | 恢复约束 |
|---|---|---|
| 单区块待办失败 | 其他能力卡可用，该卡显示重试 | 不把失败当 0，不创建聊天来弥补失败 |
| 旧卡版本变化 | “单据已更新，请重新检查” | 禁用旧 prepare，刷新领域对象，必要时重跑 M04 |
| 外部写入超时 | “结果待核实”并列出受影响对象 | 查询原 action；禁止重复提交或宣称失败撤销 |
| 部分审批成功 | 按项展示成功/拒绝/待核实 | 重试只选择已证实未执行项，并重新确认 |
| 模型文案不合 schema | 展示后端简洁模板或可恢复错误 | 不执行 HTML，不让不完整字段污染卡片表 |
| 运行槽中断 | 展示恢复按钮和已完成步骤 | 调 M14 checkpoint，不重放已成功动作 |
| 会话失权/删除 | 返回列表并清除内容缓存 | 后续工具立即拒绝；审计与业务记录保留 |
| 表单版本冲突 | 展示当前值和用户拟改值 | 用户选择重做差异，不静默覆盖他人修改 |

审计事件：thread.created/deleted、message.accepted、card.generated/refreshed、drawer.opened、context.selected、confirmation.presented、action.result_viewed。
记录 actor、thread/run/trace、resource refs、card revision、before/after version、结果和时间；不把整段聊天复制进审计。
M11 是确认/执行审计的唯一权威；M01 的“已呈现”不能被当作“用户确认”。
指标：首字等待、卡片生成失败率、SSE 重连成功率、重复消息率、过期卡拦截数、抽屉加载 P95；内容采样默认关闭。
开发保留：会话/运行内容 90 天、SSE 7 天；软删除立即停止使用，30 天内清理可删除内容，业务审计不随之删除。

## 12. 明确完成标准

全部编号需求有 UI/API/服务落点；18 项验收在真实数据库与支撑 Demo 上通过，关键场景具备自动化断言。
用户能完成首页→会话概要→清单/证据→确认→逐项回执，刷新可恢复；授权、版本或外部依赖变化时不出现虚假成功。
首期性能目标在记录的基准环境验证：本地 API 首页/抽屉 P95 ≤800 ms（不含外部系统），SSE 重连无数据缺口。
前端没有模型密钥、dsh 直连、任意 HTML 执行或业务 localStorage 数据库；所有财务数值均可追溯到后端领域数据。
未达到的能力必须显示为不可用并记录原因；不能用固定聊天、静态数组或按钮弹窗代替实现完成。
