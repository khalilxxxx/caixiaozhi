# M07 数据分析 图表与报告

版本：1.0｜性质：产品级模块详设，供 Codex 实施；本轮只交付设计，不生成应用实现。
依据：[总体架构与公共契约](./01_总体架构与公共契约.md)、[联调验收与演示数据](./02_联调验收与演示数据.md)。

## 1 定位 依赖与边界

本模块把已授权业务事实转换为确定指标、图表、下钻明细和可编辑报告，支持自然语言查询及预置视图。
M09 提供真实持久报销与费用行；M11 提供审批任务/完成事实；M12 决定本人和部门范围及导出权。
M04 提供有审核人归属和有效期的预审结果，用于低风险候选分析；不得用模型自行估计风险数量。
M01 展示 analysis_result/report_result 卡片和 analytics 抽屉；M13 注册查询与报告工具；M14 执行可靠任务。
首期支持 CNY、已知维度、固定模板指标、CSV/HTML 下载；业务源可为 Demo adapter，计算与文件必须真实。
不做支付或会计总账推断、多币种换汇、任意 SQL、预测预算、模型直接修改金额，以及自动对外发送报告。
PPT/PDF 是后续可选格式；首期没有这些 renderer 时，按钮和能力目录不得声称支持。
Agent 负责理解问题和解释结果；权限、查询计划、金额计算、快照与下载授权均由财小智服务器执行。

## 4 指标和维度目录

### 4.1 首期指标

| metric ID | 统计粒度/算法 | 日期字段与状态 |
|---|---|---|
| expense.completed_amount | 去重报销单 total_amount 求和 | completed_at；仅 completed |
| expense.completed_count | 去重 claim_id 计数 | 同上 |
| expense.submitted_amount | 每张单在查询时最新一次有效提交的 total_amount 求和 | submitted_at；pending_manager/pending_finance/completed/returned |
| expense.pending_manager_amount | 当前授权主管任务对应单据求和 | snapshot_at 当前存量；pending_manager |
| expense.pending_manager_count | 同上单据去重计数 | 同上 |
| expense.low_candidate_amount | 当前审核人符合 M04 全部候选条件的单据求和 | snapshot_at；fresh 且当前 pending_manager |
| expense.low_candidate_count | 同上去重计数 | 同上 |
| expense.entertainment_completed_amount | 已完成报销中 meals 且关联有效招待申请的费用行求和 | 母单 completed_at；不加 OA 预算 |
| expense.category_completed_amount | 已完成报销费用行按原业务 expense_type 求和 | 母单 completed_at |

completed 是审批完成，不能文案化为“已支付”“到账”“实际付款”。
submitted_amount 排除 draft/withdrawn；returned 已发生提交所以计入，并在口径说明中标注。
重新提交覆盖该单最新 submitted_at，查询名为“最新有效提交额”；如果用户要全部提交事件次数，首期要求改用可支持口径。
submitted_amount 使用快照时单据当前有效金额；若要首次提交金额或每次历史提交金额，需另建事件指标，不能冒充现有口径。
pending/low 为时点存量指标，不支持按 completed_at 过滤；planner 拒绝不兼容的日期组合。
未预审、预审 stale 或覆盖不完整的单据不计入 low；结果同时返回 checked_count 和 unchecked_count。
统计分类用业务 expense_type=meals/transport/lodging/office/other；M03 的 general 归一化不应抹掉 office 分类。
meals 不是天然等于招待；只有有效 OA 关联且业务类型为招待的行进入招待排行，未知关联单列数据质量说明。

### 4.2 维度 白名单及展示

允许维度 applicant、department、expense_type、completed_day、completed_month、submitted_day、submitted_month。
每个指标登记 allowed_dimensions、date_basis、allowed_filters、grain、unit、quality_rules、catalog_version。
最多两个维度，单次最多500个分组；排行默认前10，剩余合成“其他”，不丢失总额。
费用行聚合先固定 claim 粒度与 line 粒度；不能把 total_amount 与每行 JOIN 后重复相加。
金额指标输出 Money；数量输出非负整数计数；比例与倍率用十进制 string，单位字段不可省略。
图形类型限 bar/line/donut/table；饼图出现未知或负数时改用表格，不能画出错误占比。
只将明确允许的 metric、dimensions、filters 注册给 Agent，界面和工具同用目录。

## 5 时间 金额和演示基线

时间按 Asia/Shanghai 解释业务日，转换为 UTC 的半开区间 [from,to_exclusive)，保存两种边界和 timezone。
“今天”取 M15 Demo business clock 的2026-11-05；系统审计时间仍使用真实 RFC3339 UTC。
2026-11-05 的本地日边界对应 UTC 2026-11-04T16:00:00Z 至 2026-11-05T16:00:00Z，不按 UTC 零点切日。
当前月默认从11月1日到业务时钟所在日结束，说明“11月截至5日”；未来日期数据不提前计入当前月报。
对比默认上一完整月，标题明确“11月截至5日 vs 10月全月”；可选同期时必须重新生成10月1–5日区间。
完整对比周期、当前不完整周期以及查询截至时刻均写入快照/报告；不暗示两个窗口等长。
金额从十进制 cents string 转 bigint/数据库 numeric(30,0)，服务端确定求和后再转 string。
展示元使用精确分转两位小数；万元仅改变展示格式，不改变底层 cents，下载保留原始分值。
增长率=(本期−基期)/基期；采用有符号整数有理数计算，四舍五入到百分数2位，不经 Number 计算。
基期为0返回 rate=null 和 reason=zero_baseline；本期基期同为0可另写“无变化”，不伪造0%或无穷大。

| 基线问题 | 正确结果 | 排除/解释 |
|---|---|---|
| 张伟，销售部11月完成金额 | 590000分；李娜350000、王强240000 | 不含技术500000 |

| 销售部11月分类 | meals230000、transport160000、lodging150000、office50000 | 合计590000 |
| 销售部11月招待餐饮排行 | 王强180000、李娜50000 | 不含待审clm-002的120000 |

## 6 用户旅程 界面与状态

### 6.1 问一句 看卡片 下钻

1. 张伟说“本月部门报销比上月怎么样”，planner 提出 completed_amount、部门范围、当前月与上月完整月。
2. 若“报销”未指提交/完成，采用目录默认并在卡片显著说明；“今天报销”询问提交还是审批完成。
3. 查询任务持久入队，显示排队/读取/汇总阶段；成功返回5900元和有明确周期的比较结果。
4. 卡片展示金额、增量、增幅、周期、范围、更新时间和“查看明细/生成报告”操作。
5. 打开抽屉显示图表、数据表、口径说明与明细页；点击餐饮柱只能看到同一 snapshot 的2300元构成。
6. 继续问“谁的招待费最多”，复用已明确范围/期间；创建受控派生查询，禁止复用旧数字假装新查询。
7. 创建月报时以所选分析快照的冻结事实生成全部组件；生成报告不自动发送给任何人。

### 6.2 月报编辑与下载

报告预览展示可编辑标题、摘要说明、风险观察和行动建议；金额、图表标签、周期和来源使用 fact_ref 锁定块。
用户改“本月费用增加”叙述可保存新草稿版本；试图把5900元改为6000元时指出该数字来自快照并提供重新查询入口。
模型推断单独置于“分析判断”，带 evidence_refs；不能把相关性描述成确定原因。
例如“餐饮占比较高”可由230000/590000验证；“因为客户活动增多”无活动数据时不得当事实。
下载按钮先选 CSV 明细或 HTML 报告，再执行权限检查和 artifact 生成；完成后显示真实文件名、大小和下载入口。
HTML 首期含静态图表与可访问数据表，不依赖外网脚本；CSV 可复核每行金额及汇总。

### 6.3 页面状态

| 状态 | 用户看到什么 | 可执行操作 |
|---|---|---|
| awaiting_parameters | 缺日期、范围或口径的具体问题 | 选择答案或补充文字 |
| queued/running | 真正后台阶段与已处理页数 | 取消尚未完成的查询 |
| ready | 图表、总额、口径、snapshot_at | 下钻、生成报告、导出 |
| empty | 该授权范围/口径内无匹配业务记录 | 调整过滤，不伪造走势 |
| degraded | 可解释的数据质量限制和已验证范围 | 查看问题；不能生成无说明的正式报告 |
| failed | 公共错误与可重试提示 | 重试生成新查询任务 |
| stale | 数据或目录已更新，当前仍为历史快照 | 保留历史/重新计算 |

这是分析视图状态；领域 job 使用 M14 可靠任务设施，不能为分析/导出自动创建 Agent run；已有 run 使用公共枚举。
抽屉遵守公共560–720宽度和窄屏全屏规范；数据表可以键盘操作，图表颜色配合文字和数值。

## 7 领域模型与快照

| 实体 | 核心字段 | 不变量 |
|---|---|---|
| metric_definition | metric_id、catalog_version、grain、unit、date_basis、allowed_dimensions/filters、template_id | 服务端注册，模型不可新增 |
| analysis_request | owner_id、query_plan、plan_hash、authz_version、job_id、origin_run_id、request_text | 同幂等键复用同一任务 |
| analysis_snapshot | request_id、scope_hash、snapshot_at、business_date、source_watermark、catalog_version、quality | 完成后事实不可原地改写 |
| analysis_fact | snapshot_id、fact_kind、claim_ref、line_id、applicant_id、department_id、expense_type、amount_minor、date_facts | 只保存授权最小必要字段 |
| analysis_aggregate | snapshot_id、metric_id、dimension_key、amount_minor/count、evidence_fact_ids | 必须由 snapshot facts 确定汇总 |
| analysis_chart | snapshot_id、spec_version、type、series、axis、unit、fact_refs | 不接受任意 HTML/JS 或外部图URL |
| report | owner_id、analysis_snapshot_id、template_id、template_version、state、current_draft_version | state=draft/ready/archived，不是审批状态 |
| report_version | report_id、content_blocks、locked_fact_hash、created_by、version_no | 保留手工编辑与模型来源 |
| report_artifact | report_ref、snapshot_id、format、file_id、sha256、size_bytes、expires_at、export_scope_hash | 私有字节对象，下载重鉴权 |
| analysis_invalidation | snapshot_id、reason、new_watermark、occurred_at | 追加变化原因，不能修改旧事实 |

公共实体字段、租户外键与版本约束同总体契约；analysis/report 使用公共 ResourceRef，artifact 自有 file_id。
分析使用 PostgreSQL REPEATABLE READ 读取业务事实和 outbox 水位，保证一份快照没有跨时刻拼接。
来源如果替换为远端 adapter，必须提供一致 snapshot token 或可验证全量分页水位；否则拒绝一致快照承诺并标 degraded。
对分析事实保存 claim_ref.version、line 对应版本和最小明细投影；后续下钻使用保存事实，不重新查活表替换数值。
fact_kind=claim/line；claim 行存整单总额，line 行存费用金额，唯一键为 snapshot+fact_kind+源id；同一指标只选择其注册 grain，禁止把两种行相加。
月报快照在同一读取事务中保留授权 claim 与其全部最小 line facts；category/招待排行选 line，completed_amount/count 选 claim，二者各自对账。
详情“打开当前单据”另走 M09 并标当前版本；与历史分析的金额变化必须并列说明。
保留分析默认90天、临时导出24小时的可配置初值；需公司档案要求确定后才能作为生产保留策略。
相同参数在不同 source_watermark 的查询生成新 snapshot；缓存键同时包含 tenant/actor/authz/scope/catalog/watermark。

## 8 白名单 planner 与确定性执行

QueryPlan 的字段固定 metric、period、dimensions、filters；拒绝 additionalProperties 和任何 sql/expression/table/join 字段。
period={from,to_exclusive,timezone,date_basis,compare_to?}；compare_to 仅允许相同日期口径的 from/to_exclusive。
filters={scope:self|department|authorized_departments,department_ids?,applicant_ids?,expense_types?,top_n?}；无自由比较表达式。
当前存量指标 period 使用 {as_of:"current",timezone:"Asia/Shanghai",date_basis:"snapshot_at"}，不能伪造历史待办快照。
默认时间跨度≤24个月、返回分组≤500、下钻单页≤100；超限要求缩小范围或异步导出，不能静默截断总额。
第一步：将自然语言解析为 QueryPlanProposal，未决字段列 clarification_questions；模型只负责提议。
第二步：校验目录兼容性、时区、日期区间、数量范围以及每个 filter 的权限，不合法计划不进入数据库。
第三步：服务端将 scope 与已授权范围取交集；用户显式请求无权部门时返回403/404，不把请求悄悄改成另一部门。
第四步：固定 SQL 模板按 metric.template_id 选择；值用参数绑定，维度映射为预先定义列名，禁止模型字符串拼接 SQL。
第五步：同一事务读取去重事实并计算聚合；数值质量校验包括币种、金额格式、行合计与单据总额。
第六步：完成 snapshot 后生成 ChartSpec、比较结果和文字模板；模型解释消费只读 metrics，不重新计算数字。
第七步：下钻条件由 dimension_key 与 snapshot_id 解析，只从冻结事实分页，用户不能通过额外过滤扩权。
第八步：生成报告前校验 snapshot 仍可访问及所需事实已冻结，报告所有表图引用同一 snapshot_id。
单据总额与行合计不一致时整份相关金额分析标 degraded；不得用某一侧悄悄覆盖另一侧或丢掉异常单据。
必需事实读取失败导致查询 failed，不返回部分部门总额冒充全范围；已可区分的非数值解释失败只降级说明。
图表几何可使用缩放后的 Number，tooltip、表格、导出仍从原始 cents string 格式化，永不反向回写浮点值。

## 9 API 工具与 JSON 示例

所有路径加 /api/v1；写任务和编辑带 Idempotency-Key；更新已有报告带 expected_version。

| 方法与路径 | 输入 | 输出与约束 |
|---|---|---|
| GET /analytics/catalog | 无 | 当前用户可用指标、维度、模板与catalog_version |
| POST /analytics/queries | metric、period、dimensions、filters | 202 request_id/job_id/origin_run_id；严格 QueryPlan |
| GET /analytics/queries/{id} | 无 | 进度、snapshot_id 或错误 |
| GET /analytics/snapshots/{id} | 无 | 确定指标、图表、质量、freshness |
| GET /analytics/snapshots/{id}/rows | dimension_key?、cursor、limit | 仅快照内下钻；金额可复核 |
| POST /analytics/snapshots/{id}/refresh | expected_version | 新查询/新快照，旧快照不变 |

## 10 报告编辑 导出与 stale

报告块类型为 heading、editable_narrative、locked_metric、locked_table、locked_chart、evidence_note、user_note；只允许有限 Markdown。
服务器根据 template_version 与 locked_fact_hash 重建事实块，忽略客户端对 locked_metric 内容的伪造并返回校验错误。
editable_narrative 可以改措辞/建议；涉及现有金额或百分比时使用 fact_ref 插值，不让用户手填一个冒充统计值的数字。
用户补充未验证信息须放独立 user_note 并标“用户补充，未经业务数据验证”，不混入统计结论与图表。
报告HTML所有文本转义，不执行脚本，不加载远程图片；CSP 禁止脚本/远程请求，图表使用服务端受控SVG或表格。
CSV 使用 UTF-8 BOM 与 RFC4180 转义；金额列包含 amount_minor、currency 和精确显示值，保存清晰口径字段。
姓名、说明等文本列以 =/+/-/@/TAB/CR 起始时做公式注入转义；金额数值列按已校验金额编码，不能直接把说明当公式。
导出下载统一采用服务端鉴权代理，不下发可绕过撤权检查的对象读取链接；站内撤权后新下载立即拒绝，已下载的本地副本无法远程撤回。
artifact 保存 file_id、hash、size、生成时间、report_version、snapshot_id 和导出者；文件名不包含身份证/发票号码。
导出任务幂等唯一键包括 actor/report_version/snapshot/format/renderer_version；重复点击返回同一已生成 artifact。
源数据 outbox 水位或指标目录变动使 snapshot 标 stale；细粒度能证明无关变化时可保持 fresh，不能默认忽略变化。
历史快照仍可在当前授权下查看，标题注明“截至某时”；请求“最新”时必须重算，不能仅去掉 stale 标签。
stale 导出要求明确 freshness_choice=as_recorded 或 refresh；as_recorded 文件写明历史快照和数据已更新提示。
权限撤销不属于可保留的 stale：直接拒绝访问正文/下钻/下载，提示重新查询当前范围，不能只标一个警告继续泄露。
刷新生成新 snapshot，可选择新报告草稿；保留旧手工说明为待复核内容，不能自动套到新数字后假装仍然准确。

## 11 可靠任务和失败恢复

分析/报告/导出都由 M14 持久任务运行；queued/running 阶段刷新可恢复，取消只阻止未开始的后续工作。
快照构建在单事务提交，失败不暴露半成品；任务重复执行按 request_id 查已提交 snapshot 再决定续跑。
导出先写临时私有对象并核验字节 hash，事务登记 artifact 后才可下载；失败临时对象定时清理。
模型解释或摘要失败时保留确定图表与表格，可通过模板生成报告；不能因为模型超时丢掉已完成统计。
源适配器瞬时失败可按 M14 退避重试2次；没有一致水位时停止并说明，不能不断重试拼出一个混合时刻快照。
报告渲染失败可重试同一 report_version，已成功 artifact 不重复生成；有并发编辑时新导出必须选择明确版本。
观测项包括 query/aggregate/render 耗时、事实数、quality 异常、权限拒绝、stale 发生率和下载审计；日志不记录完整业务明细。

## 14 完成门槛
