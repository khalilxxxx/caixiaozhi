# 财小智 v1 联调验收与演示数据

版本：1.0｜用途：统一所有模块夹具、跨系统联调与发布证据。默认演示业务时刻 2026-11-05 11:00:00，时区 Asia/Shanghai（UTC 03:00:00），在当天已完成夹具的 10:00 之后；全部人物、制度、票据与金额均为合成样本。

## 1. 验收原则

产品模块必须有真实领域逻辑、持久化、权限和状态；支撑 Demo 可用模拟 OCR、身份提供方、MaaS 和消息渠道，但仍通过真实 API、数据库和状态转换。要验证“同一个对象从头走到尾”，不是分别播放互不相关的静态卡片。

每次场景测试记录 seed_version、demo_environment_id、数据 generation、使用身份、模型/profile/工具/规则版本、结果与 trace_id。真实模型测试不要求逐字相同的回答，要求工具调用范围、金额、状态、证据和确认边界正确。

## 2. 种子数据规范

seed_version=`finance-agent-v1.0`。下表 ID 为默认 t-demo 的规范 ID。自动化测试若多租户并行，使用独立数据库或生成带环境前缀的 ID，并保存 alias→真实 ID 映射；不能让两个租户共享同一业务对象。不要在产品运行代码里用这些 ID 判断风险，判断必须来自字段与规则。

基准所有单据 version=1；每次变更严格 +1；附件有独立版本/校验 hash。创建 seed 不调用真实外部系统。角色切换改变登录用户，不改单据归属。

## 3. 八条必须跑通的完整旅程

### E2E-01 制度问答与来源

身份李娜：首页输入“下周去杭州，住宿标准是多少？”→ Agent 结合授权组织和明确日期查询政策 → 展示 800 元/间夜的演示制度答案及来源 → 点击引用，右抽屉定位制度版本和段落 → 追问超过标准怎么办，只根据实际制度片段答复。

断言：无弹出传统知识库主页面；答案重要结论有可访问引用；没有制度支持的例外不能编造；切换孙静身份不能读未授权知识。

### E2E-02 差旅草稿与手工修改不丢失

李娜打开 trv-001 → 在抽屉手改出发日期并保存为 v2 → 输入“返程改到 13 号，其他不变”→ Agent 获取 v2、生成仅涉及返程的差异 → 用户采纳为 v3 → 提交摘要显示最新行程/预算 → 确认提交产生真实 Demo 回执 → 张伟在审批台看到同 ID → 批准后李娜查进度变 approved。

断言：v1 聊天不覆盖 v2 手改；两窗口竞争采纳产生 VERSION_CONFLICT；未知城市候选必须确认；无未核实自动提交。

### E2E-03 发票到报销

李娜上传两份合成票据 → 等待 OCR fixture 任务 → 核对字段并为含糊票据选择类型 → 每票生成一个费用项 → 关联已批准 oa-001（适用餐饮）→ 生成报销草稿 → 预审、补齐缺字段 → 查看差异和提交摘要 → 确认后进入 pending_manager。

断言：刷新仍有上传状态；同文件重复上传可识别；不把一张票重复计费；OA 状态/日期/金额不匹配时阻断或明确无法判断；SRS 只接结构化 JSON。

### E2E-04 自然语言个人规则

张伟选择规则创建场景 → 输入“部门内每张报销单餐饮费超过 1000 元提醒我”→ 展示部门、每单餐饮合计、gt 1000 的结构化解释 → 测试 999、1000、1001、缺字段四种样例 → 查看版本并确认启用 → 对相同待办重新预审，clm-002 进入 attention。

断言：1000 不触发、1001 触发；个人规则不覆盖住宿公司标准；启用改变规则集修订号，旧预审结果 stale；李娜自己的预检不自动使用张伟规则。

### E2E-05 待办预审与低风险审批

张伟首页待办卡显示 5 → 点击发起本次预审 → 对话出现 5 张/5,540 元概要 → 抽屉显示 4 个分组和每项证据 → 打开 clm-003 显示住宿超标准证据，可跳到同 ID 的报销系统 → 返回选择 low 的 clm-001、clm-005 → 一次确认两对象、金额 1,240 元与版本 → 收到逐项回执。

断言：两单进入 pending_finance；张伟剩 3，刘敏新增 2 财务待办；completed 报表仍为 5,900 元；clm-002/003/004 不会被自动加入批次。刘敏后续批准两单，才新增 1,240 元审批完成金额，报表刷新后为 7,140 元。

### E2E-06 选择 Skill 分析、下钻和报告

张伟在输入框选择“费用分析” → 输入“看本月部门餐饮排行”→ 确认默认 completed/本月截至今日口径 → 卡片显示王强 1,800、李娜 500 → 抽屉展开图表与明细 → 追问“做一份费用月报”→ 保存报告草稿 → 点击引用回到同 snapshot → 具备导出权限时导出。

断言：报告/图表/明细总数一致；待审餐饮不混入；技术部和其他财务私人 Skill 不可见；只查看权限不能导出；报告没有自动发给任何人。

### E2E-07 个人记忆和隔离

张伟明确“以后报告先给摘要，金额用元”→ 显示个人偏好保存回执 → 新会话创建报告遵循偏好 → 切李娜，新会话不继承 → 张伟打开记忆管理改为金额用万元或删除 → 后续运行按新值或默认，历史报告不被篡改。

断言：自然语言审核阈值路由 M03，不悄悄保存为不可审计的 memory；删除偏好后上下文缓存失效；管理员没有默认读取个人记忆入口。

### E2E-08 日报订阅与收件箱

张伟设置工作日 09:00 的只读待办摘要 → M15 仅推进演示业务时钟并触发调度 → 生成一条未读摘要 → 首页只变未读标记/待办数字 → 点击消息进入对话，显示该时点快照 → 打开抽屉读最新待办并继续预审/审批。

断言：同日同订阅同计划时点只投递一次；重启调度不重复；失权不查越权数据；摘要不自动审批；旧摘要与最新单据不一致时提示更新时间。

## 5. 自动化验证分层

### 5.1 不依赖模型的确定性测试

规则 AST/三值逻辑、金额精度、字段映射、权限、状态机、幂等、CAS、预审 stale、指标汇总与下钻、调度去重、SSE 事件去重必须用固定输入获得固定断言。测试替身只替换模型/OCR/网络，不能把整个审批或规则结果替掉。

建议仓库脚本：`pnpm test:unit`、`pnpm test:contracts`、`pnpm test:integration`。由实施阶段创建这些命令；本设计包没有声称已经存在或通过。

### 5.2 真实 dsh 与模型集成

`pnpm test:agent:real` 读取测试环境模型配置，运行少量成本受控样例：只读待办、语义规则、手改后填单、审批确认暂停、接续分析、工具拒绝。记录所调用工具和核心字段；不要断言回答逐字一致。

每个必经工具路径必须至少一例真实通过。若真实模型不能稳定遵守参数 schema，用结构化修复/澄清/受控任务流程处理，不改成前端关键词硬编码。

### 5.3 浏览器与容量

`pnpm test:e2e` 跑八条旅程及关键失败分支；`pnpm test:load` 在预生产环境测 20 活跃 run 与 100 SSE 的初始负载目标。对真实模型限流和系统排队分别计量，不将某次测试成功等同“全公司无限并发”。

## 6. 初始非功能验收目标

以下为待验证目标，非当前测量结果：

| 方面 | 目标与测量条件 |
|---|---|
| 状态可靠性 | 已接收 run、确认、动作账本和业务提交在应用/Worker 重启后可追溯；不得重复写业务 |
| 一般 API | 在目标负载下，排除模型/外部依赖的普通读取 p95 < 800ms；写请求入队 p95 < 1s |
| 用户反馈 | 接收任务后 1s 内有排队/处理状态；模型首字单独记录，不伪造业务进度 |
| 事件恢复 | SSE 断开后可重放已保留事件，游标过期转最新快照；无永久丢失终结状态 |
| 任务恢复 | Worker 丢失在租约过期后被识别，unknown 写入不自动重发；人工可查询和处理 |
| 数据准确 | 全部基准金额、分组、统计与单据状态精确一致；模型文案不覆盖事实 |
| 权限 | 角色/组织/附件/记忆/Skill/导出/日志的负面用例全部通过 |
| 可访问性 | 键盘可操作抽屉和确认；焦点返回触发按钮；状态不只靠颜色；窄屏可完整处理 |
