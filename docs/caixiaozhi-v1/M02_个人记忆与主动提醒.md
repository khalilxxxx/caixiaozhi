# M02 个人记忆与主动提醒

版本：1.0｜设计日期：2026-11-05｜实现深度：产品级｜依赖：01 总体架构与公共契约。
本模块实现应用内的个人记忆、订阅日程和主动消息；不调用当前 ChatGPT 会话的 Automations 或其他个人账户工具。

## 1. 上下文、依赖与职责边界

个人记忆服务让用户明确管理跨会话偏好；订阅服务按已授权、只读的计划生成摘要并可靠送达个人收件箱。
两者都以 tenant_id + owner_id 隔离，不能把全公司对话汇总成公共记忆，也不能把日程视为永久业务授权。

| 依赖 | 交互 | 权威边界 |
|---|---|---|
| M01 | 保存记忆入口、未读数、打开摘要会话 | 首次首页和后台投递均不自动创建聊天 |
| M03 | 将审核阈值转成正式个人规则 | 个人规则版本、试跑和启用由 M03 管理 |
| M04/M07 | 预审摘要、待办摘要、分析口径 | 每次运行读取当前结果，记忆不是业务事实缓存 |
| M05 | 可选的只读摘要 Skill 版本 | 固定版本及其使用授权，工具仍逐次鉴权 |
| M12 | 用户时区、实时权限版本与撤权事件 | 后台使用服务端委托上下文，不保存用户密码/SSO token |
| M13 | 只读工具白名单和证据引用 | 不将订阅 prompt 解释为任意工具或 URL |
| M14 | scheduler、durable_jobs、leases、outbox、background run | M02 定义产品日程和发生实例，不另造内存计时器 |
| M15 | 演示时钟和显式触发 | “立即模拟早报”只能进入 /demo 的受控触发路径 |

不做本期能力：邮件/微信外发、自动批准报销、日程触发的自动规则启用、法定节假日推断、任意 cron 和用户上传脚本。

## 2. 编号核心需求

- M02-R01：只有“记住……”等明确指令或记忆编辑界面的保存才允许持久化；普通聊天不自动提取并保存。
- M02-R02：保存后返回记忆内容、用途、来源、有效期和撤销入口；用户可独立查看、修改、删除。
- M02-R03：默认有效期到用户删除；用户明确给时间范围时保存 expires_at，并按所选时区展示截止时间。
- M02-R04：记忆只改变个人表达/输入偏好或个人工作背景，不扩大权限，不覆盖单据、政策、规则和组织主数据。
- M02-R05：个人审核金额阈值、类别提醒条件必须落地 M03 个人规则；不得用记忆偷偷改变风险分组。
- M02-R06：删除、过期、来源失效和撤权后，跨会话上下文立即排除相关记忆；缓存与在途生成均处理版本失效。
- M02-R07：订阅启用时展示明确任务、频率、时区、读取范围、结果去向和下一次时间；授权只读。
- M02-R08：日程可编辑、暂停、恢复、删除、查看最近执行；修改时使用 expected_version 并重新计算下一次发生时间。
- M02-R09：调度由 M14 的持久作业和 outbox 负责，进程退出、重复领取和消息重复发送不能丢失或重复投递。
- M02-R10：工作日固定周一到周五，不自动扣除节假日；界面说明这一口径。
- M02-R11：主动摘要只进入 M02 收件箱和首页未读数；不打开窗口、不创建聊天卡、不改变正在输入的内容。
- M02-R12：用户点击条目才创建或打开对应会话；同一条目重复打开复用绑定，不重复复制摘要。
- M02-R13：权限变化时重新计算可读范围；不能把原部门摘要直接重用到新部门，不能自动扩大范围。
- M02-R14：摘要失败、部分数据缺失和恢复操作可见；无最新数据不能伪装成“今日无待办”。
- M02-R15：每次发生的生成、投递、已读与重试有独立可追踪标识；内容保留与审计保留分离。

## 3. 记忆分类、保存语义与权限

| 分类 | 可保存的实例 | 使用限制 |
|---|---|---|
| response_preference | “请用简短中文，先列待办” | 影响表达，不缩减必需证据与确认信息 |
| input_preference | “差旅默认从杭州出发，先帮我填上” | 只形成草稿建议；每次提交以单据实际字段为准 |
| personal_context | “本月我协助处理销售部预算材料” | 不能因此取得销售数据权限；可设置本月底失效 |

“我这个月的餐饮超过 1,000 元请提醒”若指审核规则，进入 M03；若指本人费用分析订阅，创建只读分析日程。
语义不清时只展示两个明确选择，不先保存任意一种；已确认的个人规则不能同时复制成具有执行效力的 memory。
禁止保存：口令、访问令牌、完整银行卡号、未授权同事资料；提示改用安全账户配置或业务系统字段。
对话中出现姓名、部门或金额不构成保存授权。自动候选可暂存于当前页面内存，离开后丢弃；不进入向量库。
同一偏好键冲突时显示原值与拟改值；用户“以后改为……”是明确更新授权，返回新版本与撤销入口。
用户说“记住这周先看差旅”但未给精确日期时，按当前用户时区推导并在回执显示截止日期；有歧义先询问。
个人记忆只能由本人读写；平台管理员仅可查看条目数量、失效次数等元数据，无正文权限。
财务或主管角色不获得他人的记忆权；共享 Skill 只能收到本次调用允许的偏好子集，不读取整个记忆档案。

## 4. 记忆用户旅程与界面状态

### 4.1 明确保存

1. 用户在对话说“记住，我更喜欢先看结论，再看依据”。
2. 服务端识别明确保存意图并生成结构化候选；若内容单一明确，执行个人保存并给出回执，不弹业务审批式确认。
3. 回执显示“已记住：先看结论，再看依据｜仅你可见｜持续有效”，附“管理”“撤销”。
4. 复杂或多项候选先用轻量编辑面板让用户选项保存；候选未保存期间不影响其他会话。
5. 新会话构造上下文时按当前权限与有效期读取偏好，并在“本次使用的记忆”中可查看来源。

### 4.2 维护与删除

设置页“我的记忆”最大内容宽 960 px，按“表达偏好 / 输入偏好 / 工作背景”分组，提供关键词搜索和状态筛选。
每行展示内容、用途、来源、更新时间、截止时间、更多菜单；默认每页 20 条，不展示聊天全文。
编辑面板 560 px；字段为内容、用途、有效期、来源说明；保存中禁用重复按钮，失败保留用户输入。
删除只作用于记忆本体，按钮明确“删除记忆”；成功后立即从可用列表和所有运行上下文移除。
撤销采用新的写操作恢复为新版本，需重新验证来源/权限；若来源已无权或条目过期，提示重新编辑，不能盲目恢复。
空态“还没有保存的记忆”；过期项默认折叠，可筛选查看；来源已删除显示“来源不可用，暂不使用”。
用户删除原来源会话时，与该来源绑定的记忆停止自动使用，标记 source_unavailable；本人可重新明确保存为手工来源。
记忆删除不宣称删除用户原始聊天记录或已完成业务记录；原会话仍有独立删除入口。

### 4.3 阈值分流

用户说“记住，餐饮费超过 1,000 元让我多留意”。
界面解释“这是个人审核提醒，将保存为个人规则”，展示 meals 条件、阈值 Money 和影响为 attention。
进入 M03 的建议→试跑→启用确认；未启用不影响预审，启用后由 M04 绑定其正式版本。
用户放弃时不偷偷保存同内容的 memory；后续可查看 M03 的个人规则管理入口。

## 5. 订阅、时区与可靠调度

### 5.1 首期订阅类型

| type | 内容 | 允许的数据范围 | 运行权限 |
|---|---|---|---|
| todo_digest | 当前待我审批数量、分组与关键到期信息 | 当前人有审批读取权的对象 | 只读待办与已有预审结果 |
| expense_digest | 选定期间的报销审批完成金额与变化 | 本人或显式授权部门 | M07 受控指标查询 |
| document_progress | 本人指定申请的审批进度 | 明确列出的有权资源 | 单据只读查询 |

预审生成不是默认早报行为；需要实时预审时用户单独授权只读检查能力，并用 M04 可靠任务执行，仍不得审批。
早报可使用模板生成确定性概要；模型只做可追溯的语言整理，生成失败时保留结构化结果并用模板降级。
订阅可以引用已激活的只读 Skill 版本；解析后的完整工具集合必须为 M13 effect=read，含 finance.action.prepare、字段建议或规则改写能力时禁止绑定，不能靠 prompt 声称只读。

后台 run 不进入 waiting_user 或 waiting_confirmation；配置/输入不足时 run=failed，日程按可修复原因置 blocked，收件箱显示“请调整摘要配置”，不能等待聊天确认或发起业务动作。

### 5.2 时间模型

用户创建“每个工作日上午 9:00 提醒我看待审报销”；默认时区 Asia/Shanghai，界面必须显式展示，可更改为有效 IANA 名称。
02 基准夹具中个人记忆为空，全部日报关闭；仅张伟明确启用后创建周一至周五 09:00 Asia/Shanghai 的订阅。M15 显式触发使用同一 occurrence、job 和投递链路。
frequency 首期 daily 或 weekdays；local_time 是 HH:mm；timezone 是 IANA；start_date 是该时区业务日期。
业务时间按用户设置转换成 UTC scheduled_at；服务端和数据库时间仍为 RFC3339 UTC；不得使用部署机器本地时区。
weekdays 仅本地周一到周五；不识别调休和节假日，摘要界面写“工作日按周一至周五”。
DST 重复时间选择第一次出现的 UTC 时刻，单日只生成一次；不存在的时间顺延到当天第一个有效时刻，记录 dst_adjusted。
编辑时区/时间先展示下一次三个发生时刻（本地时间+UTC偏移），保存后以新 schedule_version 生效，不迁移已投递历史。
立即启用不自动补跑此前未授权时段；start_date 可今天，若今天时间已过则从下一个匹配日期开始。
服务器真实时间不受演示基准日影响；M15 控制的测试时钟只能用于隔离 demo environment 的调度实例。

### 5.3 发生实例、补跑与去重

每次计划发生先建立 occurrence；唯一键为 tenant_id + subscription_id + schedule_version + local_occurrence_date + local_time。
occurrence 记录不可变 scheduled_at、owner、授权范围快照标识、查询参数版本和只读能力集合。
scheduler 每 30 秒扫描 next_run_at，使用数据库行锁 SKIP LOCKED；同事务创建 occurrence、durable_job、推进 next_run_at。
多个 scheduler 可并发；重复扫描依赖唯一约束去重；不用 setTimeout 当作可靠日程，不把 Redis 当唯一队列。
故障恢复补跑：计划时刻距当前 ≤6 小时的最近一个未运行实例允许补跑；同订阅最多补一份，其他记为 skipped_coalesced。
超过 6 小时的实例记为 skipped_late，在执行记录可见；不发送过时的“今天早报”，下一次按原日程运行。
生成执行失败最多 5 次（首次+4次重试），退避 1/5/15/60 分钟，加入抖动；不跨越 scheduled_at+6 小时生成窗。
Worker lease 初值 30 秒，每 10 秒续租；过期可重新领取，fencing token 拒绝旧 Worker 写回；具体实现复用 M14。
生成成功后同事务保存摘要快照并写 M14 outbox；outbox 单独重试，投递延迟不重新执行模型或数据查询。
投递唯一键为 occurrence_id + channel(in_app)；inbox 对该键 unique，重复投递读取原 item，不创建第二条未读。
outbox 投递恢复可在生成后 24 小时内继续；更迟标记 delivery_expired，保留执行记录并提示查看，不伪装成实时消息。
生成窗耗尽后投递一条“摘要生成失败，可重试”的同 occurrence 条目；恢复成功更新该条目，不另发第二条。

### 5.4 暂停、修改、删除和权限变化

暂停使 subscription=paused 并增加 version；下一次扫描不创建实例，未领取 job 取消，已领取 job 在查询/发布前检查状态。
当前只读查询允许完成资源释放，但暂停后不再投递；已送达的历史摘要保留，可由用户单独删除。
恢复从下一次计划时刻开始；不自动补跑暂停期间，用户需要当前结果时可在产品中执行明确的一次只读查询。
修改读取范围、频率、时区或 Skill 版本增加 schedule_version；旧未投递实例置 superseded，新日程按新版本计算。
删除日程软删除并取消待处理实例、清除去重以外的可清理内容；历史收件箱条目保留原来源标题和生成时间，不再自动更新。
权限撤销立即阻止后续查询与投递；失去必要读取权的日程置 blocked，原因“数据权限已变化”，不返回失权对象名称。
恢复权限后仍需用户查看范围并恢复；不得根据新角色自动把“销售部”扩大为全公司。

## 6. 收件箱与对话衔接

收件箱入口包含未读总数，列表每页 20 条；每行显示标题、两行概要、生成时间和成功/部分/失败状态。
点击前无 M01 message/card/thread；websocket/poll/SSE 可同步未读元数据，但不得插入当前聊天或抢占焦点。
成功条目默认标题“今天的待审报销”；失败条目“今天的待办摘要暂未生成”；技术内部任务名不直接作为标题。
用户点击“查看”调用 open，首次创建本人 thread 和 reminder_summary，run_id=null，payload 携带 origin_run_id 与 occurrence_id。
后台 run 的 thread_id=null、origin=subscription、occurrence_id 非空；M12 ActorContext 使用 invocation_origin=subscription、有效 delegation_id、session_id=null，经 M14 生成隔离运行空间，不能创建隐藏用户聊天或复用过期浏览器身份。
同一 inbox_item 再次打开复用 thread_id/card_id；打开历史条目显示“摘要生成于……”，抽屉获取最新数据并指出差异。
点击已删除会话绑定的摘要可重新创建会话，但同一时刻仅有一个有效绑定；原业务摘要不复制出第二条 inbox item。
条目成功渲染后单独标记 read_revision；请求失败或仅鼠标经过不算已读。
已读按用户、item、内容 revision 记录；同条目从失败恢复为成功增加 revision，未读数只增加 1，不按重试次数累加。
失权条目返回经过清除的“此摘要暂不可查看”；不在搜索结果、预览文案或未读聚合中泄露旧部门细节。

## 7. 结构化数据、表约束与有效性

所有 M02 表含公共 id/tenant_id/version/created_at/updated_at；私有记录 owner_id 必填；跨表 FK 带 tenant_id。

| 表 | 关键字段 | 约束与索引 |
|---|---|---|
| memories | kind,key,content,value_json,status,source_kind,source_refs,expires_at,deleted_at | owner 隔离；同 owner+kind+key 仅一个 active；内容 ≤2,000 字 |
| memory_revisions | memory_id,revision,content,value_json,change_reason,source_refs | unique(tenant_id,memory_id,revision)；可删除内容按 30 天清理 |
| memory_profiles | owner_id,memory_epoch | unique(tenant_id,owner_id)；保存/编辑/删/过期失效均递增 epoch |
| memory_source_tombstones | owner_id,source_key,invalidated_at,reason | 防止已删记忆从旧来源摘要自动复活，不存记忆正文 |
| subscriptions | owner_id,type,title,query_spec,schedule_json,schedule_version,status,next_run_at,skill_version_id | title ≤60；schedule_version ≥1；status 索引与 next_run_at 联合 |
| subscription_occurrences | subscription_id,schedule_version,local_date,local_time,scheduled_at,status,origin_run_id,summary_id | 唯一发生键；状态迁移用 version CAS |
| digest_snapshots | occurrence_id,query_spec,source_refs,coverage,generated_at,content_json,status,authz_version | unique(tenant_id,occurrence_id)；来源版本可追溯 |
| inbox_items | owner_id,occurrence_id,channel,title,preview,summary_id,revision,thread_id,card_id,deleted_at | unique(tenant_id,occurrence_id,channel)；个人分页稳定排序 |
| inbox_reads | owner_id,item_id,read_revision,read_at | unique(tenant_id,owner_id,item_id)；read_revision 单调递增 |

memory.status=active/expired/source_unavailable/deleted；subscription.status=active/paused/blocked/deleted。
occurrence.status=scheduled/generating/generated/delivered/failed/skipped_coalesced/skipped_late/superseded/cancelled/delivery_expired。
这些是本模块记录状态，不能写入 run.status；后台 run 继续使用公共 run 枚举。
金额条件仍用 Money；日程 local_time 不能与 UTC timestamp 混为一个字段；coverage 显式区分完整/部分/不可得。
query_spec 保存受控指标/资源/范围及参数，不保存 SQL；owner_id、tenant_id 不允许从客户端 JSON 采用。

```ts
export type MemoryInput = {
  kind: 'response_preference'|'input_preference'|'personal_context';
  key: string; content: string; value: Record<string, string|boolean>;
  expires_at: string|null;
  source: { kind:'explicit_message'|'manual'; message_id?:string };
};
export type DigestSchedule = {
  frequency:'daily'|'weekdays'; local_time:string; timezone:string; start_date:string;
};
export type SubscriptionInput = {
  type:'todo_digest'|'expense_digest'|'document_progress'; title:string;
  schedule:DigestSchedule; query_spec:DigestQuery; skill_version_id:string|null;
  delivery:{channel:'in_app'};
};
```

source.message_id 必须属于本人可见消息且能验证明确保存语义；手工界面保存使用 manual，不允许模型假装来源手工。

### 7.1 记忆上下文与立即失效

ContextBuilder 每次构造 prompt 取得 memory_epoch、authz_version，并过滤 deleted/status/expiry/source ACL。
只将任务所需的 0–8 条记忆加入上下文，附 id/revision/用途/来源；超出按明确 key 匹配与最近用户更新排序。
记忆缓存 key 至少包含 tenant/owner/authz_version/memory_epoch；TTL 至多 60 秒，但不能依赖 TTL 才执行撤权。
保存或删除事务递增 memory_epoch 并发布失效 outbox；API/Worker 在每次模型提交、工具调用、回复持久化和发送前读取当前 epoch。
在途模型使用旧 epoch 时取消该生成，丢弃未投递回复，在最新上下文重新生成；已经发出的文本不能被承诺从外部模型日志抹除。
历史 checkpoint/压缩摘要携带 memory provenance；被删除来源的记忆片段必须删除或使该摘要失效，不能继续用旧摘要间接恢复。
同会话用户刚输入的明确临时事实可用于该任务，但不会重新保存已删记忆；重新永久保存必须再次明示。
删记忆后已准备但依赖该偏好的草稿不会偷偷改值；展示差异由用户决定；业务确认依旧以实际对象和版本核验。

所有路径加 /api/v1；写接口均带 Idempotency-Key、CSRF；修改/删除传 expected_version。

| GET /subscriptions | status,cursor,limit | 本人日程、下一次时间、最近执行摘要 |


query_spec 必须匹配该 type 的 schema；current_approval_scope 每次运行从当前身份推导，并与创建时范围上限取交集。
本例从 2026-11-06 首次发生；日期用于契约示例，实际创建必须从用户明确时间和当前时钟计算。
超过生成窗的手工 retry 使用当前数据生成“重新生成的摘要”，同时保留原 scheduled_at 和 regenerated_at；不得冒充原时刻事实。

LLM 可提出保存候选和订阅候选；只有经过服务端验证的明确用户操作事件才能触发 write 服务。
如需注册 finance.memory.save 或 finance.subscription.create，必须由 M13 冻结 schema 并强制 explicit_user_intent 证据；不能把模型布尔值当证据。
早报运行只允许 finance.todo.list、finance.document.get、finance.preaudit.get、finance.analytics.query 等已登记只读能力。
调度器委托身份以 owner + 当前 authz_version + 订阅范围上限构造；权限不足不切换为平台管理员执行。

## 9. 异常、审计、隐私与运维

| 故障 | 对用户的表现 | 服务端处理 |
|---|---|---|
| 记忆并发修改 | 显示新旧版本与拟改值 | 409 VERSION_CONFLICT，不覆盖另一标签页修改 |
| 源会话删除/业务来源失权 | “来源不可用，暂不使用” | 增加 epoch、阻止检索、失效旧 checkpoint |
| 日程格式错误 | 定位时区/时间字段 | 400 VALIDATION_ERROR，不写半成品 active 日程 |
| 数据提供方部分失败 | “部分数据暂不可用”，标注来源时间 | 部分 coverage，不把缺失金额设为 0 |
| 模型摘要失败 | 仍可查看结构化清单 | 后端模板降级；不重试已完成业务读取写入 |
| Worker 崩溃/租约超时 | 执行记录显示恢复中 | fence 接管；成功摘要写入与 outbox 原子提交 |
| inbox 投递响应丢失 | 最多出现一条摘要 | 唯一键查回原 item；不重跑生成 |
| 数据权限撤销 | 日程 blocked，摘要详情不可见 | 停止后续执行；旧预览即时清除 |
| 用户关闭浏览器 | 无异常弹窗 | 后台继续；下次打开读取可靠未读数 |

审计记录 memory.saved/updated/deleted/expired、subscription.created/changed/paused/resumed/deleted/blocked、digest.generated/delivered/read/retried。
记录 actor、来源 id、目标 id、before/after version、epoch、occurrence、run/trace、失败类别；审计默认不保存 memory 正文。
个人记忆正文直到删除或明确到期；软删除/过期立即不使用，30 天内清理可删除版本；tombstone 只留最少去重元数据。
摘要内容和相关运行默认保留 90 天；收件箱超过保留窗显示过期占位并清理正文；SSE 7 天，与公共契约一致。
监控：due_lag、generation_retry_count、outbox_oldest_age、duplicate_delivery_suppressed、blocked_subscription_count、memory_epoch_mismatch。
告警建议：调度延迟 >5 分钟持续 10 分钟、outbox 最老 >15 分钟；不是性能承诺，需在部署基准中调参。
管理员看任务/租约/错误分类；查看任何个人摘要正文需要独立受控排障授权并审计，不能以 operations.read 自动读取。

## 11. Given / When / Then 验收

1. Given 用户说“我通常喜欢简短回答”；When 未明确要求保存；Then 不写 memories、不改变跨会话偏好。
2. Given 用户说“记住，请先给结论”；When 保存成功；Then 返回内容、来源、持续有效和撤销入口，新会话按此表达。
3. Given 记忆用于两个活跃会话；When 用户删除；Then epoch 增加，两个会话后续上下文不含该记忆，旧在途回复不发布。
4. Given 记忆截至今天本地 18:00；When 时钟到期；Then 新上下文立刻排除，即使旧缓存仍在内存。
5. Given 来源会话已删除；When 另一会话检索关联记忆；Then source_unavailable，不从 checkpoint 或历史压缩摘要恢复。
6. Given 张伟要求餐饮超过 1,000 元提醒；When 作为审核偏好保存；Then 创建 M03 个人规则建议，未启用前预审不变化。
7. Given 陈杰有杭州出发偏好；When 实际差旅改为北京；Then 偏好只作为建议，提交采用确认后的北京字段。
8. Given 工作日 09:00、Asia/Shanghai 日程；When 周六到点；Then 不创建实例，界面明确周一至周五口径。
9. Given 两个 scheduler 同时扫描；When 同一日程到期；Then 仅一条 occurrence、一个生成 job、最多一个 inbox item。
10. Given 服务停机 3 小时错过两次测试实例；When 恢复；Then 只补最近一次，其余 skipped_coalesced，不集中刷多条早报。
11. Given 服务停机超过 6 小时；When 恢复；Then 过期实例 skipped_late，不发送假装实时的早报。
12. Given Worker 已生成且投递响应丢失；When outbox 重试；Then 返回原 item_id，未读数不重复增加。
13. Given 首页正在输入报销问题；When 早报送达；Then 只更新未读数，无新 thread/message/card，无焦点跳转。
14. Given 一条未打开摘要；When 连续双击查看；Then 只创建一个会话绑定和一张 reminder_summary。
15. Given 日程处于生成中；When 用户暂停；Then 当前读取释放资源后停止，发布前检查阻止新投递。
16. Given 用户销售权限被撤销；When 早报 job 被领取；Then 无销售数据查询、日程 blocked，旧预览不泄漏金额。
17. Given 数据源一项失败；When 摘要完成；Then coverage=部分，缺失金额显示不可用，不显示 0 或“全部完成”。
18. Given 失败摘要已被读；When 用户重试成功；Then 更新原条目 revision，未读只增加 1，保留重试与生成时间。
19. Given DST 当日时间重复；When 调度；Then 选择首次 UTC 发生，单日唯一键只投递一次。
20. Given 摘要 Skill 请求 finance.action.prepare；When 后台执行；Then 网关拒绝写意图，无 confirmation、无业务动作。

## 12. 明确完成标准

20 项验收通过；真实数据库重启后日程、快照和未读状态仍可恢复；模型不可用时结构化摘要与失败状态仍可信。
用户能明确保存/查看/改/删记忆，删除后跨会话立即停止使用；所有审核阈值只能通过 M03 生效。
每个已投递摘要可追溯 occurrence→run→查询证据→outbox→inbox；重复触发不会增加第二条消息或业务写入。
调度、去重、授权和恢复不依赖浏览器常驻、不依赖本次 ChatGPT 自动化、不依赖假早报静态数据。
M14 完成后台无 thread 的 run、lease/fence 与 outbox 集成，M15 提供显式演示入口后，本模块才可声明联调完成。
