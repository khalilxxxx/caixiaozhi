# Agent 追问交互验证

已采用输入区追问，支持选项与文字回答、稍后回答、待答恢复、答案绑定及旧问题失效。完整字段和确认提交继续使用右侧抽屉。新建申请使用独立实例，旧稿与暂存内容保留；我的单据和材料导入支持选择具体实例。

## 最新验收：输入区追问

2026-11-17 用户在三个可点击方案中选择“输入区追问”，已接入正式 Agent 本地入口。

- 问题和选项置于底部主输入区域，同一区域填写文字并发送；支持单选、多选及纯文字，不预选、不点选即发送。消息中仅保留问题定位入口及完成后的历史摘要。
- 普通聊天草稿与回答草稿独立；回答按会话和问题保存，刷新、切换和失败保留。服务端问题状态确认后清理答案缓存，恢复原普通输入内容。稍后回答不提交尚未确认的答案。
- 发送中禁用回答、防重复请求；失败就近显示并可重试。中文输入法确认不误发，长选项内部滚动。差旅业务规则不变，收集完成后展示差旅卡片，继续在右侧抽屉编辑并确认提交。
- Agent 前端单元测试：31 个文件、322 项通过，含新增输入区组件与历史展示的 13 项测试。TypeScript、Vite 构建、格式检查及 `git diff --check` 通过；构建保留现有主包超过 500 kB 提示。本轮未改后端。
- 浏览器隔离接口覆盖 14 类场景：唯一回答区、问题定位、单选与补充、刷新恢复、失败重试、防重复发送、普通草稿恢复、稍后回答、纯文字与中文输入法、多选、会话切换隔离、旧问题失效、草稿保存失败后的回答恢复与终态清理、窄屏六选项操作。1440×900、1280×800 与 390×844 截图已核对，无控制台错误；窄屏无横向溢出，聊天区仍有 272px 高度，最后一项及发送按钮可操作。
- 独立复核发现并修复了缓存提前清理问题：本地乐观修改草稿版本后保存失败，刷新会丢失未发送答案。浏览器先复现失败，再验证修复；现在只按服务端明确的问题终态清理缓存，界面仍可即时阻止已失效回答。修复后追问相关 26 项单元测试通过，复核无阻塞项。
- 本地服务 API、前端代理与页面均正常，验证时无活动任务。浏览器使用隔离接口与既有真实模型快照，不写入用户会话，不提交业务申请。

浏览器验证脚本与截图位于 `/tmp/caixiaozhi-question-composer/`。

## 上轮验收：差旅追问与待补回程

2026-11-17 根据用户进一步确认的规则完成收敛，工作区恢复后重新验证并加载本地服务。

- 自动推荐的起点、交通和席别直接使用；只有无法默认的缺失行程信息才追问。每段到达日期默认等于出发日期，明确日期、人工清空和明确跨日安排优先。
- 明确返程未定时生成一次待补回程，保留稳定行程 ID。回程日期不猜、不反复追问；后续只更新用户明确的信息。删除占位回程后不再自动生成，多城新增后回程衔接最后一站与实际起点。
- 追问阶段持续保存草稿和引用，但不展示差旅结果卡；收集结束后展示可编辑卡，明确标识“回程日期待补”。编辑、检查和提交继续在右侧抽屉完成。日期缺失可保存草稿，仍不能正式提交。
- 暂停恢复根据成功写入记录区分“已建立的新草稿”和“仅读取的旧单”，避免重复新建或错误续办。历史卡片元数据独立提供给模型，不混入助手正文。
