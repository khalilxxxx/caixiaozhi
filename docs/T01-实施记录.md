## 本轮解释与默认选择

1. `00` 第 3.1、4、7 节将真实 dsh 作为首阶段成果，`03` 将其分到 T03。按用户本轮明确范围只完成 T01，dsh 兼容性在 T03 验证。
2. `01` 第 5.1 节未限定整数金额的正负边界。本轮 Money 使用规范十进制整数分字符串，允许负值，拒绝小数、前导零、正号及负零。具体业务金额的非负约束由后续领域 schema 定义。
3. 卡片 payload 由后续阶段按类型补充。本轮定义卡片信封、固定类型及严格 payload schema 工厂，未注册的业务 payload 明确拒绝。公共事件定义既定 SSE 信封，outbox 的领域事件保持领域自有 schema，不冒充 SSE run 事件。
4. 本轮不建立身份或匿名文件业务接口。文件适配器只供服务端及技术集成验证使用。
5. `db:seed` 执行数据库连通和迁移检查后作空初始化，不注入 02 中的演示人员和业务单据。production 拒绝 seed/reset。
6. 环境分为 APP_MODE=demo/test/production，NODE_ENV 由开发和构建工具选择。时间使用数据库 timestamptz 和 UTC 连接时区，业务时区默认 Asia/Shanghai。

## 验证结果

依赖安装、锁文件复验、类型检查、构建及格式检查通过。单元 13 项、契约 108 项、真实集成 14 项，共 135 项测试通过。真实 PostgreSQL/S3 重启持久性、匿名403、Web正常/断线/503状态及编译后API/Worker SIGTERM退出均已验证。具体命令、初次失败与修复见 `T01-验收报告.md`。

Docker Compose 因本机缺Docker仅执行静态校验。采用真实原生服务完成数据及对象存储验证，容器启动仍需补验。dsh/业务E2E/负载按阶段保持明确未实施。

## 补充实施选择

- 本地S3服务使用RustFS 1.0.4，版本、SHA256和镜像digest可实际核实。原生macOS构建需ASCII可执行路径。
- PostgreSQL语句时限2500ms、客户端查询3000ms，防止依赖阻塞耗尽连接及退出无限等待。后续长迁移需显式受控调整。
- `01`第5.2节错误meta示例仅request_id/trace_id必填，额外server_time/data_mode提供时仍严格校验，成功meta四字段必填。
- 删除额外的TRUNCATE reset逻辑，T01 reset只有production守卫与未实施退出，避免超出本轮范围。

- 为确保开发退出清理可靠，API/Worker使用node --import tsx直接运行，源码变化手动重启。已复验pnpm dev的Ctrl+C清理，Web仍由Vite热更新。
