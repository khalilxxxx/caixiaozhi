# 单 Agent 执行进度与成果交付

用户已授权开启 thinking、优化第一批能力，重点是真实执行进度和前端交互；不引入多 Agent、长期记忆或复杂任务平台。

## 实施选择

复用现有 Agno 工具循环、SSE、SQLite、技能工作区与成果接口。对话中用紧凑状态行显示真实当前动作，展开查看本轮步骤、状态及耗时；完成后默认收起。普通查询无需人为拆步骤。模型内部推理、原始脚本输出、秘密及路径不呈现在业务界面。

采用真实工具事件驱动，优于只增加动画（不能解释实际执行）或新建独立任务中心（打断会话且重复存储）。用户已要求开始，按既有产品风格直接实现，保留已有未提交变更。

## 数据契约

工具事件和消息 tools 使用同一记录：id、name、label、status、startedAt、finishedAt、durationMs；status 为 running/completed/failed/cancelled。每次调用唯一 id，开始和结束复用；重试另建记录。旧历史无 id 时兼容展示。原始 input/output 可留后端诊断，但前端仅展示允许字段。

status 事件允许 phase、label；界面只呈现服务端实际状态及工具动作，未知进度不显示百分比。刷新/重连按事件 id 去重，历史运行与当前运行分开。暂停/失败后仍保留步骤和成果，追问不展示为全部完成。

## 本轮范围

- DeepSeek 官方接口开启 thinking，保留非 DeepSeek 配置兼容，不展示内部推理。
- 后端保存每次工具调用及终态，补齐失败/取消/重启的记录；文件生成未交付不能宣称完成。
- 前端接通当前动作、可展开步骤、失败/待答/暂停状态，保护输入与滚动位置，支持390px和桌面。
- 成果发布增加格式可读性与可执行的数据一致性检查；明确校验边界，不宣称通用版面智能检查已完成。
- 复用票据 OCR 供材料提取，保留证据和人工核对；业务工具结果以来源快照直接进入技能工作区，减少模型转抄。

## 验收

针对真实状态迁移、重复事件、重试、部分失败、重连、草稿/成果保留及金额一致性验证。执行后端回归、Agent前端单测、类型检查和构建；桌面与390px浏览器检查；真实模型验证 thinking 的工具往返，不自动提交业务单据。
