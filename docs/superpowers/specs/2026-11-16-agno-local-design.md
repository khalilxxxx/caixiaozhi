# 财小智本地 Agno 产品 Demo 设计

## 目标与授权

用户要求整套 5190 产品通过真实智能体架构运行，允许以模拟业务接口、政策制度和单据数据补足外部来源；授权梳理后自行评估、建设、部署与验收。保留现有界面风格与全部主流程，不再使用固定聊天回复。

## 方案评估与决定

1. 接入旧 Fastify/Postgres/Worker：复用完整权限和账本，但旧工程与独立 5190 的草稿、规则、分析、技能对象不一致，整版迁移成本高。
2. 为 5190 建设 Python Agno + FastAPI + SQLite：统一独立产品的数据与执行，可快速完整部署，适合本地单用户 Demo；未来接入正式系统时需替换业务适配器。
3. 仅替换聊天回复：无法让对话和界面共享业务对象，不采用。

由实施方选择方案 2。旧工程和数据库保持独立。此次不是生产多租户部署，不宣称已接入真实 OA/报销/银行。

## 运行架构

React（5190）通过同源 `/api/local` 调用本地服务（5191）。Agno Agent 负责多轮对话、工具选择、制度解释、结构化草稿建议、规则建议与文件内容任务；工具负责确定性查询、金额计算、草稿保存、校验和模拟业务执行。SQLite 保存工作空间、消息、run、工具记录、文件元数据与业务回执，文件字节写入受控数据目录。

模型配置读取后端 `.env` 中 AGNO_*，兼容已有 DSH_* 配置，禁止把密钥发到浏览器。使用现有 DeepSeek 连接进行真实验收；缺失配置或模型故障必须显示真实失败，不降级固定回复。

## 状态与接口

后端工作空间采用现有 `{data,tasks,activeTask}` 契约。启动只种入合成业务资料，不种入假聊天历史。`GET /workspace` 返回状态与修订号；`PATCH /workspace` 只允许界面编辑所需的 slice 与会话元数据，使用修订冲突保护，不得覆盖运行结果与回执。

`POST /runs` 创建任务，`GET /runs/{id}/events` 提供流式事件，`POST /runs/{id}/cancel` 真实取消。事件为 status、delta、tool、result、error、done；result 返回受控卡片、状态与最新业务数据。工具调用记录可核查。

业务接口负责文件上传/下载、草稿校验、确认提交/回执查询、规则建议/预审、来源查询、技能资料与分析。用户明确确认后调用提交端点，产生真实持久化的本地模拟单号与回执。Agent 只能准备草稿，不能自行确认。

## 数据与边界

合成制度包含明确来源与适用条款；单据与统计来自一致的后端种子。真实上传保存字节；文本/PDF/CSV 等可解析内容用于工具，图片无 OCR 时等待人工填写，禁止将样例识别结果套用到上传文件。上传技能保存内容，运行只允许受控工具与已发布文本指令，不执行上传代码。

本地服务只绑定 127.0.0.1，同源请求校验，文件大小与类型限制，文件名不用于服务器路径。模拟业务服务可返回真实本地受理与流程记录，但不冒充外部系统正式审批。

## 界面与验收

遵循 AGENTS.md、DESIGN.md。智能提单仍全程右侧抽屉，技能上传仍居中弹窗；页头不添加讲解，指引默认隐藏。必要状态使用简短中文，合成来源在详情/数据来源处标明。

验收覆盖真实模型至少一轮工具往返、多轮追问、取消、模型失败、文件字节持久化、业务查询与分析一致、草稿校验与幂等提交、回执可查、修改后重验、规则与技能持久化、服务重启恢复、桌面和窄屏主要页面。部署提供启动/停止/状态命令与中文说明。
