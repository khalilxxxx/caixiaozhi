# 技能工具统一目录：研究结论与重构方案

日期：2026-11-17。

状态：用户已选定“统一目录，技能和工具作为类型筛选；维护和审核进入独立管理入口”，并在恢复源码后要求继续实施。统一目录、独立管理、工具适配与右下角指引已落实到原工作区；本轮最终集成与验收记录由主线程补充。本文保留初始研究的历史证据，并作为当前设计约定。

## 1. 结论

初始研究发现，信息架构、使用状态和运行体系没有统一：当时页面同时按能力类型、所有者和管理任务分组，技能、内嵌旧工具和原生 CSV 工具各用一套界面。当前实施已按所选方案分开使用与管理，并统一目录和外层视觉；不同执行能力仍保留真实的权限与运行边界，不统一标成“可调用”。

初始研究由独立产品审查、视觉证据审查及运行边界审查交叉核验。历史浏览器走查覆盖旧版目录、详情、个人技能、团队管理、工具目录、工具管理、费用汇总和使用指引，以桌面为主，未执行上传、审核、发布、模型任务或删除。该记录仅描述重构前的研究范围；重构后的响应式实现已纳入本轮交付，实际桌面与窄屏验收结果另行记录。初始走查期间有其他任务热更新侧栏名称，本方案不涉及那部分导航调整。

以下问题、入口名称和源码行号对应重构前已读取并走查的版本，用于说明设计依据，不作为当前实现仍存在这些问题的结论。

| 优先级 | 问题 | 用户受到的影响 | 主要证据 |
| --- | --- | --- | --- |
| P1 | 技能目录、小工具、我的技能、团队资产混合不同分类维度 | 同一资产多处出现，不知道在哪里使用、哪里维护 | Skills.tsx:500、520；tool-center/app.js:33 |

| P1 | 创建者和审核者的入口混在一起 | 维护者看到审核操作，审核者缺乏明确待办视图 | Skills.tsx:644、1702、1812、1898 |
| P1 | 主应用、旧工具目录、CSV 页面各有一套外壳 | 重复导航、两套身份、不同按钮色和双重滚动；CSV 不进入目录搜索收藏 | ToolCenterEmbed.tsx:33、39；tool-center/app.js:33 |

旧版“团队资产”实际是全部技能视图，没有独立团队范围筛选；“我的技能”是 owner 等于“我”的资产，不是收藏或安装列表。这两个旧标签已由统一目录与独立管理替代。收藏仍不会授予权限，也不会把能力加入会话。

当前审核状态会保存，但技能审核尚未形成真实的服务端角色隔离；不能把前端隐藏按钮当作完成了组织权限建设。旧工具审核有演示角色判断，仍属于独立浏览器状态。

## 3. 方案比较与已选方向

方案一：统一目录，以类型筛选技能和工具，管理单独进入。优点是一个地方搜索、比较与收藏能力；代价是需要统一目录元数据与状态，并保留不同执行入口。用户已选择此方案。

方案二：保留技能和工具两个目录，统一管理与视觉。迁移较小，但用户仍需先理解技术类型才能决定进入哪里，不符合本轮降低理解成本的重点。

## 4. 页面划分

### 4.1 统一目录

页面标题沿用“技能工具”。页头只展示标题及按权限出现的业务操作，不添加用途介绍或副标题。

目录提供一套搜索、类型筛选（全部／技能／工具）、业务分类及收藏筛选。管理入口独立；上传或添加能力位于管理区域，避免与日常使用争夺主操作位置。目录不再提供“我的技能”和“团队资产”两个同级标签。

目录展示当前账号可查看的已发布版本；草稿、审核中和退回版本进入管理。仅存储的只读资料标为“仅供查阅”，没有调用权限标为“无使用权限”，包检查或运行条件受阻标为“暂不可用”；均不展示使用按钮，详情说明实际原因。一个资产有新版草稿时，目录继续以当前已发布版本为准，管理区同时显示现行版本和最新提交版本。

卡片统一包含：名称、类型、一句真实用途摘要、维护者、当前版本、当前可用状态、收藏及一个主要动作。用途摘要帮助选型，属于资产业务信息；教程、操作示例不放入卡片。

技能主要动作为“在对话中使用”；工具主要动作为“打开工具”；只读资料为“查看详情”。点击名称打开详情。不得使用“查看与选择”这种把两步混在一起的主操作文案。

CSV 费用汇总作为普通工具进入目录，和其他项目使用同样的搜索、分类与收藏，不保留目录上方特殊横条。

### 4.2 独立管理区域

“我创建的”负责上传、草稿、包检查、提交审核、退回修订及版本维护；“审核发布”负责当前有权处理的审核与发布。管理员查看全部资产属于管理视图，不回到普通目录增加导航。

管理采用统一表格，以名称、类型、现行版本、待处理版本、发布状态、更新时间和当前动作组织。技能与工具使用同一管理入口，但各自需要的业务字段与检查内容必须完整保留。

现有技能说明下载、工具分享与旧链接、文件预览、版本查看、可见范围、使用范围、申请使用、访问申请处理及停用功能继续保留。查看、下载、分享放在详情或工具结果的相关位置；权限范围、申请处理和停用归管理，仍按原有权限提供。

本轮不自行新增“未审核技能直接私用”能力，不放宽既有运行门槛。若未来需要个人试运行，应作为独立权限与隔离能力设计，不能通过改页面绕过审核。

### 4.3 详情与操作容器

目录详情使用右侧抽屉：先展示用途、输入输出、可用性与主要动作，版本记录和权限等信息按需展开。

上传技能、上传工具使用空间充足的居中弹窗，完整保留文件、版本、用途、校验结果和提交反馈。不得为了统一表面形式而丢失原有字段。关闭时保留草稿或明确确认放弃，返回触发控件。

工具运行使用完整业务工作区。统一页头、返回、运行状态、结果与导出区；移除旧工具目录的内层导航、重复身份和重复帮助。上传 HTML 工具的运行隔离仍保留，界面统一不意味着取消隔离。

自有工具统一业务组件与真实运行反馈；任意上传的 HTML 工具先统一外层页头、返回、加载和加载错误。其内部运行状态、结果与导出保持工具原有能力，除非已经提供可核验的通信协议。本轮不自行新增协议，也不通过外层按钮伪造内部运行完成或结果下载。

## 5. 三条核心使用流程

使用技能：搜索或筛选 → 在对话中使用 → 绑定所选技能与发布版本到当前草稿 → 用户补充需求后发送 → 在原会话查看状态与成果。选择不自动发送、不新建空会话、不覆盖文字与附件。没有当前会话时先进入可继续编辑的首页草稿。

使用工具：搜索或筛选 → 打开工具 → 选择真实文件或填写参数 → 明确执行 → 查看结果与下载。只有真实接通对话引用的结果才提供对应入口；不能给浏览器工具增加无法履行的“交给 Agent”按钮。

维护资产：管理 → 我创建的 → 创建或修订 → 文件校验 → 保存草稿 → 提交审核 → 查看审核与发布状态。审核操作另从审核发布进入，当前阶段、进行中与已完成的视觉表达必须一致。

## 6. 状态与运行边界

发布状态、账号权限、运行条件和执行入口分开存储与判断。目录只给出当前用户能否完成主要动作的结论；原因在相关控件和详情就近展示。版本已发布不自动等于当前可用。

| 能力 | 当前真实执行方式 | 结果能力 | 重构约束 |
| --- | --- | --- | --- |
| 已发布上传技能 | 对话任务；满足环境与权限时可运行隔离脚本 | 可按现有服务生成和发布成果 | 更正“上传代码不会执行”的过时指引，不把上传和运行混为一谈 |
| CSV 费用汇总 | 页面与 Agent 共用服务端实现 | 保存完整结果，可重开并下载；同原件可复用结果 | 保留真实历史和结果定位 |
| 两表核对、台账转换、费用分析报告 | 浏览器内确定性计算 | 即时结果与导出；持久保存主要是活动摘要 | 不把活动摘要称作可恢复结果历史，不宣称已接入 Agent |
| 用户上传 HTML 工具 | 隔离 iframe | 依工具本身能力 | 保留安全边界，如实展示可用性 |

目录可以统一展示，但正式统一身份、可见范围、发布权限和使用权限需要服务端支持。在此之前，不通过隐藏内层身份或前端映射伪装成已经打通授权。过渡期保留必要“演示权限／浏览器本地保存”状态标识，详细限制放在交付说明或使用指引。

过渡期每项资产继续由原来源判定查看、使用、管理与审核能力；统一目录只汇总判定结果，不按人员名称合并账号，也不重新授予权限。演示工具在相关状态或详情中简短标明权限来源，演示角色切换只放在右下角指引内。技能审核若缺少真实角色授权，保持明确的演示审核状态，不能以按钮显隐冒充完成角色隔离。

本轮界面重构不包含建设统一服务端授权系统。主应用当前身份用于既有技能与原生工具；旧工具继续使用原有所有者和演示角色判断，不把主应用用户直接映射为旧工具审核人。统一管理按来源汇总允许的操作，并保留必要权限来源标识。

相似功能按输入、输出与执行方式区分：CSV 费用分类汇总、费用基础报告、月度费用分析技能可以共存，但名称和摘要必须准确，不凭相似名称直接删除功能，也不把尚未连接的 Skill 标成已关联执行。

## 7. 视觉统一

沿用当前 Agent 工作区已确定的中性灰白办公界面与少量珊瑚红主操作，不另建新的品牌主题。

统一页面宽度、页头、搜索筛选高度、卡片密度、标题和正文字号、图标位置、按钮高度、边框、圆角、状态色及空态。目录卡片采用同一阅读顺序，不再出现技能图标独占一行、工具图标与标题横排两种规格。正文和元信息不能依靠 9px 标签及 11px 长描述承载关键判断。

工具工作区沿用相同组件与设计变量。页面由单一主容器滚动；表格和编辑区仅在必要时局部滚动，避免页面与整页 iframe 各有一条滚动条。

窄屏将筛选和卡片自然换行，详情及完整表单按可用空间调整；主要操作、错误和关闭入口始终可达。实际验收覆盖 1440×900、1280×800、768px 和 390px 宽视口，不将源码断点存在等同于验证通过。

## 8. 右下角使用指引

全模块只保留一个右下角“使用指引”，默认收起、用户主动打开、可随时关闭；按当前目录、详情、上传或工具页面显示对应内容。

以下全部移入指引：功能讲解、使用步骤、技能与工具区别、提问示例、示例 CSV 下载、使用示例数据、示例工具文件、演示身份切换和演示流程。旧工具内层右上帮助入口移除。

旧工具不再默认装载示例文件或自动执行示例。用户主动从指引使用示例后，业务区必须保留“示例数据”来源标识；示例标识属于真实数据来源，不应为了简洁隐藏。

以下保留在任务相关位置：字段标签、必要格式与容量限制、权限不足原因、输入校验、执行失败和恢复操作、真实数据来源、结果与保存状态。技能详情中的输入输出属于资产内容，不迁走。表单占位文字只表达必要格式，不承担教学。

指引统一为：“上传本身不会运行代码；已审核发布且环境可用的技能，可在任务隔离环境执行脚本。”并说明哪些工具可以在对话使用，哪些只能在页面打开，避免笼统承诺。

## 9. 交付验收

- 同一目录可搜索全部技能与工具，CSV 费用汇总不再是特殊入口。
- 普通使用路径不要求理解审核、资产治理或模拟身份；管理功能完整保留且入口职责清晰。
- 卡片可用状态与实际主要按钮一致；无权限、未通过检查、环境不可用分别解释。
- 有新草稿时仍能选择有效发布版本；选择技能保留会话草稿、附件与滚动位置，不自动发送。
- 工具打开、返回和旧分享链接指向正确资产；返回目录恢复筛选和位置，不留下无关 CSV 横条。
- 技能上传、工具上传、退回修订、版本查看、审核与发布字段和反馈无丢失。
- 下载、分享、文件预览、可见与使用范围、申请使用、访问申请处理和停用按原权限保留，不因统一目录遗漏或越权。
- 实施前对照实际源码核对既有操作清单；删除、撤回、下架或版本恢复等如实际存在则完整保留，不凭本方案自行新增。
- 工具结果是否保存、是否可恢复、是否可被 Agent 调用均与真实实现一致。
- 默认页面、卡片、抽屉、弹窗和空态无教程与示例；右下角指引支持键盘、关闭和焦点恢复。
- 原有业务校验、数据来源、环境限制和脚本隔离保留，视觉统一不改写业务真相。

## 10. 审查记录

初始版本的独立产品启发式评估为 21/40：主要短板是一致性、简洁性和状态表达；已有优势是详情信息、会话技能选择和上传草稿／版本保护。该评分仅用于本次问题定位，不是上线验收结论。

初始研究的机械扫描产生 1 条 warning、0 条 error；warning 为浅色页面 toast 阴影被识别为 dark-glow，经实际截图判断为误报。未注入浏览器检测叠层，未启动额外服务。自动扫描不能替代跨页面流程与视觉审查。

当前已从研究与设计进入实施：统一目录、独立管理、工具工作区适配和右下角指引已落地。最终验收结论以本轮集成记录为准；本轮不对统一服务端权限接入、原浏览器工具完整结果持久化或新增 Agent 调用能力作已完成承诺。

实施前的独立方案复核已补充权限判定来源、现有分发与访问操作保留、上传 HTML 工具的外层统一边界；用户恢复源码并要求继续后，已按该边界推进实施。

历史情况：初始文档整理期间，原工作区源码曾暂时不在原位置；随后用户恢复了源码。实施已在恢复后的原工作区继续，保留并行开发成果，未重建缺失工程，也未提交用户已有改动。第二节的旧行号继续作为历史研究证据保留。
