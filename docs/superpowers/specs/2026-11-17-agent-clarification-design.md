# Agent 追问交互

用户已认可前一轮建议并要求开始优化。沿用现有 React、Agno、FastAPI、SQLite 与企业主题，不新建产品入口。

对话中的任务选择、歧义澄清和无法默认的缺失行程信息采用可直接回答的追问卡片，保留单选、多选与自然语言回答。当前任务最多一个有效待答问题，回答后显示已回答摘要并继续同一会话；暂不处理、刷新恢复、重复提交、旧问题失效都使用真实状态。问题和回答由服务端保存并绑定任务，不能只把按钮文案当无关联的新消息。

先读取现有草稿，保存用户本轮明确提供的信息并应用默认规则，再追问无法默认的缺失行程信息，例如目的地、出发日期和未知线路交通。已有起点、交通或席别推荐直接使用，普通差旅申请的到达日期默认等于该段出发日期，不为确认默认值而追问；明确日期、人工清空及明确跨日安排保留。已提供或已说明暂未确定的信息不重复追问。完整字段编辑、校验和提交仍在右侧抽屉完成，确认提交不与回答问题混用。

未说明返程安排时可问一次；用户明确返程未定后保存 `returnDatePending`，生成或保留同一条稳定 ID 的待补回程，城市衔接实际行程、交通采用可用推荐、日期留空，不再追问返程日期。后续只更新用户明确的目标字段，保留其他行与人工内容；明确单程不添加返程。待补回程可保存草稿，缺失日期仍阻断提交。

追问阶段的草稿、业务引用和工具成果持续持久化，消息标记 `collecting` 并隐藏其中的提单卡；其他业务卡和历史已展示卡保留。收集结束后标记 `ready`，仅展示最新目标草稿卡，用户可打开右侧抽屉编辑和提交。模型失败、暂停或服务重启后，若仍有待答问题则保持 `collecting`，否则展示已存草稿供恢复。卡片元数据只作为独立系统上下文供模型定位和续办，卡片由界面自动展示，助手正文不复述内部 JSON、草稿 ID 或元数据说明。

支持新建北京申请并保留上海草稿，草稿类型与实例身份分离。兼容既有 travel/expense/personal 入口、暂存编辑、校验及回执；新实例使用空白业务字段，避免继承示例行程。失败或暂停后的续办使用当前绑定的真实实例 ID，保留已存成果，不重复新建；新建还是修改仍有歧义时先澄清，不擅自覆盖旧单。历史草稿可从我的单据查看与继续编辑。

比较过只添加快捷回复、对话追问结合抽屉、把完整表单搬入聊天三种方向。本次采用第二种：补齐任务决策交互并复用现有填单能力，避免重复表单和长段追问。

验收以有既有上海草稿的北京出差为主：问题可回答、同一任务继续、旧草稿保留、字段在抽屉补齐；同时覆盖自由文本、多选、暂不处理、刷新恢复及旧问题不可重复执行。差旅连续补充还需覆盖默认值不追问、缺失出发日期追问、返程未定后结束收集、原回程目标字段更新、追问与出卡顺序、失败恢复不重复新建，以及正文不外露卡片元数据。
