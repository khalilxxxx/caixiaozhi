# 财小智对话过程优化

用户初步偏好：极简高效，接近 Claude / Codex，趣味点到为止。

最新范围：用户随后要求先做三版交互预览，再选择正式方案。本轮仅交付 `apps/web/public/demos/conversation-comparison/index.html` 及其独立资源，不执行下述正式改版。A 为专业有温度，B 为陪伴感更明显，C 为极简高效。初步偏好不视为最终选定。

## 目标与方向

在现有 React Agent 入口优化真实执行过程、消息阅读节奏及输入反馈。保留灰白办公背景、珊瑚主操作与蓝白小智。采用轻量行动摘要与按需展开的工作记录，不增加流程看板或明显的角色表演。

当前动作优先来自正在执行的工具，其次来自服务端阶段。可用阶段为分析、处理、核对、整理回复；不推断未发生的未来步骤。多工具并行时如实显示同时执行数量。工作记录提供实际步骤、状态、真实耗时；完成收起，失败、暂停与待回答仍可理解。只有确切时间戳才显示运行时长，不用工具耗时之和伪装整轮耗时。

回复使用更舒展的文字、间距与低对比背景，减少后台表格感。助手身份与内容保持清楚层级。趣味仅由工作指示符的轻微呼吸和复制成功的就地反馈承担，不增加随机文案、模拟思考或人为等待。

运行中输入仍可编辑，明确草稿保留与停止操作；不宣称支持尚未实现的队列或实时引导。保留现有追问、草稿、结果卡、停止与恢复逻辑。使用指引默认收起。

## 方案取舍

- 轻量对话过程：本轮采用，改动现有组件，符合用户极简高效偏好。
- 展开式任务看板：信息量较大，不适合每轮财务对话。
- 角色陪伴式表达：动效与表情更明显，与用户选择不符。

## 验收

真实状态与重试不被掩盖；长步骤、无工具、并行工具、等待回答、暂停失败均可读。键盘可展开记录；系统减少动效及页面隐藏时停止循环。1440×900、1280×800及窄屏不溢出。前端类型检查、构建、相关状态与会话回归测试通过；浏览器核对实际聊天和完成状态。
