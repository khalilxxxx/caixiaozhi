# SRS 语义规则执行与场景示例

## 目标与授权

用户要求优化规则平台，恢复原 SRS 执行时调用 LLM 的能力，为差旅申请与费用报销建设规则 Demo，并评估历史规则是否应全删。此前已核实原 SRS 的执行器及当前能力缺口；按用户本轮实施授权直接建设。

## 实施决定

采用现有 Agno 服务中的语义执行器：代码准备业务上下文、选择规则，LLM 按业务指令判断并返回可定位证据，代码校验与汇总。保留数值、重复材料等现有确定性检查。仅扩充关键词无法满足语义需求；直接依赖相邻 SRS 项目会引入独立服务、存储及版本耦合，因此复用其契约思想，不跨项目运行代码。

新增规则使用 metric=semantic，包含 instruction、requiredFields、documentTypes。规则系统仍为 oa/expense，范围仍为 submit/review/both。生成允许自然语言语义条件与组合，不能编造制度阈值、不可用事实或自动审批。新建个人规则仅提醒。

## 执行与证据

输入包含单据类型、事由、行程、活动、费用行及附件元数据，金额保持代码计算。LLM 只使用输入事实；处理否定、计划/实际及不确定语境，不把提及敏感词直接认定为消费。输出逐规则 MATCHED/NOT_MATCHED/INSUFFICIENT_EVIDENCE，中文原因及 path/quote 证据。代码验证规则完整性、引用路径和原文；模型故障或非法输出形成待核实，绝不退回关键词假结果。

检查在数据库事务外调用模型，保存前核对单据版本、规则签名和来源快照；变化则拒绝保存过期结论。提交复用相同快照的已检查结果并重新进行基础校验。预审结果存服务端，前端不重算语义结果。

个人语义提醒的命中和证据不足均如实展示，不升级为公司提交拦截；原有公司强制检查与基础字段校验仍决定是否可提交。

## 历史与示例

不全删历史规则。保留重复材料、住宿上限、费用凭证、餐饮金额和长差旅提醒的现有阈值、启停状态。通用 OA 强制附件规则与差旅实际必填不符，原始示例停用，保留原版本与说明。用户自建内容、草稿、历史单据和回执不删除。

新增六类可编辑语义示例：差旅事由明确性、差旅私人活动风险、行程与业务安排一致性、业务招待高档消费风险、费用与报销事由一致性、业务招待信息完整性。每类提供命中、未命中与证据不足样例。样例明确标注合成数据，不作为企业制度。

## 界面与验收

沿用现有企业主题和独立规则编辑页。详情展示业务逻辑、检查依据和证据结果；提供默认收起的样例测试入口，真实调用模型。页头不增加教学说明。原有启停、版本、草稿和提单抽屉不受破坏。

验收覆盖语义生成、肯定/否定/缺证据、伪造证据拒绝、模型异常、迁移幂等、用户规则保护、版本过期、真实模型测试、前端类型检查与构建、桌面界面。
