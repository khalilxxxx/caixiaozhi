# 财小智 PC 对话首页实施计划

> 用户已确认前轮方向并补充快捷功能、外露上传与技能、随机示例，明确要求开始修改。主线程整合导航与视觉，独立代理实现对话入口、应用选择及会话模型，最终统一复核。目录不是 Git 仓库；备份位于 artifacts/agent-first-home-20261116/before/。

**目标：** 首页以新会话与自然语言输入为核心，应用辅助办理，提供清楚可操作的能力入口。

**架构：** 复用现有 React、TypeScript、CSS 及业务面板，保留本地数据。会话历史按真实消息时间排序，业务待办入口单独过滤；快捷功能只准备需求，不伪造执行结果。

**设计依据：** 本轮用户已批准的讨论及补充要求。仅面向 PC，验证笔记本和桌面尺寸。

## 约束与决定

- 侧栏：新建会话、常用应用（待办中心/智能提单/数据分析/规则中心/技能中心）、全部应用、最近会话、个人信息。删除工作空间/我的任务/消息主导航及偏好设置入口。
- 移除首页完整顶栏；右上通知保留，搜索迁至侧栏。应用页保留本地标题与业务操作。
- 输入框常驻上传文件、选择技能、快捷功能。快捷功能包含回单查询、附件翻译、合同分析，不隐藏在不明含义的关联入口中。
- 输入框下随机展示 3 条中文示例，支持换一组，不自动轮换、不自动发送、不覆盖已有草稿。
- 首页最多 2 条轻量需处理提醒，不显示进行中任务列表或固定应用卡片。
- 现有 demo 没有真实翻译/合同/银行回单服务，新入口明确收集需求与材料，发送后如实反馈未接入，不返回伪造结果。
- 规则与技能选择保持当前权限与可调用状态，不把不可调用技能变成可执行能力。

## 复核重点

- 连续快捷选择或技能引用不覆盖草稿、不拆成多个会话。
- 后台状态刷新不冒充新消息时间；旧时间不确定时不显示虚构的相对时间。
- 应用入口增长不挤占历史会话；用户可找到完整待办和全部应用。
- 首页示例稳定展示，换一组有效且不影响当前输入。
- 新能力未接入时不使用已有分析/票据分支伪造处理成功。
