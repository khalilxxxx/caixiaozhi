# 首页双方案本地交互原型

用户明确要求独立构建WorkBuddy与Kimi两种思路，只做首页交互，保存本地HTML、不部署。原agent.html不修改。两版保持财小智品牌、272px侧栏、约760px居中输入框与原应用入口，以便比较信息架构与点选行为。

## 设计与证据

A借鉴WorkBuddy的场景组织：业务场景分组→快捷任务→任务样板→同一个对话草稿。官方通用首页可确认分组和框上方快捷布局；Buddy行业定制版官方文档可确认工作模式、预置场景与指令卡。财务分组、模板弹层属于本次迁移方案，不声称逐项复刻通用首页。

B借鉴Kimi的能力直达：框下方少量明确能力→专属输入状态→上下文提示与相关示例。实测kimi.com/deep-research与/docs均改变placeholder并显示底部能力状态。财务专属任务提示属于本次设计，不冒充Kimi原生财务能力。

两版：上传文件只保留本地元信息、技能可多选、场景/能力切换保留文字附件技能、示例准备草稿、不自动发送。发送仅本地确认输入并明确未执行；禁止伪造查询/审批/翻译结果。提供收起的使用指引。侧栏展示一致；超出首页范围的入口准确说明边界，不伪造完整应用。

- [x] workbuddy.html：场景分组、上方任务标签、模板选择、下方随机示例，首页基础交互。（子代理）
- [x] kimi.html：框下方能力入口、专属状态与切换/退出、上下文示例，首页基础交互。（子代理）

- [x] 本地浏览器验证两版桌面尺寸、选择保留、键盘关闭、文件与发送边界；保存截图、只读复核与最终交付。（主代理）

所有产物放在 apps/web/public/demos/home-comparison/，核心两版均内联CSS/JS及本地品牌图片，支持双击打开，无CDN和后端依赖。可通过已有127.0.0.1:5190本地服务预览，不启动外网部署。

## 完成验证

独立本地Chromium通过file://打开两版，拦截并确认无HTTP外部依赖。1440×900与1280×800的输入框中心分别为450与400，未出现水平溢出。切换保留文字/文件/技能，选择能力不自动填入长指令，模板追加、能力退出、技能空态、Escape、新建取消与确认、发送尚未执行反馈均通过。index iframe方案切换通过。无JS运行时错误，完整记录见 artifacts/home-comparison-20261116/verification.json。

统一修正小于12px的元信息字号、对比不足的辅助文字及头像文字，使用系统中文字体；无规则忽略。两默认截图位于交付目录preview-workbuddy.jpg/preview-kimi.jpg，其余截图位于artifacts/home-comparison-20261116。独立只读复核查看全部6张截图，结论ship，未发现实质P1/P2；范围与局限已按截图/实测证据区分。

WorkBuddy证据修正：5.11.0官方更新日志明确下线通用首页办公/开发/设计入口，因此A为场景组织迁移，参照行业定制版的场景及指令机制，不标为最新版复刻。两版未改动原agent.html。
