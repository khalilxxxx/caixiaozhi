# 智能提单默认填写实施计划

目标：落实用户要求的历史规则梳理与默认填写优化，减少重复追问，保护人工编辑。

设计依据：[默认规则与场景优化](../specs/2026-11-17-submission-defaults-design.md)。现有工作区有多项未提交改动，原地局部修改并保留，不覆盖、不整体格式化、不混入提交。

- [x] 并行核对智能提单、智能报销项目，区分已实现规则、目标文档与演示夹具。
- [x] 新建服务端默认引擎及独立员工/线路参考配置；先写失败测试，再实现 Base、衔接、返程、交通/席别、短途日期与人工保护。
- [x] 将默认规则接入 Business 和 Store 两条写入路径，模型以有效草稿为基线，保护版本、已提交快照与来源。
- [x] 优化 Agno 提单工具说明与指令；通过真实业务服务的运行器集成测试验证默认行为和缺项。
- [x] 在原右侧抽屉与卡片展示可展开的自动填写依据；来源只对当前仍有效的默认值显示，清空/修改后消失。
- [x] 验证核心边界：缺档案、未知线路、跨日、显式返程、人工清空、稳定 ID 重排、报销不推事实、保存与对话一致。
- [x] 跑 Python 测试、前端单元测试、Agent 类型检查与构建；独立代码审查；桌面与窄屏验收。

文件分工：`submission_defaults.py/json` 为配置与确定性规则；`business.py/store.py` 为业务持久化与版本保护；`agent_runtime.py` 为语义理解与对话策略；`submission-defaults.ts` 与 `SubmissionDefaults.tsx` 为来源过滤和展示；其余 UI 仅接入组件，不改变办理容器。

重点审查：无来源的城市/距离不填；人工清空不复活；同一值重新指定时处理不误伤；新建/重排行程不串来源；自然语言更新不覆盖抽屉草稿。

## 验证结果（2026-11-17）

- 前端完整单元测试：334 项通过；后端完整测试：350 项通过。期间其他聊天并发开发产生的临时缺模块/测试失败在最终运行中已消除。
- Agent TypeScript 检查、Vite 构建、`git diff --check` 通过。构建仍有现有大分包提示；后端测试有 Starlette/httpx 弃用提示，均不影响测试通过。
- 独立审查发现并已修复：已有编辑的行程重排被并发合并丢弃；新增费用在编辑器主动清空币种/非租房后被补回。均先失败再通过回归验证。
- 真实模型三轮：明天上海拜访/周五回 → 改北京出发 → 去程一等座、返程二等座，数据与默认来源正确。记录 `artifacts/submission-defaults-live/submission-live-09af73f3debe.json`。
- 真实模型针对性摘要回归：缺项为空、允许提交时不把个人提醒升级为必填；最终摘要不输出表格或反转城市。记录 `artifacts/submission-defaults-live/submission-live-5afdd21e9cec.json`。模型仍可能在调用工具前说一句处理说明，未扩大修改共享流式输出逻辑。
- 使用隔离数据库与5197/5198临时服务完成桌面、390px窄屏验收；依据默认收起，展开后页面宽度390px，无横向溢出；实际浏览器清空交通后补事由，服务端仍为空并记录抑制。截图保存在 `artifacts/submission-defaults-ui/`。
