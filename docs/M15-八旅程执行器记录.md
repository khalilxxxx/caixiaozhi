# M15 八条正式 API 旅程执行器

`packages/demo/src/journeys.ts` 提供 `createDemoJourneyRunner`，`tests/e2e/journeys.spec.ts` 登记 E2E-01 至 E2E-08 八条独立测试。执行器实际调用正式 HTTP API，不将 queued 场景记录视为通过。

## 接口与执行约束

```ts
const runner = createDemoJourneyRunner({
  baseUrl,
  origin,
  loadInvoiceFixture,
  onEvidence,
  saveReport,
  heartbeat,
  signal,
});
await runner.run({ scenarioId: 'E2E-05' });
// 或由控制面先重置，在新 generation 创建执行任务：
const baseline = await runner.resetBaseline('E2E-05');
await runner.execute({ scenarioId: 'E2E-05', baseline });
```

所有身份来自 `/auth/demo/identities` 与明确 `selected_user_id` 的正式登录；服务端 Cookie 与 CSRF 随正常请求传递。没有跳过权限、写入 actor 或直接修改数据库的演示选项。文件以真实字节完成登记、上传和 SHA256 finalize，发票读取仓库两份合成 PDF。

每条先完成受控 reset，E2E-04 使用 `rule-creation`，其他使用 `baseline`。新 generation 重新登录，核对 reset 已成功、旧/新 generation、场景、manifest 摘要、七人十一单、五张 v1 销售待办、554000 分以及完成额590000分。相同 runner 不并发操作全局演示环境，也不重复消费同一个基线。

控制面 Worker 应使用独立定时执行器；旅程会等待 OCR、Agent、预审和报告队列，不能占住唯一普通 Worker tick。跨 reset 的场景租约属于控制面，不能被当作旧代普通作业取消。场景控制器接线由主任务维护。

HTTP 请求合并控制器取消信号、每次最多60秒超时和整条旅程默认15分钟总时限。`journeyTimeoutMs` 可配置总时限；控制器传入取消信号不会覆盖网络超时，超时保存失败证据并终止执行。

## 证据与隐私

每次请求保存 method、path、脱敏请求体、状态、实际回执、trace 与资源版本引用；断言保存 expected/actual。Cookie、CSRF、确认 token 不进入证据。`saveReport` 只应写入受控测试产物或适当授权的业务证据位置。平台管理员场景控制记录应仅保留 step、pass、trace、资源引用和时间，不能保存完整问答、记忆或摘要正文。
