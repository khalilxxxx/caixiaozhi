# M03 规则与字段映射治理补齐记录

本记录说明最终采用的治理设计与已执行的定向验证，不替代总验收记录。范围仅包含规则停用、人工专用规则测试集和字段映射治理。

## 动作协议与资源边界

M11 对领域动作注册的要求是“至少覆盖”既有清单，因此在唯一的 `ActionNameSchema` registry 中新增两个规范动作名：

- `rule.disable`：明确停用当前生效规则，通过统一准备、审阅、确认及执行流程完成。
- `rule.mapping.publish`：发布通过人工样例验证的字段映射版本。

没有扩展公共 `ResourceRef` 类型，也没有把映射伪装为 `rule` 资源。映射发布使用空 `resource_refs`，领域处理器明确生成一个 `resource_ref: null` 的执行项；成功回执的 `resource` 也为 `null`，`external_receipt_id` 保存实际映射版本 ID。

映射的对象身份、定义版本、草稿 ID、草稿哈希、现行版本、样例证明、权限版本、字段目录版本及映射依赖快照均写入 `extra_guards`。统一动作服务在实际执行前重新生成并比较守卫，映射服务在发布事务中再次检查权限与 CAS，不能依靠空资源列表绕过领域授权。

规则停用的确认摘要使用当前生效版本的可信名称、分类及适用范围，说明公司必查覆盖变化。聚合版本 CAS 成功后才推进修订并写出事件；旧版本、非法参数及未授权主体不能执行停用。

## 0023：人工专用规则测试集

`0023` 为人工登记的规则样例提供持久、不可变集合。集合包含完整 SRS 输入和人工独立指定的 `expected_truth`，不接受任意脚本，也不使用待测解释器生成预期结果。

专用集合以 `rts-UUID` 标识，绑定租户、owner、规则、精确草稿版本 ID 与草稿内容哈希。仅改变名称产生的新草稿版本也不能复用旧集合。HTTP 接口支持登记、列出及选择人工测试集，并继续通过真实持久队列产生测试证明；样例数量为 4–100。

既有 `finance.rules.test@1.0.0` 工具协议保持固定 `boundary-v1` 和四例证明。HTTP 启动、任务视图与证明使用独立扩展 schema，没有静默扩大既有 published capability 的输入或输出定义。实际重新计算的完整定义 checksum 仍为：

```text
20f8e0fbfdec80b31b7c332d6750cc889d2ab7ccd536699e6cde251d064e2c2d
```

人工专用测试集已完成新增 5 项与既有规则任务 9 项定向验证，共 14/14 通过；详细边界与证据见[人工样例集合交付记录](M03-人工样例集合交付记录.md)。总体验收仍由总验收记录统一汇总。

## 0024：映射草稿、样例证明与发布

`0024_mapping_governance.sql` 新增映射定义、不可变草稿和不可变人工样例证明，继续使用既有 `field_mapping_versions` 存放已发布版本，并保护已发布记录不可原地更新。新表保留 Demo generation 写入 fence；没有修改或绕过旧迁移与归档代写入限制。

映射按提供方、来源 schema 版本和模块管理配置头，并声明适用部门。创建、保存、验证和发布均要求当前交互身份具备 `rule.manage.company`，且覆盖所涉及的全部管理组织。发布同时检查草稿范围和旧生效版本范围，避免仅凭新范围移除无权管理的旧生效范围。

配置仅接受固定字段目录、JSON Pointer 和五种纯转换：`identity`、`trim_string`、`date_iso`、`decimal_yuan_to_minor`、`enum_lookup`。拒绝目录外字段、任意代码、原型路径、重复目标及不受支持的配置。集合模板如 `expense_items[].amount` 通过来源数组中的稳定行 ID 展开，不能把数组位置当作业务行身份。

人工样例明确登记来源快照、原始 JSON、预期字段状态与预期值。预期必须覆盖该样例展开后的全部配置目标。验证仅执行受限纯归一化并对比人工预期；生成的结果属于样例证明，不形成真实业务事实。来源缺失、未映射和转换失败保留对应未知状态，不能使用旧值、默认零值或默认布尔值制造“已知”。

发布证明绑定当前草稿、owner、权限版本、现行版本、映射修订及依赖快照。失败样例不能准备发布；修改草稿、仅改名、修改映射依赖或撤销授权都会阻止复用旧证明。发布事务原子完成版本插入、current 指针 CAS、mapping revision 提升和 `mapping.changed` outbox。事务失败不改变 current、版本、修订或事件。

保存未发布草稿不会改变生效配置或生效组织。归一化始终从 `current_version_id` 对应的不可变版本及其组织范围读取；已声明的生效版本缺失时失败关闭，不回退为“全部已知”的 legacy 输入。

## Demo 固定口径与实际业务接线

内置 `demo-expenses/expense-v1` 已提供权威规范 DTO，因此治理不能重新解释其财务值：

- 同名字段使用 canonical JSON Pointer 和 `identity`；仅在适用字符串、日期字段上允许不改变业务含义的受限转换。
- 规范 Money 不能从其他 pointer 换值或重新解释金额单位，部门和申请人授权坐标必须同源保留。
- `office`、`other` 固定归为 `general`，并保留 `source_expense_type`；从原始费用类型映射分类时，其余已知类型保持原样。

API 及确认摘要区分 `live_demo` 与 `sample_only`。当前真实业务适配器只接入 `demo-expenses/expense-v1` 的 `expense_claim`。其他提供方可以使用固定纯函数验证人工样例、保存配置版本，但摘要明确其未注册业务适配器，不能宣称已改变现行业务输入。`normalizeSnapshot` 不会将未注册来源冒充为实际生效来源。没有生效治理映射时，既有 legacy 适配器路径保持兼容。

根代理已在 `FinanceService` 构造并注册映射服务与动作处理器。Application 的 `FinanceBusinessPort.getPreauditInput` 先执行原有 fault wrapper 和真实业务读取，再把已授权、原子的 `SrsInputSnapshot` 交给 `normalizeSnapshot`，没有绕过故障控制或替换业务领域实现。

新增动作扩展了动作状态输出中的 operation 枚举，因此 `finance.action.status` 明确升级为 `1.1.0`；没有原地改写旧 published 版本。定向核验中，现有持久定义与 checksum 的不匹配数量为零。

映射生效通过输入 provenance 中的实际映射版本和输入哈希体现。旧预审重新读取时检测到版本变化并成为 stale；旧规则测试证明也因 mapping revision 或快照变化失效。

### 映射界面与真实浏览器结果

独立 `MappingsWorkspace` 已接入“制度与规则”的“字段映射”标签，仅具有 `rule.manage.company` 管理权限及组织范围的身份可见。界面提供列表、严格草稿 JSON、人工样例 JSON、版本及校验值、失败或失效证明提示、不可变历史记录，以及既有 `ConfirmationPanel` 的正式确认与回执。保存新草稿时旧发布版继续生效。修改草稿或样例、刷新版本、切换身份及动作返回后均清除不能继续使用的本地证明；请求沿用会话取消机制，避免旧身份响应回填。

界面将来源接线状态显示为“已接入演示业务”或“仅人工样例 · 未接业务来源”。未注册来源的已发布配置不会被显示为实际业务生效版。Demo 模板遵循 canonical 口径，样例输入在浏览器中生成合成快照并实际计算 canonical SHA-256 `input_hash`；预期为独立人工固定示例，不调用归一化解释器生成答案，也不预置 `passed`。

真实 Playwright 定向用例首轮 1/1 通过，总耗时 16.9 秒，用例耗时 10.2 秒。用例先故意提交错误人工预期，实际取得失败证明并确认发布按钮禁用；重新核对样例后取得真实通过证明。第一版省略 `invoices[].verified`，通过浏览器审阅和确认后，独立主管会话的实际预审从 low 变为 incomplete；第二版补齐该字段，再次正式确认后恢复 low，核对业务金额不变及两版真实映射引用。旧版记录保持不变，旧预审成为 stale，普通员工切换后没有映射入口且手写详情 ID 返回 404。整个用例不依赖模型配置。

桌面与 390px 窄屏截图已在同一轮批量检查，窄屏抽屉没有横向溢出，键盘可聚焦发布按钮，浏览器无 `pageerror`。web 与 E2E 类型检查、变更文件 Prettier 检查均通过，设计机械扫描无确定性问题。Playwright 结束后 API、Worker、Vite 已退出，3000 与 5173 端口均无监听。

## 尚需其他证据的范围

本次验证证明的是确定性治理和真实 Demo 业务接线，不替代真实模型闭环测试。模型是否能在实际会话中正确选择已授权测试集、解释失败证明并准备正确动作，仍需使用真实模型凭据运行对应验收流程。

外部业务提供方仍需要正式适配器、来源 schema、授权读取、原子快照和稳定行 ID 协议，并完成独立的实际业务接线及端到端验证。`sample_only` 的人工样例成功不能替代这些条件，也不能作为外部真实业务已生效的结论。
