# 运行与恢复手册

本手册描述已实现的安全边界和生产补验方法。Docker 启动、真实模型容量、多机滚动升级及备份恢复演练尚未在本机完成，不能把以下操作步骤当作已通过的演练记录。

## 运行、停止与依赖故障

在根目录按 README 配置并迁移后执行 `pnpm dev`。SIGINT/SIGTERM 会停止领取任务、关闭本 Worker 拥有的独占 dsh、等待领域作业与回执查询退出，再关闭数据库/S3客户端。已经提交的动作不会因退出而撤销。模型密钥不是 API/Web/Worker 启动条件。

`GET /api/v1/health/live` 只说明进程可响应；`GET /api/v1/health/ready` 同时探测已迁移数据库与私有桶，依赖未就绪返回503和固定的依赖分类。`/status` 显示同一真实结果。模型可用性需独立运行真实任务和 `pnpm test:agent:real`。

数据库或对象存储故障时保留卷、任务、确认和动作账本；恢复依赖后从持久队列继续。不得通过删除账本、清表、重新发相同业务写请求来消除错误。未知依赖输出不能作为低风险或验证通过。磁盘满时先停止新模型任务，扩容受保护运行卷，再检查原run与动作；不能把未完成日志当成安全恢复依据。

## unknown 动作

后台每秒巡检，按原动作与 external_request_id 查询回执；持久退避为2/5/15/30/60/300秒，单次查询有界，30秒租约及attempt fencing阻止旧查询覆盖新结果。它不会调用原写命令。原业务提交与回包丢失后，仍以业务回执为准。

超过十五分钟仍未知会追加一次 `reconciliation.manual_required` 审计；后台继续有界查询。具备 `operations.read` 的人员可在任务运维的“待核实动作”查看标识、待核实项及是否需要人工核查，不可读取业务正文。本人通过原动作详情核实；管理员不能冒充本人重新提交。

人工核查应保存 action_id、trace_id、external_request_id、原幂等键与原系统查询结果，联系原系统确认。确认成功或失败后仍由受信适配器产生可核验回执。若原系统没有幂等或回执查询能力，对应写能力应关闭。禁止换新key绕过unknown资源保护。

演示重建遇到unknown会进入blocked；先核实原动作，再继续原reset任务，不能删掉旧代unknown强行重置。

## 撤权与连接器停用

授权变更提升authz_version，旧会话/工具/流在下一次验证时停止。助手消息、卡片、事件和工具调用的内容授权快照不可变；续接只保留完成状态与action引用，业务正文重新读取。下载每次都重鉴权；已经下载到用户本地的文件无法由本系统撤回。

连接器/能力停用通过接入台的受控配置与统一确认完成。停用阻止新调用；已有unknown仍需按原账本核实。真实 adapter 缺少已验证凭据、固定地址或安全写入能力时保持关闭，不能回退为Demo成功。

## 密钥轮换与滚动升级

模型/S3/连接器秘密仅由部署secret提供。轮换前停止新调用，核实在途写入；更新secret后重建API/Worker，不把秘密写进工具参数、数据库正文或日志。会话签名支持key_id轮换，保留旧验证钥匙的重叠期后再撤旧钥匙；生产接线与组织的secret管理需部署时完成。

滚动升级先让目标Worker停止领取并正常退出，检查其独占dsh已结束，再启动新版本。新所有者使用新epoch，旧所有者不能写回。只读中断最多自动重放一次；未决写入进入回执核实，不能通过重放模型命令恢复。先迁移兼容的新增结构，再升级读写进程；已应用SQL不可改写。

## 备份与恢复演练

使用专用备份账号对PostgreSQL执行一致性备份，同时记录私有对象桶和受保护运行卷的恢复点。示例使用由部署系统管理的pg_service配置，命令中不出现连接秘密：

```sh
pg_dump --dbname=service=caixiaozhi_backup --format=custom --file=caixiaozhi.dump
pg_restore --dbname=service=caixiaozhi_restore --single-transaction caixiaozhi.dump
```

恢复目标必须是隔离的新数据库与私有桶。恢复前隔离所有旧Worker，恢复后先校验迁移摘要、业务/回执关联、文件SHA、私有性与授权，再以新epoch启动。S3备份需包含对象版本/删除策略，不能只有数据库文件名。先做只读、确认等待、unknown和普通领域任务的恢复演练，再允许真实写入接入。当前机器只完成原生服务重启后的持久读取验证，没有完成异机备份恢复演练。
