# T01 工程实施计划

目标是在当前目录交付共享契约、三个进程骨架和持久化基础，后续 T02 可以继续接入可信身份。

架构采用 pnpm workspace。contracts 提供唯一公共 schema，platform 提供配置、数据库及私有对象存储，jobs 仅提供事务 outbox。API 暴露健康检查，Web 消费真实 API，Worker 只负责可靠启动和退出。

## 任务与验收

- [x] 契约。创建 `packages/contracts/src/{common,cards,events,health,permissions,index}.ts` 和 `tests/contracts`，先写正反例，验证金额、枚举、严格对象、版本及身份上下文约束。
- [x] 持久化。创建 `packages/platform`、`packages/jobs`、`infra/migrations` 和 `infra/compose.yaml`。验证迁移重复执行、元数据/outbox 事务提交和回滚、私有对象读写及匿名拒绝。
- [x] 运行链路。创建 `apps/{web,api,worker}` 和配置模板。单元测试先定义健康响应及配置约束，开发并验证健康/未就绪/退出行为。
- [x] 整体验收。执行锁文件安装、typecheck、build、各实现测试及启动检查，提供可复制命令、版本和真实证据。后续阶段测试命令退出非零并说明未实施。

所有 schema 已定义字段严格拒绝未知键。生产 seed/reset 拒绝，未授权前不提供业务文件接口，不引入模型密钥依赖。审阅重点包括依赖超时及页面错误信息脱敏、事务失败后无孤立事件、跨租户及版本元数据、未知卡片 payload 拒绝、进程退出释放资源。
