# 差旅、报销提议与票面矫正补充记录

本记录补充结构差异、明确选择采纳、独立票面矫正和对应界面。已应用迁移 `0013_business_proposals.sql` 保持冻结；模型、API、Worker 总装由主任务统一接入。

## 真实行为

差旅支持头字段与全部行程字段替换，以及新增、删除、重排。费用支持头字段和费用项允许字段替换、新增、删除；原票面与业务状态不属于模型操作白名单。模型返回的临时标识由服务端重新分配；保存后保留既有 `leg_id` 和 `item_id`。

生成任务持久保存源草稿、用户本轮明确选择的材料及票据版本与摘要。`evidence_refs` 必须来自本轮输入。采纳使用聚合版本、每项旧值及依赖快照复核，并按服务端原顺序执行用户明确选择的 operation；空选择不写，材料或源草稿变化拒绝采纳。费用新增只能使用本轮本人已确认票据，绑定、预留和金额汇总仍走真实保存事务。采纳不提交申请，也不提前增加 OA 提交占用。

`PATCH /api/v1/expenses/invoices/:id` 单独保存票面矫正，检查所有人、版本和绑定报销是否可编辑。修改后恢复 `needs_confirmation` 与 `verification_state=pending`，清空旧核验证据及指纹，并在同事务提升绑定报销版本。再次确认票面使用确认接口；已确认票据要先矫正，再重新确认。

业务服务公开返回使用 `BusinessDocument<K>`，三个 DTO 由严格 Zod schema 实际解析。`get/list/project/create/saveTravel/saveExpense/saveOa` 不再依靠泛化 `details` 丢失领域字段；模型端口的源单据也使用具体差旅或报销 DTO。集成测试移除了用于掩盖 legs/items/预算返回类型的断言转换。

界面支持明确选择材料与已确认票据、逐项选择差异、展示结构变更与版本冲突。票面矫正后可以明确选择新版本更新已有费用行；原申报金额保留，并提示核对金额、日期及关联申请。只读单据显示原成本中心，即使该中心不在当前用户可选范围。
