# 财小智 Agno 本地 Demo

## 入口与启动

访问 **http://127.0.0.1:5190/agent.html#home**。

在项目根目录运行：

```sh
pnpm demo:agent
pnpm status:demo:agent
pnpm stop:demo:agent
```

也可双击 `scripts/demos/start-agent-workspace.command`，启动并打开浏览器。脚本会检查已有服务、复用可用的5190入口，并仅停止本启动器登记的进程。服务在后台运行，关闭启动终端不丢失业务数据；电脑重启后重新执行启动命令。

首次在其他机器安装：

```sh
pnpm install --frozen-lockfile
uv sync --project apps/agno-service --python 3.12 --frozen
cp -n .env.example .env
pnpm demo:agent
```

本地产品使用 Python 3.12、Agno 3.2.0、FastAPI、SQLite 和现有 React/Vite。依赖版本由 `apps/agno-service/uv.lock` 锁定，无需 Docker、PostgreSQL 或 S3 即可运行本入口。根目录原有 `pnpm dev` 仍启动旧的5173工程，和本次5190产品相互独立。

## 模型配置

密钥只写在项目根目录 `.env`，不进入浏览器或源码：

```dotenv
AGNO_API_KEY=你的模型密钥
AGNO_BASE_URL=https://api.deepseek.com/v1
AGNO_MODEL=你的模型标识
```

未填写 AGNO_* 时自动兼容已有 DSH_API_KEY、DSH_BASE_URL、DSH_MODEL。本机已使用现有 DeepSeek 配置进行真实工具调用验收。应用和数据存储在本地，模型通过已配置的网络接口调用，因此不是完全离线运行。

修改配置后执行停止、启动命令。密钥缺失、模型不可用或超时都会显示真实错误，不会切回固定回复。

## 架构与数据

运行链路：浏览器5190 → 同源 `/api/local` → 本地5191服务 → Agno模型与受控工具 → SQLite及本地文件。

- Agno负责多轮理解、工具选择、草稿字段填写、制度问答、规则建议和报告任务。
- 业务工具负责单据查询、金额统计、规则检查、版本管理和模拟业务受理。模型没有提交、批准或付款工具。
- 提单仍由用户在右侧抽屉检查、勾选确认后提交。服务器重新校验并生成唯一单号、持久化回执和查询记录；重复请求复用同一回执。
- 同一类单据目前共用一个当前草稿，提交后可“新建同类单据”；历史提交快照、单据、回执不会被新草稿替换。本版本面向本机单用户演示，不提供多用户身份隔离。
- 浏览器只缓存界面偏好和输入草稿；业务对象、会话、运行记录和文件元数据以服务器为准。运行事件支持重连，服务重启会将未完成任务明确标为暂停。
- 业务适配器使用可替换的合成单据、2026年9/10月费用汇总和制度条款。分析界面、报告与工具共用数据源；汇总记录不是逐张真实发票。
- 选择已上架技能后，Agno读取对应版本的真实指令文本。上传技能先保存原件和文本，再人工审核/发布；上传脚本或ZIP不会作为代码执行。
- 定时预审为本地服务的真实调度：启用后按上海时区每日指定时间执行，重启不会重复执行当天已完成任务；通知只产生于实际预审结果。

数据目录默认为 `.runtime/agno-local/`：`workspace.sqlite3` 保存业务与运行记录，`files/` 保存原件，`api.log`、`web.log` 保存运行日志。可通过 AGNO_DATA_DIR 指定其他本地绝对路径。备份时先停止本地服务，再复制整个目录；不要直接删除数据库或只复制正在写入的主文件。

## 可直接走的路径

1. 新会话输入“10月销售部报销费用比9月增加了多少”，实际调用统计工具；继续追问集团口径。
2. 输入“上海出差住宿每晚700元符合标准吗”，检索合成制度并展示来源卡片。
3. 输入“请生成并保存10月销售部费用分析报告”，取得可打开的持久化报告。
4. 输入“帮我填写差旅申请：11月19日从杭州乘高铁去上海拜访客户，11月21日高铁回杭州”，在抽屉核对信息、检查、确认提交，再查询本地回执和单据。
5. 在材料页上传文本、PDF或Word，下载原件并核对字节；在对话中引用可解析文件做摘要或翻译。
6. 在规则中心描述单一检查条件，真实生成规则草稿，核对后保存启用，再重新预审。修改规则会使旧检查失效。
7. 上传技能文件，保存、申请审核并录入审核结论；仅已发布且满足调用条件的文本技能可供会话选择。

## 接入边界

OA、资金、发票查验及制度不是外部真实企业系统。界面显示“本地已受理”表示模拟业务服务已保存记录，不代表外部审批或支付成功。

真实上传文件会保存字节。文本、CSV、Markdown、JSON、YAML、文字型PDF及Word可提取内容；图片、扫描PDF没有接入OCR，Excel/ZIP目前按原件存储。缺少有效发票查验结果的报销保持待核实，不会因为上传或模型判断就变成已查验。合成材料仅用于演示既定业务字段；不会冒充新文件识别结果。

规则自动生成支持金额、餐饮合计、每间夜住宿、天数和发票/附件布尔检查；复杂组合或不支持的条件应拆分处理，不能由模型偷偷改写成另一项检查。报告页面提供数据图表、修改和HTML/CSV导出，导出过程使用当前服务器数据。
