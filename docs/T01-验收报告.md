### 契约与确定性验证

金额正例涵盖零、正负整数和超过 JavaScript 安全整数范围的字符串。反例涵盖小数、科学计数、前导零、负零、正号、数字类型、非 CNY、全角数字、空白及末尾换行。资源版本缺失、零、负值和非整数被拒绝，所有定义对象的未知字段被拒绝。

身份区分交互会话和订阅上下文。角色、权限、运行/工具/回执枚举均按规格校验。UTC 时间和事件信封接受规范正例，拒绝错误字段及非法类型。卡片工厂按注册类型校验 payload，默认空注册表明确拒绝业务卡片。错误响应兼容 01 第 5.2 节只有 request_id/trace_id 的 meta 示例。

## 实测发现并修复

- 配置 URL 的后置校验曾抛出原始 Invalid URL，现通过受控配置错误统一报告字段名。
- 错误信封 details 曾传 null，与已定义 schema 不一致，现采用契约中的可选字段。
- PostgreSQL 关闭空闲连接曾导致 API 崩溃，现捕获固定脱敏连接池错误，并有真实后端终止回归与停库复验。
- outbox 现对默认 strip 对象 schema 强制 strict，未知字段导致事务回滚。
- 数据库查询现有执行时限，防止健康探测底层永久等待和退出阻塞。
- 根环境曾强制 NODE_ENV=development，导致正式 Web 构建使用开发分支。已从模板及本机配置移除，重新构建验证生产模式。
- 开发 watch 包装器在 Ctrl+C 时重复转发信号，现由 node --import tsx 直接运行 API/Worker，信号处理保持幂等。再次 pnpm dev 启停已确认 Worker 输出 worker.stopped，端口释放。API/Worker 源码改动后需手动重启，Web 保留热更新。

## 当前配置、默认解释与限制

- 采用 RustFS 1.0.4 提供开发 S3 兼容私有存储。MinIO 下载链接和镜像查询失败，RustFS 版本及镜像元数据可实际核实。
- 01 第 5.1 节未限定 Money 正负边界，本轮允许负整数分，具体业务的非负限制留在领域 schema。
- 数据库 statement_timeout 固定 2500ms，query_timeout 为 3000ms，满足当前小迁移和健康检查。后续较长迁移或领域查询需设计显式、受控的超时配置。
- 卡片与 SSE 的业务 payload 由后续模块收紧。当前卡片默认注册表为空，outbox 的领域事件与 SSE run 事件分开。
- 当前本机 `.env` 为 test 模式，随机技术凭据仅存于被忽略文件。数据和原生工具在本机 `.runtime` 及临时 ASCII 目录，标准跨机器启动使用 Compose。
- RustFS 原生二进制存在中文可执行路径问题，本次使用 ASCII 路径运行。该本机替代路径及临时对象目录的寿命详见 runtime-compatibility.md。
- 构建仍有 Zod 第三方注释位置警告，产物已生成且编译入口已验证。
