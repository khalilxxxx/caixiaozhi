03

五个应用，一条连续的工作路径

整合的是对象、状态与返回路径。应用页承接完整操作，对话承接意图、澄清和结果；技能、制度及材料是可引用上下文。

重点应用对话中的最小结果完整工作区与联动
智能提单当前草稿、关键金额/行程、缺项或待确认状态。字段编辑、材料引用、规则检查、确认快照、待回执；保存费用与生成报销分开。
单据进展对象标题、真实状态、最多两项业务摘要、当前处理。六类单据详情、流程阶段、多人处理、ETA依据；引用该对象继续追问。
规则平台批次概要与关注数量，单据问题可定位。规则来源/范围、个人规则编辑启停、检查快照、备注；修改影响后需重查。
数据分析明确范围＋金额＋短结论，历史卡保留原快照。筛选、对比、下钻、CSV、报告、编辑草稿和带范围追问。
技能中心输入区引用技能名与版本，选择本身不执行。目录、详情、权限、版本与治理共用状态；退回修订与仅存储发布可回到目录验证。
04

通用卡片、版本、确认与异常

统一骨架，保留业务差异

卡片负责标题、状态、少量摘要与一个明确入口。OA无金额时不留空金额位；审批结束与付款完成分别表达。长表格、流程和规则原文进入详情。

当前对象与历史结果分清

分析卡和报告保留创建时范围；规则检查保留依据快照。草稿或适用规则变化后重新检查，不用新数据悄悄改写旧结论。

编辑、保存、提交分别有含义

报告与技能上传/修订草稿可关闭后恢复。业务提交前核对当前内容与检查版本；当前前端只生成本地请求并等待回执，不伪造真实提交成功。

未知是一种有效状态

缺失比较期不按0计算；缺预算不展示虚假执行率；发票待查验不算通过；源系统失败不显示0条；请求结果未知先查回执。

技能权限与审核结论独立

查看、下载、调用分别判断。安全失败禁止技术通过；兼容失败只能存储发布。退回版本锁定，1.2与1.2.0视为重复。

必要反馈就近，讲解独立收纳

产品默认页头不放功能说明；风险、字段约束、来源与状态反馈保留。使用指引默认关闭，评审步骤及实现限制集中在本页。

05

M01—M15：范围保留，平台后端暂缓

本轮是前端整合评审，并非重新宣称早期工程已全部实现。下表将可见体验与依赖后台的完整能力分开，M13—M15不新增管理界面。

原规划模块本轮可见范围暂缓或尚未接入
M01对话、卡片与工作区统一输入、上下文引用、紧凑结果卡与按需详情；两版共享业务组件。真实模型理解、任意业务卡片变体。
M02个人偏好与主动提醒偏好、消息及最近任务；每日摘要归入消息与任务入口。跨设备记忆、后台调度、消息外发。
M03规则中心通用规则只读、个人提醒规则新增/编辑/启停；分系统与执行场景。组织级治理、任意复杂规则解析、生产配置权限。
M04预审中心8张固定待办，关注/待核实/未发现异常；依据、备注及重查。生产批量预审、真实发票查验、后台定时运行。
M05Skills Hub目录与治理共享状态；版本、收藏、独立权限、双审、退回锁定。技能包托管、安全扫描、依赖部署、隔离执行。
M06制度知识与问答制度入口、正文和来源引用。企业文档检索、知识治理和真实模型问答。
M07数据分析与报告范围筛选、图表/明细、连续追问快照、CSV和报告导出、编辑草稿恢复。数据仓库、生产指标服务、任意分析问题。
M08差旅申请固定差旅草稿、字段修改、检查、确认与待回执状态。任意新单创建与任务隔离、差旅系统写入。
M09费用报销材料核对、费用保存、形成报销、重查与提交前确认。真实OCR/验真、多单分组提交与生产报销写入。
M10OA及跨系统业务查询OA请假、合同、付款、预算等类型；保留源系统状态。任意OA表单、全量流程与跨系统办理。
M11统一审批与动作同一处理入口承接预审、意见、办理确认与结果追踪。真实审批权限、审批引擎、审计及付款执行。
M12身份、组织与主数据统一林悦·财务部；当前身份和业务范围清楚呈现。真实登录、组织目录、服务端鉴权和授权隔离。
M13系统接入与能力目录仅保留用户识别来源、状态与输入所需语义。系统接入管理、MaaS能力目录；本轮不建设后台。
M14Agent运行底座保留任务处理、暂停及等待人参与的前台状态。运行底座与框架选型；本轮不安装或选择Agent框架。
M15演示数据控制台固定合成案例用于交互评审，限制在本说明中披露。不建设数据控制台，不在产品内加入场景模拟开关。
06

从可操作旅程评审完整性

两版共享本浏览器状态；切换版本不会重置已经编辑的数据。以下步骤适合用默认案例逐条检查，界面中的「使用指引」也可随时打开。

01

连续费用分析 → 报告

进入10月费用分析任务，依次输入“只看销售部”“换成9月”“查看差旅”，打开分析明细，再整理报告、编辑摘要、下载。

核对：集团48.60万 → 销售21.80万 → 9月销售19.00万 → 9月销售差旅11.00万；旧卡不变。9月无8月比较期，其他范围无集团预算。
02

材料核对 → 保存费用 / 形成报销

打开上海客户拜访票据，查看住宿日期、关联业务与用途待确认项；处理后分别检查“保存费用”和“生成报销”的后续路径。

核对：6笔有效费用共¥2,962；重复排除与识别失败分开。新选本机文件仅记录元信息，未识别前不得混入金额。
03

草稿 → 规则检查 → 确认 → 待回执

进入智能提单，修改字段后检查；打开提交确认，再返回修改金额或适用规则，观察旧检查是否失效。

核对：阻断和未知结果不能提交；个人提醒不自动阻断。形成请求后保留待回执，重复查询不凭空变成成功。
04

跨系统单据查询与对象追问

查看OA请假、采购付款和合同会签；打开某张详情后围绕该对象继续提问，查看时间预估依据和来源。

核对：OA没有空金额位；审批通过的付款单仍可能待执行；仅列出当前未完成处理人，缺依据不承诺完成时间。
05

待办预审 → 规则调整 → 重查

打开今日待审单据，筛选需关注/待核实；查看问题与制度依据，保存审核备注，再从规则中心调整个人规则并重查。

核对：备注不改变正式审批状态；通用规则不能被个人提醒覆盖；系统与执行场景无关的变更不误伤其他检查。
06

技能引用、双审与修订恢复

查看月度费用分析的下载/调用权限，选择后观察输入区引用；再进入团队资产，检查退回版本、重复版本、安全失败及不兼容仅存储发布。

核对：选择不产生执行消息；关闭上传/修订表单后可恢复草稿；上架仅存储版本在目录中仍不能调用。
07

需要业务确认的决定

默认入口与密度

是否采用统一助手为默认、集中处理台为财务可选视图？需用实际高频任务验证切换与同屏价值。

提交与单据隔离

任务、草稿、正式单据如何对应？多任务是否可复用同一草稿？生产阶段需明确每个新单的独立身份、版本和幂等规则。

提醒、阻断与人工责任

哪些组织规则必须阻断，哪些仅提示？待核实能否特批？规则、预审意见与正式审批各由谁负责？

统计口径

审批完成日、费用发生日还是付款日作为默认？预算范围与金额定义需由财务确认；当前分析不是付款报表。

技能治理职责

业务审核、技术审核及上架分别由哪些角色完成？仅存储发布、旧版使用、下载授权与撤销策略如何规定？

外部结果与通知

生产回执、重试、超时和部分成功如何处理？消息需要哪些触达渠道？提醒频率与催办授权应独立确认。

08

阅读覆盖与交付边界

项目清单覆盖8个可访问对话：整体整合、agent.md、T01工程基础，以及规则平台、数据分析、Skills Hub、单据进展、提单。已对项目与归档清单翻页至末尾；最新五个设计对话读取完整可访问正文及附件信息，未仅依据标题或预览。

最新五对话的读取终点均为hasMore=false、nextCursor=null：规则平台5回合、单据进展2回合、提单1回合、分析与技能各3回合。规则平台有用户纠正回合未返回助手正文，不把未返回消息声称为已读。历史助手方案只作为参考，最新用户纠正优先。

本次是可操作的本地前端评审版本

  • 入口由本机HTTP服务提供。状态保存在浏览器本地，同源两版共享；不同浏览器、不同端口或清理站点数据不会共享这些状态。
  • 使用固定合成业务数据，身份为林悦·财务部。分析按审批完成日、人民币含税统计；10月集团48.60万元，9月42.80万元，10月集团预算60万元。
  • 当前只有1份报销草稿与1份差旅草稿的共享场景，不等于任意新单均具备独立任务隔离。该限制必须在生产建模时补齐。
  • 没有接入真实大模型、OCR、票据验真、企业检索、审批、付款或业务提交；固定场景响应不代表通用理解能力。
  • 选择本机文件只取得名称、大小、类型等元信息；未知文件保持待识别。没有伪称服务端上传、解析、扫描或授权完成。
  • 提交请求的本地记录不等于外部系统受理。缺少真实回执时保留待回执/未知，查询不会伪造成功。
  • 技能双审、上架和权限用于检查前端状态设计，不是服务端鉴权、安全扫描、隔离运行或真正部署的证明。
  • 本页为独立评审文档，允许展示步骤与限制；产品界面保留必要业务反馈，教学说明默认收在角落入口。
