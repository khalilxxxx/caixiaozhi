# 内容 JSON

所有路径相对于当前任务根目录。输入建议保存到 `work/content.json`，输出必须放在 `output/`。

```json
{
  "title": "用户指定的汇报标题",
  "subtitle": "汇报范围或资料来源",
  "author": "用户指定的署名，可省略",
  "include_cover": false,
  "total_slides": 2,
  "slides": [
    {
      "title": "本页结论或主题",
      "bullets": ["来自用户材料的第一条要点", "需要人工核对的事项"],
      "source": "来源：用户提供材料",
      "notes": "可选的讲稿或补充说明"
    },
    {
      "title": "事项清单",
      "table": {
        "headers": ["事项", "状态"],
        "rows": [["来自用户材料的事项", "待核对"]]
      }
    }
  ]
}
```

- `title` 必填，最多 48 字符；`slides` 为 1 至 40 组内容。
- `include_cover` 为布尔值，默认 `true`，自动生成一页封面。用户指定每页主题（如“2页，第一页文稿生成，第二页表格汇总”）时设为 `false`，并将两个主题依次放入 `slides`；此时第一页就是第一组内容，不再添加封面。关闭封面后，顶层 `title/subtitle/author` 保存在文档属性中；需要让读者看到的信息应写入具体页面。
- `total_slides` 为可选正整数，表示**包括封面、要点分页和表格分页在内的最终总页数**，不是 `slides` 数组长度。用户要求固定页数时必须填写；未限定页数时省略。上面的示例有两组短内容、无封面，因此恰好两页。
- 自动分页后若与 `total_slides` 不符，脚本在保存前报错，给出实际页数和封面状态，不强行截断、删减内容或填充空页。应先调整封面与内容组织；无法同时保留完整内容和满足页数时，向用户说明冲突，不要删除页数约束后交付。
- 每组有 `title`，至少提供 `bullets` 或 `table`；两者都有时分别出页。
- 要点一条最多 180 字符，按可用空间自动分页。每组最多 80 条。
- 表格为 1 至 6 列、1 至 200 行，每页最多 6 行。单元格长度随列数限制，长说明请放在要点或讲稿中。
- `source` 最多 120 字符，显示在页脚；不提供时不伪造来源。
- 金额、币种、单位、期间和“待核对”状态写入用户给出的原始含义；缺信息时不暗示已确认。

脚本结束输出 JSON，包含实际生成的文件名、页数、字节数。不能仅根据拟定的输出文件名宣称成果已生成。
